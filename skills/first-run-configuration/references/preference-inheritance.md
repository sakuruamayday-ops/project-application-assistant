# 个人偏好与升级继承协议

## 三层结构

1. 官方核心：发布包内的正式Skill，只读更新，承载能力、事实核验和安全核对。
2. 个人层在 `~/.config/project-assistant/preferences.json` 存结构化偏好，凭据和客户资料留在其受控来源。
3. 登录用户通过 `/v1/preferences` 同步偏好，Token 由鉴权机制独立管理。

## 允许记录的偏好

- 默认省、市和常用地域口径。
- 输出格式、详细程度、语气、是否先给结论和是否附来源。
- 知识库优先、适用任务输出偏好和已授权归档范围；复杂任务继续执行对话四问，新增保存对象按对应授权处理。
- 用户术语映射。
- 单个Skill的结构化参数，例如固定章节顺序或默认报告类型。

个人偏好与身份权限、来源核验、政策有效性、财务真实性及其他保护规则共同应用；获批判断按实际条件和证据说明。

## 三方合并

同步比较基线、本机和云端，单侧变化继承；同字段冲突保留本机并生成 `preference-merge-conflicts.json`，核对后同步该字段。

## 识别直接修改SKILL.md

每次安装记录官方 `SKILL.md` 的SHA-256。升级时比较旧官方哈希、当前安装文件哈希和新官方哈希：

- 当前文件等于旧官方：没有用户直改，可直接升级。
- 当前文件不同、官方未变化：检测到用户直接修改。
- 当前文件和官方都变化：判定为升级冲突。
- 没有旧官方基线：判定为未纳管既有Skill。

出现后三种情况时，旧目录进入可恢复备份，新官方核心正常安装；继承报告列出差异，需要保留的习惯转为个人覆盖层。

升级给偏好迁移候选。已授权迁移时用 `--migrate-preferences` 写入安全结构化习惯；权限、来源、政策、财务及保存范围按现有授权保持，云端同步沿本次授权执行。

## 查看、撤销和恢复默认

- 网站“个人偏好”页面可查看当前版本和历史记录。
- “撤销上一版”生成一个新的恢复版本，不删除历史记录。
- “恢复官方默认”清空个人覆盖效果，但仍保留审计历史。
