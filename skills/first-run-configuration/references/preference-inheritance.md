# 个人偏好与升级继承协议

## 三层结构

1. 官方核心：发布包内的正式Skill，只读更新，承载能力、事实核验和安全门禁。
2. 个人覆盖层：统一保存为 `~/.config/project-assistant/preferences.json`，只写结构化偏好，不写凭据和客户资料。
3. 跨设备同步：登录用户通过 `/v1/preferences` 同步同一份个人偏好；Token仅用于鉴权，不写入偏好文件。

## 允许记录的偏好

- 默认省、市和常用地域口径。
- 输出格式、详细程度、语气、是否先给结论和是否附来源。
- 是否执行四问复盘、知识库优先和自动归档。
- 用户术语映射。
- 单个Skill的结构化参数，例如固定章节顺序或默认报告类型。

身份权限、来源核验、政策有效性、财务真实性、获批承诺和其他保护规则不得被个人偏好覆盖。

## 三方合并

同步时比较上次同步基线、本机偏好和云端偏好：只有一侧变化时自动继承；两侧修改同一字段时生成 `preference-merge-conflicts.json`，保留本机值但停止上传，等待用户确认。

## 识别直接修改SKILL.md

每次安装记录官方 `SKILL.md` 的SHA-256。升级时比较旧官方哈希、当前安装文件哈希和新官方哈希：

- 当前文件等于旧官方：没有用户直改，可直接升级。
- 当前文件不同、官方未变化：检测到用户直接修改。
- 当前文件和官方都变化：判定为升级冲突。
- 没有旧官方基线：判定为未纳管既有Skill。

出现后三种情况时，旧目录进入可恢复备份，新官方核心正常安装，升级继承报告列出差异。不得把旧文件自动覆盖回正式Skill；需要保留的使用习惯应转写到个人覆盖层。

升级工具会自动调用旧Skill偏好迁移助手。安全且可结构化识别的地区、格式、详细程度、语气、归档方式和个人写作习惯直接进入个人覆盖层；涉及凭据、权限、来源核验、政策效力、财务真实性或获批承诺的内容只进入迁移报告，不自动生效。用户也可在Agent中输入“请迁移我的旧版Skills个人习惯，并同步到云端”重新执行。

## 查看、撤销和恢复默认

- 网站“个人偏好”页面可查看当前版本和历史记录。
- “撤销上一版”生成一个新的恢复版本，不删除历史记录。
- “恢复官方默认”清空个人覆盖效果，但仍保留审计历史。
