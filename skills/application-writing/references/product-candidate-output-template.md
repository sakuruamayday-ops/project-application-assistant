# 主导产品候选逐段输出模板

用于产品候选及六问结论，沿本轮字段要求输出；完整申请、资格与评分按对应任务另行组织，确认状态沿用实际用户记录。

## 固定结构

```json
{
  "result": {
    "products": [
      {
        "name": "技术载体与产品特征组成的候选名称",
        "family": "该候选所属的商业产品类别",
        "linkedIpIds": [],
        "technologyCardIds": [],
        "relation": "该候选已知的材料、终端制品及专利支持关系；未确认关系在本句中明示",
        "directionQuestion": "针对这个候选需要用户作出的具体选择"
      }
    ],
    "sixAnswers": {
      "Q1": "产品载体：说明输入已给出的材料、产品或服务对象。",
      "Q2": "行业问题：说明这些资料实际指出的问题。",
      "Q3": "技术方法：说明已给出的结构、工艺或方法，分别标明来源。",
      "Q4": "性能与产业化：逐项保留已给指标的数值、单位、测试对象和方法；未提供的部分明确列为缺项。",
      "Q5": "产业链价值：说明现有方法的用途；拟组合路线按条件建议表述。",
      "Q6": "名称归纳：给出候选名称、归纳理由及具体方向确认问题。"
    },
    "supportingIpIds": []
  },
  "basis": [],
  "missing": [],
  "nextAction": []
}
```

数组中的引用只取输入实际存在的ID。`linkedIpIds`与`technologyCardIds`分别保存专利和技术卡，不交叉填入。`basis`记录实际依据，`missing`只保存一份缺项清单。

## 每部分怎么仿写

1. **名称**：采用“技术载体或方法特征＋可识别产品类别”；材料、指标和专利填本轮企业事实。
2. **关系**：优先写“技术卡描述的〔材料〕经〔方法〕形成〔终端产品〕”。另一专利仅涉及该类产品结构、对应关系待核时，分句写“〔专利ID〕描述〔结构〕，尚未确认用于上述产品”。
3. **组合建议**：写“若〔技术卡〕与〔专利〕属于同一产品，可考虑〔组合名称〕”，六问统一保留该条件，建议与已实施事实分别说明。
4. **方向问题**：围绕实际业务选择提问，例如“该候选应以功能基材还是终端制品作为主导产品载体？”用户确认按真实回复记录。
5. **设备支撑**：仅有设备专利时填 `supportingIpIds`；设备对外产品或服务有依据时再列入 `products`。
6. **指标**：写“〔对象〕的〔指标〕为〔数值＋单位〕，方法为〔已提供方法〕”；缺项写“主要技术指标待补充”。

## 段落仿写示例

以下为表达骨架，方括号说明输入字段；输出时填入本轮已取得的事实，缺项标明待核：

> 技术卡〔ID〕记载，〔材料或载体〕通过〔已给出的方法〕形成〔产品〕，用于解决〔资料明确指出的问题〕。其〔测试对象〕的〔指标〕为〔数值与单位〕，测试方法为〔方法〕。据此建议将〔候选名称〕作为主导产品方向，需明确采用〔载体A〕还是〔载体B〕作为申报对象。

指标缺项写入 `missing`，先交付成立内容。只有一个合理载体时直接给建议及适用条件；未关联专利单独说明：

> 〔专利ID〕涉及〔已知结构〕，与上述产品的搭载关系待核；若属同一产品，可考虑〔组合候选〕。

## 确认与修改方式

此模板生成候选，用户已确认的 `directionConfirmed` 由上游输入传入并保留。修改某一问时，重写该问及受影响的下游，复用其余已确认内容。

## 验证边界

示例用于说明表达和结构。本轮验证采用新会话及相同输入，核对事实和结构；缺项先交付成立部分与具体问题，复用已正确的内容。
