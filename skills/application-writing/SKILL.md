# 申报材料撰写

## 输入与方法

1. 识别项目类型、申报年度、申请书版本、目标章节、字数和评审关注点，汇集政策、企业事实、证据及待补项。
2. 专精特新和小巨人按对应申请书版本，对主导产品、补短板、填空白和国产替代分别判断。
3. 形成章节任务单，明确本段问题、事实、结论依据和长度；按“结论—行业问题—企业做法或技术—指标—客户或产业化验证—项目价值”组织。
4. 数字保留来源精度、单位与期间，缺项标待核验。正式正文用直接陈述，括注信息融入句子；“国内领先”“填补空白”等判断绑定具体证据。
5. 企业简介和主导产品参考 `references/application-section-patterns.md`，结构采用当期表单要求；来源编号由 `evidence-ledger` 统一，表单来源字段或独立来源说明承载引用。
6. 成稿按需用 `consistency-check` 核对跨章节事实；自然化润色使用 `gongchuang-humanizer-zh`，修订后复核事实与资格判断，交付说明实际稿件状态。

## 模板填写

按用户模板的原文字节点填充，保留字体、字号、颜色、红字、抬头、页眉页脚、表格布局、合并关系、边框、节属性和页面边距。文字过长时精简表达。可按需使用 `skills/_runtime/template-fidelity/scripts/validate_docx_text_only.py` 及逐页检查，核对页数、分页、表格边界、溢出与重叠。用户要求增删重复表格时，复制完整同类 OOXML 片段，记录结构变化并检查成品。

## 主导产品候选

- 候选与内部六问按 `references/product-candidate-output-template.md` 的字段、段落功能和表达方式组织，事实取自当前企业。
- 结构化输出采用用户指定字段；请求 `result`、`basis`、`missing`、`nextAction` 时返回这四项，缺项清单维护一份并据此计数。
- 产品名称候选、资格判断分别呈现。有效发明总数未知时，按已知技术与商业产品族提出暂定候选并注明数量规则待应用。技术卡、专利关联使用输入的对应关系；技术目的与实测效果分列，指标保留测试对象、单位和方法。
- 专利引用 ID 取自 `patents[].id`，技术卡引用 ID 取自 `technologyCards[].id`。已知产品事实分列；缺少对应关系的组合方案及每项六问均用“若确认……可……”表达。生产支撑设备列支撑方向或未覆盖专利；具有对外产品或服务依据的对象进入 `candidates` 并计数。
- 用户确认状态取自本轮输入或已确认的上游记录。新候选保持待确认并提出具体方向问题；`directionConfirmed` 随真实确认记录填写。

## 输出

交付正文、采用的事实编号及一份待补证据清单。咨询说明留在对话；案例包用于借鉴章节骨架、论证顺序和附件类型，企业名称、财务、客户、产能、技术参数、知识产权和人员数据取自当前企业证据台账。

报告表达采用[报告写作规则](../_runtime/report-writing.md)。
