# 申请文件核稿方法

## 依据层级

1. 现行法律与实施细则。
2. 基准日有效的专利审查指南及修改决定。
3. 目标保护中心公开规则。
4. 撰写质量建议。

无法定位现行官方依据的项目只能标记“待核验”或“撰写建议”。

## 核查矩阵

| 对象 | 核查重点 |
|---|---|
| 摘要 | 名称、技术领域、技术问题、方案要点、用途、字数和附图标记 |
| 独立权利要求 | 保护客体、必要技术特征、清楚性、支持、单一性和保护范围 |
| 从属权利要求 | 引用对象、逐路径累积特征、附加限定及引用基础 |
| 说明书 | 背景、发明内容、实施方式、公开充分性、术语和数据一致性 |
| 附图 | 图号、部件名称、附图标记和正文引用一致性 |
| 文件结构 | 表格、文本框、脚注、尾注、公式、嵌入对象、媒体和关系完整性 |

## 引用关系

核稿前先对照原始输入与工作副本，区分原文、助手新增内容和缺少的材料。缺少附图只能记附图未提供，不能据此抹去文字已记载的结构。原文已有“丝杆转动使活动夹块靠近或远离固定夹块”时，不得再称全文未记载调节方式；丝杆支承或限位是否足以实施是独立问题，应说明具体缺口。不要把同一引用错误重复拆成多条严重问题以增加问题数，正常项放在覆盖说明而非问题清单。

名称比权利要求主题多一个功能修饰词，不自动构成主题不一致；先核对保护客体与实质技术关系。摘要可以概括说明书和从属权利要求，不能仅因摘要比独立权利要求多写一个实施特征就判范围冲突，也不能仅因含功能性表述就要求删除。建议把从属特征并入独立权利要求前，必须说明没有该特征为何无法解决所述技术问题，并披露缩小保护范围的代价；无法成立时列为待确认的保护策略，不写成确定缺陷或强制补正。缺图、材料节选、待确认事项与确定错误分开统计，同一事实不要分别在名称、摘要和独立权利要求下重复计数。

先解析每项权利要求直接引用的权利要求，再展开到独立权利要求的全部合法路径。对每条路径分别检查：

- 当前项新增特征是否有引用基础；
- 同一术语是否在路径上保持同一技术含义；
- 多项引用是否继续以多项引用方式被引用；
- 择一关系、并列关系和马库什变量是否被错误压平。

三层以上嵌套、多组择一或边界无法确定时标记人工复核，不自动改写。
