# 焦糖专利申请文件核稿

把核稿作为独立轨道运行。若用户同时要求企业级全面审查，由 `jiaotang-patent-router` 另建任务记录；两条轨道分别输出。

## 任务头

记录法域、基准日、原文件 SHA-256、证据来源和保密级别。默认法域为中国。法律结论按基准日核对现行《专利法》《专利法实施细则》《专利审查指南》及适用修改决定。

## 固定流程

1. 复制原文件并计算 SHA-256，禁止覆盖原件。
2. 运行 `scripts/patent_extractor.py`，提取正文、表格、文本框、脚注、尾注、OMML 公式、OLE 对象、附图和关系。
3. 按 `references/review-method.md` 建立问题清单。每条意见必须包含原文定位、问题类型、依据层级、修改建议和置信度。
4. 用 `scripts/review_adder.py` 在副本中添加批注。默认只批注；未取得主人明确同意时，不自动替换技术内容。
5. 用 `scripts/verify.py` 比较原件与输出件的 OOXML 部件、媒体、关系和正文，验证失败时不得交付批注文件。
6. 对整页渲染、复杂表格、文本框、公式和附图执行视觉复核；无法可靠解析的 OLE 对象标记人工复核。

## 审查边界

- 法定要求、审查指南规则、保护中心规则和撰写建议分层标注。
- 不把模糊词、数值、功能性限定或“由……组成”等表达机械判错。
- 引用关系按每条从属路径分别累积特征；择一引用和多项引用不得合并成不存在的单一路径。
- 语义等同只能列为复核候选，必须结合说明书、附图和本领域通常含义裁决。
- 不补造实施例、实验数据、技术效果、附图标记或权利要求特征。

## 输出

- `review.json`：机器可读问题清单。
- `review.md`：按严重程度和章节组织的核稿报告。
- `commented.docx`：通过完整性验证后交付的批注副本。
- `verification.json`：原件与输出件的结构核验结果。
