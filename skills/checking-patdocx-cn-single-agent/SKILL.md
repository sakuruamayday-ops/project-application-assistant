# 专利申请文件核稿

记录法域、基准日、原文件 SHA-256、证据来源和保密级别，默认法域中国。法律依据按基准日核对《专利法》《专利法实施细则》《专利审查指南》及修改决定。

## 核稿流程

1. 保留原文件，在副本计算 SHA-256 后核稿。文字转 Word 时忠实转录输入，原始输入缺少的材料另列。
2. 用 `scripts/patent_extractor.py` 提取正文、表格、文本框、脚注、尾注、OMML 公式、OLE 对象、附图和关系。
3. 按 `references/review-method.md` 列意见：原文定位、类型、依据层级、建议和置信度。确定错误、待核实风险、可选建议、未提供材料分别计数；结合原文完整结构判断问题。
4. 默认以 `scripts/review_adder.py` 在副本批注；按用户提出的修订范围修改技术内容。
5. 用 `scripts/verify.py` 比较原件与输出件的 OOXML 部件、媒体、关系和正文，结合实际渲染检查复杂表格、文本框、公式及附图。待解析 OLE 列人工复核项；结构问题保留原副本并修复、复验，说明当前状态。

## 判断方法

- 分层标注法定要求、审查指南规则、保护中心规则和撰写建议。模糊词、数值、功能性限定及“由……组成”等结合上下文判断。
- 按每条从属路径累积特征，择一引用、多项引用分别追踪；语义等同结合说明书、附图及本领域通常含义复核。
- 实施例、实验数据、技术效果、标记和特征引用原稿依据；功能判断对应原文结构及动作关系，疑问定位具体待补关系。
- “固定夹块”记部件名称，“固定于底座”记连接关系；“包括”按开放式限定解释。主题名称的功能修饰词结合实际特征评价。
- 螺杆支承或轴向限位待明时，提出机构约束核实项；必要技术特征判断结合完整结构、附图和通常含义，修改建议对应原稿支持的结构。
- 片段及合成短稿中缺少的附图、章节、申请信息归未提供材料组。同一摘要附图缺口合并记录；相同动作的不同措辞结合语义判断。

## 输出

交付核稿范围、问题与修改建议、批注副本及核验结果：`review.json`、`review.md`、`commented.docx`、`verification.json`。公司级全面审查按请求衔接 `patent-router`，各项结果注明范围；引用政策文号时绑定适用依据和来源。

报告表达采用[报告写作规则](../_runtime/report-writing.md)。
