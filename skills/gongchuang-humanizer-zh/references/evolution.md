# 去 AI 味技能受控进化

## 目标

用真实改写任务中的选择、纠正和专业评审持续改进技能，同时阻止检测器驱动、样本泄露和规则漂移。

## 信号结构

每条反馈至少包含：

- 样本标识与原文哈希
- 文体和任务字段
- 候选版本及评分
- 主人或专业评审选择的胜出版本
- 失误标签与简短原因
- 是否通过事实锁、必要叙事和格式门禁

默认不保存原文。确需保存真实样本时，只记录经主人授权的本地文件路径，并确保文件位于受控资料目录。

## 评分顺序

按硬门禁和软评分两层判断。

### 硬门禁

1. 数字、名称、技术关系和限定词没有漂移。
2. 补短板、填空白、锻长板等必要叙事没有被删减或弱化。
3. 正式申报正文满足字段字数、括号和口径要求。
4. 主导产品、替代进口、填补空白和知识产权保持同一技术主线。

任一硬门禁失败，该候选不得胜出，无论 AIGC 检测得分多低。

### 软评分

| 维度 | 建议权重 |
|---|---:|
| 任务与字段完成度 | 30 |
| 申报或行业专业性 | 25 |
| 自然表达与可读性 | 20 |
| 信息密度与结构 | 15 |
| 检测器参考分 | 10 |

评分权重可随文体调整，但检测器权重不得高于专业质量或任务完成度。

## 进化循环

1. 收集同一样本的原稿、现行技能稿和候选稿。
2. 隐去版本来源，先由主人或专业规则盲评，再看检测器结果。
3. 将失误归入事实丢失、必要叙事丢失、过度压缩、模板腔、节奏机械、字段偏离、格式违规或检测器过拟合。
4. 至少出现两次同类失误，或一次高风险硬门禁失败后，才提出永久规则变更。
5. 将候选规则先放入进化报告，不直接写入 SKILL.md。
6. 使用保留样本回归，并比较现行版与候选版的胜率和硬门禁失败数。
7. 主人确认后再应用；应用后保留回滚所需的差异和评测摘要。

## 最小命令

记录一次反馈：

```bash
python3 scripts/record_feedback.py \
  --case-id case-001 \
  --domain 政府申报 \
  --field 补短板 \
  --source-file 原文.txt \
  --candidate 当前版:89 \
  --candidate 候选版:92 \
  --winner 候选版 \
  --issue 过度压缩 \
  --note 保留必要叙事后表达更清楚
```

生成候选变更包：

```bash
python3 scripts/build_evolution_pack.py
```

脚本默认读写技能目录下的 `references/evolution-feedback.jsonl`，可用 `--input` 和 `--output` 指定临时或受控路径。

## 禁止事项

- 不根据单个检测器反复改写并直接固化规则。
- 不把客户敏感原文、通信或凭据写入技能。
- 不用参与规则设计的同一批样本同时充当最终回归集。
- 不自动修改平台无关核心规则、事实锁或主人确认的必要叙事规则。
- 不把本地汇总报告描述成 GEPA、DSPy 或外部模型优化结果。
