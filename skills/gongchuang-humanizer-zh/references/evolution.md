# 去 AI 味技能受控进化

## 目标

用真实改写任务中的选择、纠正和专业评审持续改进技能，同时阻止检测器驱动、样本泄露和规则漂移。

## 信号结构

每条反馈至少包含：

- 样本标识与原文哈希
- 文体和任务字段
- 候选版本及评分
- 主人或专业评审选择的胜出版本
- 失误标签与简短原因
- 是否通过事实锁、必要叙事和格式核对

反馈默认存脱敏统计；真实样本已授权时记录受控本地路径。

## 评分顺序

从事实保持和表达质量两方面比较候选。

### 事实保持

1. 数字、名称、技术关系和限定词没有漂移。
2. 已确认叙事保留实质含义；专项审查后的替换联动全文。
3. 正式申报正文满足字段字数、括号和口径要求。
4. 主导产品、替代进口、填补空白和知识产权保持同一技术主线。

候选按事实保持、专业质量、任务完成度和可读性比较；AIGC 检测分作为辅助指标。

### 软评分

| 维度 | 建议权重 |
|---|---:|
| 任务与字段完成度 | 30 |
| 申报或行业专业性 | 25 |
| 自然表达与可读性 | 20 |
| 信息密度与结构 | 15 |
| 检测器参考分 | 10 |

评分权重随文体调整，优先反映专业质量和任务完成度，检测器作为辅助。

## 进化循环

1. 本轮比较原稿、现行稿和候选稿，保存或学习反馈按用户授权执行；普通修订应用于当前任务。
2. 隐去版本来源，先由主人或专业规则盲评，再看检测器结果。
3. 将失误归入事实丢失、必要叙事丢失、过度压缩、模板腔、节奏机械、字段偏离、格式违规或检测器过拟合。
4. 已复现问题按当前维护授权直接形成有界候选；其他反馈归纳为待评建议。
5. 将候选规则和理由放入进化报告，正式规则按维护授权更新。
6. 使用独立保留样本比较现行版与候选版的事实、质量和完成度。
7. 主人确认后再应用；应用后保留回滚所需的差异和评测摘要。

## 最小命令

记录一次反馈：

```bash
python3 scripts/record_feedback.py \
  --case-id case-001 \
  --domain 政府申报 \
  --field 补短板 \
  --source-file 原文.txt \
  --candidate 当前版:89 \
  --candidate 候选版:92 \
  --winner 候选版 \
  --issue 过度压缩 \
  --note 保留必要叙事后表达更清楚
```

生成候选变更包：

```bash
python3 scripts/build_evolution_pack.py
```

脚本读写用户数据目录：`$GONGCHUANG_SKILL_DATA_DIR/gongchuang-humanizer-zh/evolution-feedback.jsonl`；变量缺省时使用 `~/.config/gongchuang-skills/gongchuang-humanizer-zh/evolution-feedback.jsonl`。本轮临时或已授权路径通过 `--input`、`--output` 指定，候选反馈与已签名核心分别保存。

## 交付方法

- 多维比较候选后形成规则建议，当前修订直接应用本轮。
- 技能使用脱敏示例，客户敏感原文、通信和凭据留其受控来源。
- 设计样本与最终回归样本分别组织，说明覆盖范围。
- 核心规则、事实锁和必要叙事调整作为有界维护候选，沿本轮授权处理。
- 本地汇总说明实际方法、输入和结果，外部优化框架按真实执行记录说明。
