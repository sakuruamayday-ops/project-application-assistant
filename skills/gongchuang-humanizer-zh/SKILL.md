# 中文自然化改写

让文本自然、具体、可信。数字、事实和必要条件原样保持，专业判断沿用已核结果；资格、政策、法律与学术真实性按需衔接专业任务。

## 文体与强度

| 文体 | 处理重点 |
|---|---|
| 政府申报、公文 | 事实、口径、依据、字段长度，正式直接 |
| 咨询报告 | 判断在前，依据、风险与行动清楚 |
| 技术、学术 | 术语、逻辑、实验及因果依据准确 |
| 品牌、官网 | 具体卖点、可信语气和读者视角 |
| 公众号、社媒 | 作者声音、节奏和已有真实细节 |
| 知识库、说明文 | 信息密度、可检索结构及必要列表 |

沿用原文正式程度，按目标选择快速去味、标准改写、深度重写或强力精简。正式材料参考 [formal-materials.md](references/formal-materials.md)，深度改写参考 [patterns.md](references/patterns.md)，检测需求参考 [detector.md](references/detector.md)。

## 改写方法

1. 提取事实锁：数字、日期原式、金额、比例、单位、公式、字符上限；企业、产品、客户、机构、政策和项目名称；知识产权编号、标准、资质、法律状态；参数、材料、动作顺序、场景、性能条件；引用、限定、否定、比较对象和证据等级。
2. 材料事实与项目判断分列。补短板、填空白、锻长板、对标、替代等沿用对应项目已确认判断；内部矛盾保留原值并指出，企业自述保持对应来源状态。
3. 识别空洞拔高、宣传词堆叠、模糊归因、同义循环、虚假范围、聊天残留及过分整齐的句长和收束。真实技术动作、政策条件、证据类别与必要术语完整保留，形式性重复按语义精简。
4. 用已知具体事实替代空话，调整句长、连接与段落；正式文本保持专业语气。编辑要求用于指导操作，产品描述的归属按原文范围解释。
5. 核对新增事实、必要条件、限定否定、数字单位、名称和技术关系，以及文体、字段目标和自然程度。

## 审计与可选检测

事实或参数密集文本可运行：

```bash
python3 scripts/audit_rewrite.py --source-file 原文.txt --rewrite-file 改写.txt --max-chars 300
```

已有文件直接使用路径，候选保存后通过 `--rewrite-file` 审计。短文本可使用 `--source-text`、`--rewrite-text`。审计定位数字、专名、字符和格式风险，语义由逐句对照复核。对应专项判断已完成且本轮为表达改写时，可使用 `--trust-required-narrative` 并注明沿用的结果。

宿主需要 `gongchuang_professional_validate` 时，`sourceText` 取逐字原文，长文件可使用真实读取回执的 `sourceToolCallId`，二者择一；`candidateText` 对应实际改写稿，证据 `values` 引用原文片段。统计按实际需求计算。

用户要求检测时可用 `python3 scripts/score_aigc.py --file 改写.txt`，默认本地缓存，首次下载使用显式 `--allow-download`。结果记为对应模型分类概率，整体评价以事实保持、任务完成、专业质量和自然表达为主。

## 反馈学习

按用户反馈目标参考 [evolution.md](references/evolution.md)。本轮形成脱敏候选；用户要求保存或学习时，用 `scripts/record_feedback.py` 在用户数据目录记录样本哈希、场景、评分、胜出版本和失误标签。`scripts/build_evolution_pack.py` 汇总重复问题及假设，提示词候选按需衔接 `skill-evolution`。

回归采用独立保留样本，核对事实、必要叙事、字段目标、格式和专业可读性；按实际完成程度记录本地汇总或模型优化结果。候选差异、测试、签名、安装和发布由维护流程处理。

## 输出

按请求直接交改写稿，必要时附一句诊断、关键修改、事实待核项及实际审计结果。申报判断按“判断—依据—风险—建议”简述，正式正文使用直接陈述。
