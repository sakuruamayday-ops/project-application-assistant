# 检索编排协议

## 一、先形成检索计划

从问题中拆出项目、地区、年份、批次、文件类型、企业名称和用户要的是条件还是名单。只输入市级项目泛称且没有默认城市时先追问城市；已有默认城市时只加载当地市级项目。

项目简称必须展开为正式名称。名单查询同时生成公示名单、认定名单、附件和通知变体。国家专精特新“小巨人”认定批次可使用以下年份映射：2019年第一批、2020年第二批、2021年第三批、2022年第四批、2023年第五批、2024年第六批、2025年第七批、2026年第八批。映射只用于认定批次检索，不用于复核、重点小巨人或财政支持名单。

## 二、结构化与全文并行

名单问题必须并行执行：

1. 结构化路径：REST `POST /v1/lists/search` 或 MCP `public_list_search`。
2. 全文路径：REST `POST /v1/search` 或 MCP `knowledge_search`。
3. 关键命中：REST `GET /v1/documents/{id}` 或 MCP `knowledge_document`。

例如“2022年杭州小巨人名单”至少检索：

- 2022年 杭州 国家专精特新“小巨人”企业
- 2022年 专精特新小巨人 公示名单
- 第四批 杭州 小巨人
- 第四批 浙江省 专精特新小巨人
- 第四批 专精特新“小巨人”企业公示名单

结构化结果用于企业、年份、批次和地区筛选；全文结果用于找原始通知、Excel、PDF、附件及遗漏元数据。两条路径结果按文档编号、企业名称、项目和年份合并去重。

产品、行业或技术主题词反查国家小巨人、省级专精特新等企业认定时，必须使用 `recognition_search` 交叉产品/行业证据与认定证据。`authoritative_list_search` 的 `product_name`、`industry` 只对三首产品专表有意义；其他名单类型不得传入这两个字段。服务端返回“不支持筛选”时应转用 `recognition_search`，不得删掉主题筛选条件后继续把全量名单当作筛选结果。

检索执行器必须返回统一查询计划，至少包含标准项目、地区、年份、认定批次、文件阶段和检索变体。全文命中不能替代结构化名单查询，结构化名单命中也不能替代政策原文读取。

三首项目统一调用 `three_first_analysis`。服务端根据问题自动组合全文、名单、历年目录差异和企业产品匹配，不向用户暴露内部子查询，也不形成新的 MCP 配置项。

## 三、首轮未命中的回溯

依次放宽，但不能删除核心项目限定：

1. 替换简称、全称和引号样式。
2. 年份替换为认定批次，批次反查年份。
3. 增加公示、认定、名单、附件、通知等文件类型词。
4. 地区从区县回溯至城市、省份和国家名单，再按可靠地区字段筛选。
5. 使用标题、来源路径和目录分类检索旧格式文件及OCR文本。

所有路径均未命中时只能写“当前知识库检索层未命中，不能据此判断资料不存在”，随后核验主管部门官方来源。

## 四、在申报期项目提醒

项目检索、企业项目匹配和企业成长路径规划均需检查命中文件中的企业申报截止时间。仅当文件属于当前有效的申报通知或申报指南、截止时间晚于当前时间且不超过未来一年时，才标记为“当前仍在申报期”。

提醒必须包含标准项目名称、截止日期时间、距离截止天数和来源文件。企业申报截止与主管部门推荐报送截止同时出现时，优先采用企业申报截止；无法判断截止对象时不得输出精确倒计时。

倒计时按服务端北京时间动态计算，不写入静态 Skill。距离截止不足24小时显示“不足1天”，已截止项目不得继续显示申报提醒。

## 五、项目防串项

“小巨人”默认允许国家专精特新“小巨人”企业的申报通知、公示名单和认定名单。除非用户明确要求，排除专精特新中小企业、重点专精特新中小企业、重点小巨人财政支持名单、地方科技小巨人和小微企业资料。

专精特新相关资料必须先判断认定对象，不得只按标题中的“专精特新”或“小巨人”召回：

- `专精特新中小企业`：对象为企业，认定层级为省级；查询名单时排除“小巨人”、重点支持、产业园、服务机构和公共服务平台。
- `国家专精特新“小巨人”企业`：对象为企业，认定机关为工业和信息化部；排除省级专精特新中小企业、地方科技小巨人和地方自行命名的“小巨人”。
- `地方科技小巨人／地方专精特新小巨人`：属于地方独立项目，必须保留完整项目名、地区和发文机关，不得折算为国家专精特新“小巨人”企业。
- `专精特新产业园`：对象为园区或运营载体；不得进入企业资质名单或企业称号核验结果。
- `重点专精特新／重点小巨人`：属于重点培育、财政支持或高质量发展项目；不得当作新的企业认定层级。

检索排序至少使用标准项目名、认定对象、行政层级、地区、发文机关和名单性质六项。缺少认定对象或行政层级时，只能返回待核验候选，不进入精确名单统计。

查询条件时优先管理办法、认定标准和当期申报通知；查询名单时优先官方完整名单、官方分地区名单，再使用第三方动态索引。培训材料和解读文件不能作为最终名单依据。

## 六、地区归属门禁

不得通过企业名称判断登记城市。名称含“杭州”只能作为待核验候选，名称以“浙江”开头也不能排除杭州企业。

城市归属至少需要以下一项证据：

- 主管部门发布的地市名单；
- 名单自带的省、市、区县字段；
- 合法企业信息源的工商注册地址。

企业身份核验按以下顺序执行：

1. 先用规范化完整企业名称精确匹配，统一社会信用代码已知时以代码为主键。
2. 先查询云端企业身份时间轴，分别读取统一社会信用代码、历年名称、认定时名称与地区、当前名称与地区。
3. 对名单跨年关联、城市归属或复核缺失结论，优先用天眼查核对现名、曾用名、注册地址变更、同名主体、合并及重组；企查查补齐天眼查未覆盖、字段缺失、状态不明或高影响事项。
4. 两个商业源冲突，或结论会影响称号有效性、项目资格和城市统计时，回到市场监管、主管部门公示、上市公司公告或企业正式披露裁决。
5. 同名、近似名称、集团与子公司、迁址前后主体不得仅凭字符串自动合并。
6. 分别保存认定时名称与地区、当前名称与地区、变更事件、来源引用和核验时间；企业年报通信地址不得替代登记地址。
7. 只有统一社会信用代码一致，或规范名称、认定地区与变更证据共同闭环时才可自动关联；其他情况进入人工核验。

天眼查、企查查等商业源只用于主体识别和变更核验，不得替代官方名单中的认定年度、批次、状态和认定时地区。调用商业源时采用串行、缓存、指数退避和断点续传；遇到限流记录实际响应，不猜测未公开的调用上限。

省级名单没有城市字段时，先标记“城市待核验”。核验覆盖率不足100%时输出“已核验数量＋待核验数量”，不得输出精确城市总数。企业迁址时分别保存认定时城市和当前城市。

## 七、交付前检查

- 列出实际使用的结构化、全文和原文读取路径。
- 区分认定、复核、重点支持和推荐名单。
- 核对项目、年份、批次、地区和名单性质。
- 名单企业名称和序号抽样复核；表格提取注明抽样范围。
- 第三方数据标记为发现或比对线索，最终结论回到官方原文。
- 对正在申报期的匹配项目核对企业截止时间，并输出动态倒计时提醒。

完整性与计数还必须满足：

- 分别输出布尔值 `coverage_complete` 和 `truncated`；任何已调用分页路径仍有下一页时，后者必须为 `true`。
- 覆盖不完整时，中间进度和最终答复均禁用“全部闭合”“完整覆盖”“证据链已收齐”“确认不存在”及同义措辞。
- 每个分类数字标明单位、去重键和精确值/下限；显式列出的去重实体数量必须与统计一致。
- 文档数、事实行数、企业数和企业项目年度记录数分别统计。

## 八、认定与复核状态链

历年官方公示或认定名单不得被动态索引替代。官方名单用于确认当年批次、公示性质、企业名称、序号和政策时点；动态索引用于跨年、跨地区发现和比对。

全国小巨人企业级主表必须逐条保留地区、认定年度、认定批次、名单状态和官方链接。认定、复核、重点支持、地方小巨人和园区名单不得扁平合并。官方链接缺失或仅有企策发现记录时，只能标记待官方分片核验，不能作为完整官方名单交付。

判断复核状态时按以下顺序：

1. 确认企业原认定批次、认定年度和当期是否属于官方明确的复核范围。
2. 确认复核通过的最终官方名单已经印发；拟推荐、推荐汇总、公示中或平台年份不能代替最终名单。
3. 用统一社会信用代码匹配企业；暂无代码时，组合平台企业ID、规范名称、曾用名、认定时地区和当前登记地区。
4. 复核范围和最终名单均完整、身份匹配已核验，但企业不在复核通过名单时，输出材料统一标记：“未见复核通过，原称号需按当期通知作失效核验。还可能是更名、迁址或合并。”
5. 不根据名单缺失擅自区分未申请、未推荐或审核未通过；随后联网检索工信部、省级主管部门、企业公告和工商变更，核对更名、迁址、合并、重组、取消认定或复核结果。

尚未印发最终复核通过名单时，不得根据动态平台未显示新年份就判定复核未通过。
