# 检索编排协议

## 一、先形成检索计划

从问题中拆出项目、地区、年份、批次、文件类型、企业名称和用户要的是条件还是名单。只输入市级项目泛称且没有默认城市时先追问城市；已有默认城市时只加载当地市级项目。

项目简称展开为全名，同时查公示、认定、附件及通知。国家小巨人认定批次映射：2019第一批、2020第二批、2021第三批、2022第四批、2023第五批、2024第六批、2025第七批、2026第八批；复核、重点支持及财政名单各据相应通知。

## 二、结构化与全文并行

名单问题并行执行：

1. 结构化路径：REST `POST /v1/lists/search` 或 MCP `public_list_search`。
2. 全文路径：REST `POST /v1/search` 或 MCP `knowledge_search`。
3. 关键命中：REST `GET /v1/documents/{id}` 或 MCP `knowledge_document`。

例如“2022年杭州小巨人名单”至少检索：

- 2022年 杭州 国家专精特新“小巨人”企业
- 2022年 专精特新小巨人 公示名单
- 第四批 杭州 小巨人
- 第四批 浙江省 专精特新小巨人
- 第四批 专精特新“小巨人”企业公示名单

结构化结果用于企业、年份、批次和地区筛选；全文结果用于找原始通知、Excel、PDF、附件及遗漏元数据。两条路径结果按文档编号、企业名称、项目和年份合并去重。

产品或技术反查企业认定时，用 `recognition_search` 交叉产品/行业和认定证据；`authoritative_list_search` 的 `product_name`、`industry` 仅适用于三首产品专表。服务返回筛选受限时，切换 `recognition_search` 并保留主题条件。

检索执行器返回标准项目、地区、年度、批次、文件阶段和变体计划；全文、结构化名单与政策原文按各自证据用途配合查询。

三首项目统一调用 `three_first_analysis`。服务端根据问题自动组合全文、名单、历年目录差异和企业产品匹配，不向用户暴露内部子查询，也不形成新的 MCP 配置项。

## 三、首轮未命中的回溯

保留核心项目限定，依次放宽以下辅助条件：

1. 替换简称、全称和引号样式。
2. 年份替换为认定批次，批次反查年份。
3. 增加公示、认定、名单、附件、通知等文件类型词。
4. 地区从区县回溯至城市、省份和国家名单，再按可靠地区字段筛选。
5. 使用标题、来源路径和目录分类检索旧格式文件及OCR文本。

各路径未命中时写“当前知识库检索层未命中”，随后查主管部门官方来源，并说明覆盖范围。

## 四、在申报期项目提醒

项目检索、企业项目匹配和企业成长路径规划均需检查命中文件中的企业申报截止时间。仅当文件属于当前有效的申报通知或申报指南、截止时间晚于当前时间且不超过未来一年时，才标记为“当前仍在申报期”。

提醒注明项目全名、企业申报截止时间、剩余天数和来源；主管部门报送节点另列。截止对象待核时先提示核对时间。

倒计时按服务端北京时间动态计算；不足24小时显示“不足1天”，已截止项显示截止状态与后续安排。

## 五、项目防串项

“小巨人”默认允许国家专精特新“小巨人”企业的申报通知、公示名单和认定名单。除非用户明确要求，排除专精特新中小企业、重点专精特新中小企业、重点小巨人财政支持名单、地方科技小巨人和小微企业资料。

专精特新资料先识别以下认定对象，再结合完整项目名、地区和发文机关召回：

- `专精特新中小企业`：对象为企业，认定层级为省级；查询名单时排除“小巨人”、重点支持、产业园、服务机构和公共服务平台。
- `国家专精特新“小巨人”企业`：对象为企业，认定机关为工业和信息化部；排除省级专精特新中小企业、地方科技小巨人和地方自行命名的“小巨人”。
- `地方科技小巨人／地方专精特新小巨人`：按地方独立项目保留全名、地区和发文机关。
- `专精特新产业园`：归入园区或运营载体名单，企业资质另查。
- `重点专精特新／重点小巨人`：归入重点培育、财政支持或高质量发展项目，注明原有企业认定层级。

排序结合项目、对象、层级、地区、机关和名单性质；待核项先给候选，精确统计按已核范围列示。

查条件优先读管理办法、标准和当期通知；查名单优先读官方完整或分地区名单，第三方动态索引、培训和解读作发现线索。

## 六、地区归属核对

企业名称用于生成候选；登记城市按实际登记字段核对，杭州及浙江名称均结合主体资料识别。

城市归属至少需要以下一项证据：

- 主管部门发布的地市名单；
- 名单自带的省、市、区县字段；
- 合法企业信息源的工商注册地址。

企业身份核验按以下顺序执行：

1. 先用规范化完整企业名称精确匹配，统一社会信用代码已知时以代码为主键。
2. 先查询云端企业身份时间轴，分别读取统一社会信用代码、历年名称、认定时名称与地区、当前名称与地区。
3. 对名单跨年关联、城市归属或复核缺失结论，优先用天眼查核对现名、曾用名、注册地址变更、同名主体、合并及重组；企查查补齐天眼查未覆盖、字段缺失、状态不明或高影响事项。
4. 两个商业源冲突，或结论会影响称号有效性、项目资格和城市统计时，回到市场监管、主管部门公示、上市公司公告或企业正式披露裁决。
5. 同名、近似名、集团子公司及迁址主体以信用代码和变更证据核对归并。
6. 分别保存认定时及当前名称、地区、变更、来源与核验时间；年报通信地址和登记地址分别记录。
7. 代码一致，或规范名、认定地区和变更证据闭合时关联；其他候选列核验依据。

商业源用于主体和变更识别，官方名单确认年度、批次、状态及认定地区。商业调用沿 [企业数据源替代路径](../../_runtime/enterprise-source-fallback.md)，瞬时错误按实际响应处理，限流时换源并记录状态。

省级名单缺城市时标“城市待核”；部分核验时报告已核与待核数量，迁址企业分别记认定时和当前城市。

## 七、交付前检查

- 列出实际使用的结构化、全文和原文读取路径。
- 区分认定、复核、重点支持和推荐名单。
- 核对项目、年份、批次、地区和名单性质。
- 名单企业名称和序号抽样复核；表格提取注明抽样范围。
- 第三方数据标记为发现或比对线索，最终结论回到官方原文。
- 对正在申报期的匹配项目核对企业截止时间，并输出动态倒计时提醒。

完整性与计数还满足：

- 分别输出 `coverage_complete` 和 `truncated`。前者为布尔值；后者为 `true`、`false` 或 `unavailable`。任何已调用分页路径仍有下一页时为 `true`；只有全部检索路径都提供分页状态且均已到底时为 `false`；实际使用 `knowledge_search` 等无分页状态的路径时为 `unavailable`，除非其他路径已确认截断。
- 覆盖不完整时，中间进度和最终答复均禁用“全部闭合”“完整覆盖”“证据链已收齐”“确认不存在”及同义措辞。
- 每个分类数字标明单位、去重键和精确值/下限；显式列出的去重实体数量与统计一致。
- 文档数、事实行数、企业数和企业项目年度记录数分别统计。

## 八、认定与复核状态链

历年官方名单确认批次、公示性质、名称、序号和政策时点，动态索引用于跨年跨地区发现和比对，两类证据分别保存。

全国小巨人企业主表逐条保留地区、年度、批次、状态和官方链接；认定、复核、重点支持、地方项目和园区分别建类。仅有发现记录的项标待官方核验，并交付实际覆盖范围。

以可读的当期官方最终名单核对主表遗漏；申报、推荐、公示候选和年份映射分别保留其阶段。

判断复核状态时按以下顺序：

1. 确认企业原认定批次、认定年度和当期是否属于官方明确的复核范围。
2. 查明最终复核名单的印发状态，拟推荐、推荐、公示和平台年份作为相应阶段线索。
3. 用统一社会信用代码匹配企业；暂无代码时，组合平台企业ID、规范名称、曾用名、认定时地区和当前登记地区。
4. 复核范围和最终名单均完整、身份匹配已核验，但企业不在复核通过名单时，输出材料统一标记：“未见复核通过，原称号需按当期通知作失效核验。还可能是更名、迁址或合并。”
5. 名单缺项先列待核，再查工信部、属地主管部门、公告和工商变更，分别核对更名、迁址、重组、取消及复核状态。

最终复核名单尚待印发时，记“结果待正式名单确认”，继续跟踪官方发布。
