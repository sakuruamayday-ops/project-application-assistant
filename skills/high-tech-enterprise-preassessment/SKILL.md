# 高新技术企业申报体检（免费引流版）

## 商业定位与执行红线

本技能为 **WorkBuddy 免费上架的单技能体检入口**，遵循 [WorkBuddy 商业分层与 MCP 规范](../_runtime/workbuddy-core/mcp-routing-and-tiering.md)：

- **只做体检、不做撰写**：严格基于企业原件实绩与《高新技术企业认定管理办法》（国科发火〔2016〕32号）及《工作指引》（国科发火〔2016〕195号）逐项核验八大硬门槛、双年度成长性与已有材料缺口，输出结构化体检报告与四列缺陷清单（缺陷项 / 差距 / 补强动作 / 优先级）。
- **严认原件、绝不估算、绝不估分**：不替企业自打数值总分，不编造任何财务、专利或技术指标；不携带商业申请书 Word 母版或受保护九表采集工作簿。
- **单技能独立闭环 + 黑板接力**：零账号、无 MCP 连接即可独立读取用户本机材料跑完体检；核验完成后将已核事实写入当前工作区 `.facts/<企业标识>.facts.json`（`origin: enterprise_source`），供后续付费撰写无缝复用。若工作区已有撰写初稿与黑板，调用 `facts_blackboard.py reconcile` 自动回查正文估算项：人工已改为实测的自动销项，未核改的在体检核对表中客观提示核定。
- **MCP 双态与止步衔接**：未配置 MCP 时正常用上传原件完成体检，文末给出 1 句客观边界与升级引导——“高企资格体检与四列缺口清单已完成；如需撰写 RD/PS 正文、行业指标设计与原 Word 申请书母版无损回填，请连接高企撰写收费 MCP。”若已配置 MCP 但鉴权/配额异常，显式报错绝不静默降级。

地方条件按[省级管理办法检索指引](references/policy-lookup.md)核对适用办法。申报时间、截止日期与当年申报范围由客户按当期通知确认。

逐项对照资格条件与企业事实，核对矛盾、计算及时间线。资格、材料和权利使用依据国家管理办法及工作指引，地方差异按管理细则和客户提供的表单核对。创新能力评价的官方合格线和四个评价维度见[政策基线](references/policy-baseline.md)。正式评价结果用于核对该资格项，缺正式结果时列缺项及补强动作。

## 口径与输入

记录地区、客户选择的评估年度、首次或重新认定、曾未通过、三个会计年度、审定或预测状态、IP 取得方式、有效性、共有及使用情况。缺项可分情景，说明假设后继续比较。

先读取已有文件和已确认答案，将当前阶段缺失且会改变结论的字段合并成一组，每轮至多提出5个问题，少于5个时按实际缺口提问；同一资料能回答的字段合并询问，已有材料覆盖的字段直接沿用，其他可计算和可判断部分继续完成。

需要采集表时复制 [高企预评估双年度采集表.xlsx](assets/高企预评估双年度采集表.xlsx) 到新路径，按下节选取的填写范围逐年度记录人员、财务和质量状态。客户端画像 `high-tech-preassessment-workbook`，报告与工作簿分别验收。

营业收入、销售收入、总收入、净利润、利润总额分别取对应资料；缺总收入时保留输入空值及高品占比条件待核，可另算占营业收入比作经营参考。报告结论、已通过数量与工作簿使用同一状态。

旧采集工作簿先按[财务核验](../financial-verification/SKILL.md)核对各原表主体和原始比率，双年度条件只采用同主体、同口径的资料。

## 按实收材料选档

先盘点企业已提供的材料和已确认答复，按下表登记六组覆盖状态。每个结论按材料内容和可定位的证据计一次，同一份申请书可以覆盖多组。文件名、空表、只有制度无执行记录的材料，按实际能支持的字段登记。

| 材料组 | `partial` 的最低覆盖 | `complete` 的条件 |
|---|---|---|
| `qualification` 资格 | 至少一项资格条件有证据 | 主体及申报年度确定，八项资格条件均有判断依据 |
| `growth` 成长性 | 现窗销售收入或净资产至少一项能独立复算 | 现窗两项均可复算，年度及口径齐全 |
| `ip` 知识产权 | 至少一个知识产权评价子项有直接依据 | 数量、先进性、核心支持、取得方式及加分项均有判断依据 |
| `conversion` 成果转化 | 至少一项成果有来源、转化过程和应用证据 | 现窗各年有完整的转化台账和独立成果计数依据 |
| `organization` 组织管理 | 至少一个评价子项有制度和执行依据 | 各子项均有实际执行记录或已明确缺失的环节 |
| `next_window` 次年窗口 | 有一项新增或退出事实可用于次窗判断 | 次窗资格与四个评价维度均有事实或有依据的预测，新增和退出年度可逐项对照 |

其余记 `none`。宿主准备 `{"material_coverage":{"qualification":"partial","growth":"complete"}}` 形式的 JSON，逐组保留证据定位，未登记的组按 `none`。运行 `python3 scripts/compare_scenarios.py --select-intake intake.json`，把返回的 `tier`、`basis` 与 `missing_for_complete` 纳入本轮回执。没有终端时，由宿主执行同一判定表。

| 实际覆盖 | 选档 | 输出依据 |
|---|---|---|
| 六组均为 `complete` | 完整 | 比较双年度资格及各评价维度的事实、差距与补强动作 |
| 四个评价维度中至少一组为 `partial` 或 `complete`，六组仍有缺项 | 局部 | 核对已有证据支持的项目，登记缺少的材料 |
| 四个评价维度均为 `none` | 初筛 | 对照已有证据能判断的资格条件并列其余所缺资料 |

选档表示实收材料可支持的深度，用户指定更窄范围时按该范围交付。按[材料与结论映射](references/intake-tiers.md#材料与结论映射)选取九表字段并保留原工作簿和公式。

## 资格条件

从 [policy-baseline-2026.json](references/policy-baseline-2026.json) 的 `conditions` 逐项检查注册年限、领域、核心 IP 所有权、科技人员、研发占比、境内研发、高品收入、创新评价和重大事故违法事项。每项记录要求、企业现状、证据和判断。成长性档位单独对照。条件存在差距时给整改或培育路径，缺证据项保留未知。

## 成长性与缺口诊断

资格阈值和成长档位取 [policy-baseline-2026.json](references/policy-baseline-2026.json)，条款出处见[政策基线](references/policy-baseline.md)。存在版本差异时先核对当期适用文件。

按[证据核验方法](references/scoring-evidence-rubric.md)逐项比较两个年度。缺口用实际单位量化。例如占比差用百分点，成果不足用独立成果项数，证据缺口注明缺哪份材料。以下为缺陷输出结构。

```json
{"items":[{"item":"本年度 / 科技人员占比","requirement":"不低于 10%","actual":"8%","gap":"少 2 个百分点","evidence":"当年度职工及科技人员统计表","action":"复核科技人员归类与工时记录，补齐合规人员配置","priority":"高"}]}
```

用 `scripts/compare_scenarios.py` 或客户端 `high-tech-enterprise-preassessment.calculate-scenarios` 读取工作区 JSON 的 `scenarios`。各年度填 `material_coverage`、`revenue` 和 `net_assets`。缺的会计年度值填 `null`，能够独立复算的财务指标继续计算，缺项列差距及补强动作。旧底稿已有评价资料时，可沿用可选的 `scores` 容器及其中的 `coverage`、`missing_evidence`。脚本输出缺口、财务指标及资格状态。缺正式评价结果时按资格项补证，正式资格以本年度适用结果为依据。

读取 `validation_errors` 一次核对全批输入。每项包含 `field_path`、`actual`、`expected`、`fix`、`business_location`，缺值用 `null`。校验失败沿用退出码 `2`，从 stderr 的 JSON 读取问题和 `scenarios` 中可独立复算的指标。按字段位置修正同一输入后重跑，核对缺口及受影响的年度结果。

十进制精确计算后分档，最后舍入显示值。负分母、合并或报表口径变化、数据冲突列财务专项复核。资格有效期按证书三年口径，2026 认定的正常到期重新认定为 2029，监督检查另记事件。

专利数量、先进性、核心支持、取得方式和转化质量分开核验。缺项写清适用要求、已确认事实、证据、差距及补强顺序。本年与次年各按其实际材料或注明依据的预测登记。

研发部门、设备与合作按真实记录评价；政府研发机构称号与企业组织能力分别列示。未来制度、奖励和人员等预测标记情景；领域待核及其他未知项保持对应状态。

## 双年度与补强

按 [timing-and-remediation.md](references/timing-and-remediation.md) 同时计算新增财务、转化、已授权 IP，以及退出窗口的旧年度贡献；比较Ⅱ类使用、有效授权、年度数据变化及关键假设。

补强分为已发生事实的证据补齐和未来实际执行的新事实。制度、合同、转化、IP 及执行记录对应真实日期与状态，同一成果按实质计数。滚动窗口将已完成与预测分列：2024、2025 各完成 3 项、2026 预测 3 项时，确认 6 项、预测情景 9 项；年度数量按年度汇总，RD、PS、IP 分配待明确时另列缺口。

硬门槛明确不满足时停止给出当年可申报结论，列出差距及完成整改所需时间。缺证据的条件保留未知，区分已发生事实的补证和需要实际完成的建设。依据 [rd-super-deduction-strengthening.md](references/rd-super-deduction-strengthening.md) 核对立项、人员设备、工时领料、小中试、变更结题、专利、月分配、辅助账和明细账，与高企 RD、专项审计及纳税口径衔接。

## 结论与报告

用 `items` 呈现要求、企业现状、差距、证据、补强动作和优先级。正式结果或适用依据缺失的资格项列缺项，明确不满足的标出实际差额和影响。各硬门槛逐项通过后，才能给出对应资格结论。

呈现资格状态、双年度证据缺口、次年预测、滚动窗口净变化、年度建议及按时限排序的动作。

比较两个评估年度的硬门槛、证据完整度及滚动数据变化。每项建议同时展示现有依据和成立条件。

前期评估与可行性参考 `project-feasibility/references/two-report-contract.md`。前者保留关键年度决策条件，后者展开资格、四个评价维度的缺陷与差距、双年度窗口、加计扣除与动作。使用 Word 母版时按 `table_content`、`core_associations` 填已有事实及全部 RD、技术、专利、成果、收入关系。已提供制度和有效权利沿用输入状态，证明缺口另列。

## 权利和事实口径

申请、授权及有效权利分别记载。II 类在未通过申请中的使用记录与通过认定中的使用次数分别核验；I、II 类、共有及其他规则对应当期指引与属地口径。制度文本与执行记录分列，财务采用用户资料、审计、纳税申报和标明的预测。

```bash
python3 scripts/compare_scenarios.py input.json
```

脚本负责确定性计算，资格、证据与政策有效性由对应分析给出。报告表达采用[报告写作规则](../_runtime/report-writing.md)。
