# 高新技术企业预评估

## 便携运行门禁

每次触发时，从宿主提供或当前已读取的 `SKILL.md` 实际路径定位本技能目录，并运行其 `scripts/portable_skill_runtime.py prepare`。不得假设特定宿主变量或猜测路径。

先按本技能文档执行，工具调用以当前宿主实际暴露的接口为准。一般任务按需读取；用户要求源码审阅、接口核对或修复时，可直接定向读取相关源码、帮助和样例，不必先制造失败。

`fail` 表示签名、发布者身份或完整性失败，必须停用受影响副本；`limited` 表示已验签副本的依赖或偏好读写受限，仅在任务所需能力仍满足时继续并说明边界。只应用返回的 `active_preferences`；临时要求不持久化，明确授权的长期习惯才按协议保存。偏好不得覆盖真实性、安全、验签和质量门禁。完整规则见[便携运行协议](references/portable-runtime-protocol.md)。

## 总原则

先判断资格硬门槛，再评分；先列事实和数据缺口，再给申报年度建议。把企业提供的数据作为本轮分析输入，但检查内部矛盾、计算错误和时间线冲突。涉及政策、截止日期、地方材料口径或知识产权使用规则时，先核验当期国家规则、属地通知和系统要求。

政策合格线与内部风控线必须分开：

- 官方创新能力评价要求综合得分超过 70 分。
- 75 分仅可作为内部保守缓冲线，不得写成政策门槛。
- 没有同地区、同年度、同领域真实结果样本时，不输出虚构的百分比通过率；改用高、中、低把握及分数安全边际。

## 工作流

### 1. 锁定口径

确认或分情景列示：

- 申报地区、拟申报年度、截止时间；
- 首次认定、重新认定或曾申报未通过；
- 评估使用的三个会计年度；
- 当前年度数据是已审定、暂估还是预测；
- 知识产权是否自主取得、有效、共有、受让或曾用于高企申请。

信息不足但可以安全分情景时不要停止，明确假设后同时给出今年与明年结果。

需要系统采集资料时，把 [高企预评估双年度采集表.xlsx](assets/高企预评估双年度采集表.xlsx) 复制到本次任务输出目录后填写；保留技能内母版不变。采集表包含硬门槛、四年度财务、知识产权、成果转化、组织管理、双年度评分和补强计划。每个年度只填写该年度已提供的人员和财务数据，不得把最近一年人数复制到其他年度。缺失数据留空并说明；比例或人员分母缺失时使用母版“待核”结果，不以零值、公式错误或“不通过”代替未知。

客户端交付该 Excel 时使用 `high-tech-preassessment-workbook` 画像，不套用 Word 可行性报告画像。报告与采集表分别执行 artifact 校验和文件检查；报告通过不代表采集表通过。保留母版九张工作表及公式，预测、空缺和待核事项仍明确标注。

营业收入、销售收入与高企口径总收入分别取对应来源，不因数值接近或缺少其他收入明细而互相代填。只有营业收入时，采集表“总收入”年度输入留空，高品收入占总收入比例及对应硬门槛保持待核；可以另列高品收入占营业收入比例作经营结构参考，但不能用它判定认定门槛通过。Word结论、硬门槛已通过数量与Excel必须同步反映该缺口。净利润同样不能代填利润总额。

### 2. 检查硬门槛

先阅读 [policy-baseline.md](references/policy-baseline.md)，并按其中来源层级核验当前有效性。

逐项检查注册年限、技术领域、核心知识产权所有权、科技人员比例、研发费用比例、境内研发费用比例、高新技术产品或服务收入比例、创新能力评价及重大事故违法事项。

把“成长性 0 分”与“研发费用或高新收入硬门槛不达标”严格区分。硬门槛不通过时停止形成“建议申报”结论，转为整改路径。

### 3. 计算成长性

用 `scripts/compare_scenarios.py` 计算本年度和下一年度销售收入增长率、净资产增长率及保守赋分。不得凭趋势描述代替公式。

客户端优先调用 `gongchuang_skill_operation` 的 `high-tech-enterprise-preassessment.calculate-scenarios`，参数为 `input` 工作区 JSON 路径。校验台账使用一条 `kind: calculated`、`status: calculated`、`source: high-tech-enterprise-preassessment.calculate-scenarios`、`values: []` 的证据，由宿主绑定该操作回执。正文总分和成长性直接取操作结果，不另造汇总分；非财务评分仍需逐项核对依据，程序求和不代表评分依据已核验。Word、Excel如展示内部申报建议区间，使用同一回执的 `internal_recommendation_thresholds`，明确不是官方认定门槛，不另以技能名伪造已核验来源。

输入文件完整结构如下。两个申报年度各放一个 `scenarios` 元素，财务数组按对应三年由早到晚排列。示例数值仅说明结构，必须替换为企业实际输入及逐项有依据的评分，不得直接复制示例分数。

```json
{"scenarios":[{"name":"本年度","revenue":[100,110,121],"net_assets":[100,105,110.25],"scores":{"ip":{"target":25,"conservative":22,"stress":19},"conversion":{"target":20,"conservative":18,"stress":15},"organization":{"target":15,"conservative":12,"stress":10}}}]}
```

不得改成 `years`、`financials` 或把三个评分维度放在 `scores` 外。先完成两个年度的输入后合并调用一次；失败时按返回的完整示例修正输入，不逐字段试探。客户事实的证据来源和重读路径须复用真实读取结果，不手工改写文件名、连字符或扩展名。

增长率按输入十进制数值精确计算后比较分档门槛，最后才舍入展示值。不得用展示值或宽松误差容忍值进行分档，避免门槛值被降档或门槛以下被抬档。

高新技术企业资格有效期按认定证书载明的三年口径管理。2026 年认定后的正常到期重新认定节点是 2029 年，不得误写为 2027 年；监督检查或中途资格处理应另行建事件，不能与到期重新认定混同。

当分母为负、报表口径变化、合并范围变化或数据相互冲突时，标记为财务专项复核，不强行计算有利分数。

### 4. 评估非财务三项

阅读 [scoring-evidence-rubric.md](references/scoring-evidence-rubric.md)，分别形成：

- 目标分：材料完整且专家认可时可能达到；
- 保守分：现有证据能够完整支撑；
- 压力分：关键争议项按下一档处理。

每个分数必须附“评分档—事实—证据—缺口”。不得统一机械减分，也不得用专利数量替代先进性、核心支持作用或成果转化质量。

各维小计必须等于其子项相加，总分必须等于四维小计；目标、保守和压力三档的同一子项及总分应满足目标不低于保守、保守不低于压力。不能为了沿用已有总分而改写子项依据。区间下沿取值必须与实际区间一致，未来制度、奖励或绩效措施未提供时不得写成已执行。

有子项评分时，计算输入使用 `scores.ip.components` 或 `scores.organization.components` 数组，每项填写 `target`、`conservative`、`stress`，由同一 `calculate-scenarios` 操作相加；此时同维旧小计不参与计算。例如 `"ip":{"components":[{"target":8,"conservative":5,"stress":4},{"target":8,"conservative":8,"stress":7},{"target":8,"conservative":7,"stress":6},{"target":6,"conservative":4,"stress":3}]}` 得到30、24、20。示例不代表企业得分，子项依据仍须实际评定。Excel与Word引用返回的 `nonfinancial_scores` 和 `totals`，不得保留旧手填小计。

“未提供产学研、检测或管理资料”不等于企业不存在相应事实。企业已设研发部门时，应按实际组织、设备条件及合作记录评估，不能把取得政府研发机构称号增设为组织管理评分前提。领域目录尚未核对到适用条目时保持待核验；预测年度的人数、守法记录等不能沿用上一年度直接判通过。汇总结论按各项实际状态生成，不把待核验项计入已通过数量。

### 5. 比较两个申报年度

阅读 [timing-and-remediation.md](references/timing-and-remediation.md)，同时计算：

- 下一年度新增的财务、成果转化和已授权知识产权；
- 退出滚动窗口的旧年度财务和成果转化；
- Ⅱ类知识产权使用次数风险；
- 申请中知识产权能否在截止前授权的不确定性；
- 提前一年认定的税收及项目机会价值。

不得因为“计划申请若干专利”就默认下一年度更优。

### 6. 制定补强方案

把动作分为：

- 证据补强：事实已经发生，仅补齐、核对和组织真实材料，可服务当前年度；
- 事实补强：当前尚未发生，必须真实执行并形成持续记录，通常服务下一年度。

禁止倒签制度、补造合同、虚构成果转化、重复拆分同一成果或把未授权专利计入知识产权得分。

滚动窗口分别列已完成数量与未完成预测，预测不进入“已发生”列或当前保守评分。例如2024、2025各已完成3项而2026预测3项尚未完成，2024—2026窗口已确认数量为6项，9项只可列为预测情景。只有年度总数时，不自行分摊到RD项目、产品或专利；关联表保留年度汇总并标明具体分配未提供。

当前保守分未过线只支持“按现有材料暂不建议申报”。除非已核对全部可补证事实及评分上限，不能断言“当年不存在达标空间”；补证与新事实的影响分别计算，不以某单项数量不能变动推断总分必然无法提高。

高企补强清单还必须读取 `references/rd-super-deduction-strengthening.md`，核验研发费用加计扣除规范化服务是否形成从立项、人员设备、工时领料、小试中试、变更结题、专利关联到月度分配、辅助账和明细账的连续证据链。该证据链需要与高企 RD 项目、专项审计和纳税申报口径一致；资料未提供时写“待企业确认，建议补强”，不得默认已经规范归集。

### 7. 给出结论

至少输出：

1. 硬门槛结论及数据缺口；
2. 今年目标分、保守分、压力分；
3. 明年预测分及关键假设；
4. 两年度新增贡献与退出损失；
5. “今年申报／补强后今年申报／明年申报／两年均暂缓”结论；
6. 按得分提升、完成时限和责任资料排序的补强清单；
7. 会改变结论的敏感变量。

用户要求高企前期评估报告或可行性分析报告时，同时读取 `project-feasibility/references/two-report-contract.md`。前期报告只保留决定年度选择和申报可行性的核心条件；可行性报告完整呈现硬门槛、四项评分、两年度滚动窗口、研发费用加计扣除证据链和逐项补强计划。两类报告都把检测报告、产学研、成果转化、人员、知识产权等未提供事项标为待企业确认，并给出真实补强动作。

使用通用 Word 母版时，将评分四维逐项明细、双年度依据、数据口径、补强动作与倒排节点按 `project-feasibility` 的 `table_content` 回填，不保留与已有数据冲突的通用待填表。用 `core_associations` 覆盖输入中全部研发项目、技术、专利、成果及产品收入关联。输入中已说明存在的制度、有效专利与转化记录应作为本次测算事实；缺少另附证明只列核验材料，不抹去已提供事实。目标分、保守分、压力分和所谓补强上限均须逐维给出依据并复算，不凭空添加总分上限。

任务结束复盘、模型操作和签名校验过程只在对话中说明，不进入客户报告。报告仅保留业务判断、依据、风险与行动，章节编号连续且不得重复。

内部建议规则：

- 保守分不低于 75 且硬门槛全部通过：原则上建议当年申报；
- 保守分 71 至 74：仅在截止前可通过真实证据补强形成安全边际时建议当年申报；
- 保守分不高于 70：原则上转下一年度，但必须先验证下一年度确有净改善；
- 压力分显著低于 71：明确提示专家争议风险，不以目标分掩盖。

## 真实性门禁

- 专利申请不等于授权；申报节点前未授权的不计入有效知识产权。
- 曾申报未通过时使用的Ⅱ类知识产权不消耗使用次数，可在后续申报再次使用；只有曾在通过认定中使用的Ⅱ类知识产权才按已使用处理。仍需核验权属、有效性和技术关联。
- Ⅰ类与Ⅱ类知识产权的分类、共有权属和其他使用规则按当期工作指引和属地执行口径核验。
- 同一科技成果多产品、多地区或重复包装，原则上不重复计数。
- 制度文件不等于制度执行；组织管理评分必须检查实际记录。
- 财务和税务数据只使用用户资料、专项审计、年度审计、纳税申报或明确标注的预测数据。
- 地方实践、专家经验和内部缓冲线不得冒充国家政策。

## 计算脚本

准备 JSON 后运行：

```bash
python3 scripts/compare_scenarios.py input.json
```

输入格式和示例见脚本 `--help`。脚本只负责确定性计算，不替代硬门槛、证据质量和政策有效性判断。
