# 标准撰写

以标准化对象和可验证技术事实起草，按当前资料直接形成草案，缺项集中列清单。法规、强制性标准、起草规则和技术数据分别标版本及适用关系。

## 设计与依据

1. 识别层级、文件功能、制定修订或审查任务、对象、使用者、场景、地域和行业。
2. 依据矩阵记录法规、强制性标准、GB/T 1.1 与适用 GB/T 20000/20001/20002 系列、同类标准、产品试验工艺资料及国际文件，核对效力与引用关系。
3. 参考 [gbt-1-1-drafting-rules.md](references/gbt-1-1-drafting-rules.md)、[standard-type-structures.md](references/standard-type-structures.md) 设计名称、范围、章节、术语、技术来源、符合性判断、与现有标准差异及专利声明。
4. 技术指标、条件、抽样及阈值采用真实依据，待取项保持待确认；每项要求对应试验、验证和判定规则。专利、安全、环保、健康、数据及认证事项列对应核验点。

标准条款用语按性质选“应、不应、宜、不宜、可、不必、能、不能、可能、不可能”，保留其规范含义。范围界定对象、内容和适用界限；规范性引用列构成条款所需的公开文件。起草依据登记在 `evidence-ledger`，标准正文沿原结构，“规范性引用文件”原位，另交《标准数据来源说明》。

## 起草与审查

采用 [standard-draft-template.md](assets/standard-draft-template.md)，按文件功能调整章节。Markdown 章条用 `#` 至 `######` 标题，便于同稿审查及生成。

核对名称范围、必要术语、单条动作、同概念用词、表图公式引用、量单位容差及适用条件，要求与方法相互对应；检验写分类、组批、抽样、判定和复验，包装运输等对应实际对象。

编制说明采用 [compilation-note-template.md](assets/compilation-note-template.md)，写任务目的、过程、原则、技术指标来源、法规标准关系、分歧及意见处理、专利、成本效益和版本变化。

客户端审查接口 `standard-drafting.audit-draft` 使用 `{"draft":"工作区标准草案.md"}`；其他宿主可用：

```bash
python3 skills/standard-drafting/scripts/audit_standard_draft.py 标准草案.md
```

自动结果作为结构、措辞和映射检查，专业意见按实际专家或归口审查记录说明。

## 模板与交付

用户原格式模板按既有文字节点填充，保留封面抬头、段落表格、样式、红字、页眉页脚、边框合并和页面属性，过长条文优先精简。可按需使用 `skills/_runtime/template-fidelity/scripts/validate_docx_text_only.py` 及实际渲染核对成品。

按用户目标交标准草案、编制说明、独立来源说明、引用核验表、要求—试验—判定矩阵、意见处理表或问题清单，生成后提供文件入口。完整度说明可使用“可进入征求意见、补证后进入征求意见、对象与技术依据待明确”，列依据及下一步，立项发布等状态按真实进展记录。

报告表达采用[报告写作规则](../_runtime/report-writing.md)，标准正文沿标准结构。
