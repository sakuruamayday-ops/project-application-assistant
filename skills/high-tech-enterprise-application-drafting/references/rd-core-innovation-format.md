# RD核心技术及创新点批量回填规范

## 执行顺序

1. 用 `plan_hightech_inputs.py` 嗅探器盘点输入；旧 `.doc` 使用签名提取器，转换状态集中给清单并复用已有结果；
2. 用 `expand_rd_ps_tables.py` 将RD、PS数量调整为实际数量；
3. 核验企业规模、主营产品、生产方式、研发基础和公开专利；
4. 按本规范准备结构化JSON；
5. 用 `fill_rd_core_innovation.py` 同批回填RD核心技术、创新点与四项阶段性成果；
6. 脚本重新打开输出DOCX并核对每个目标单元格后，再运行 `audit_application_docx.py` 和逐页视觉检查。

## 输入JSON

资料盘点清单先标注每个文件是 `essential` 还是 `supporting`，再执行：

```bash
python3 scripts/plan_hightech_inputs.py \
  输入清单.json --state 输入状态.json --report 输入盘点.json
```

旧 `.doc` 首次返回转换清单，指纹及格式未变时复用 `stopped_no_progress` 状态，继续其他资料。

```json
{

  "enterprise_profile": {

      ]

```

`scale_evidence`、`patent_evidence` 填校准记录；提供 `stage_results` 时每个 RD 填四条。核心技术与创新点合计、阶段成果合计各按400字上限处理。检索未命中时记录主体、检索层和日期；`verified_advanced_terms` 列本企业资料、公开专利、产品、人员或测试直接支撑的术语。

可选 `basic_fields` 支持 `研发活动名称`、`起止时间`、`技术领域`、`技术来源`、`知识产权编号`、`研发经费总预算`、`目的及组织实施方式`，按原标签回填相邻物理格。缺省项保持原值；日期接受 `YYYY.M.D-YYYY.M.D`，校验顺序并补零，使用现有回填器。

示例数值用于格式说明。指标缺依据或本轮按已有事实写作时，`indicators` 填 `null` 并记 `pending_indicators`；领域待核记 `pending_field`。相应 DOCX 标 `draft`，继续检查和编辑，正式提交状态据缺口闭合情况判断。

核心技术 `indicator_kind` 区分 `proposed` 拟定与 `measured` 实测，缺省为拟定。实测项填 `indicator_source` 及工况，并按实测结果输出；拟定项附校准提示。来源字段记录依据，原始测试内容另行核验。

## 技术复杂度核对

高阶术语与 `verified_advanced_terms` 对照，证据差异随稿说明；据实际资料校准技术措辞并继续生成。

术语校准结合专利、产品、人员和测试等真实依据，差异随稿说明并继续成稿。

## 三类真实使用示例

### 正常任务

中小制造企业已提供工装夹具专利和加工记录。采用结构、定位、遮挡、节拍与换型指标撰写，脚本回填并生成通过审计。

### 边界任务

软件企业资料明确有机器学习算法软著、算法工程师和测试集记录。在`verified_advanced_terms`列入“机器学习”，并保留证据来源后，可以使用该词，但识别准确率仍标为拟定或引用实测来源。

### 证据校准任务

只有项目名时按现有资料写真实技术机制；高阶术语列直接依据或待核项，继续交付成立段落。

## 命令

```bash
python3 scripts/fill_rd_core_innovation.py \
  输入申请书.docx RD核心技术.json 输出申请书.docx \
  --report RD核心技术审计.json
```

输出保存为独立文件；显式使用 `--overwrite` 时，程序先做可恢复备份再写新文件。
