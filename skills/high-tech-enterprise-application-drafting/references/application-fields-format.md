# 整表字段回填

输入用扩缩并回填 RD 的母版副本，输出另存；金额用万元，缺值 `null`，省略模块保留原样，现有回填器按母版字段定位。

顶层 `schema_version` 可省略或填整数1；字段名称可使用带或省略 `（限400字）` 后缀的一种写法，程序按400字上限处理。回填沿用输入母版的样式、字体、字号和合并关系。

`registration`是字段名到值的对象，包含企业名称、注册时间、注册类型、外资来源地、注册资金、所属行业、企业规模、统一社会信用代码、行政区域、邮政编码、企业所得税征收方式、通信地址、企业是否上市、上市时间、股票代码、上市类型、是否属于国家级高新区内企业、高新区名称、技术领域、经营范围、企业简介。企业名称同步封面；注册时间不会写入企业名称栏。

`cover` 填企业名称、地区（也可用企业所在地区）、认定机构和申请日期。签章由实际签署流程完成。

`summary` 按母版原字段填技术领域、Ⅰ/Ⅱ类、人员、基础研究、总收入、高新收入及重大事件；企业总收入和销售收入分别输入。

`annual_financials` 填连续三个实际年度，含 year、net_assets、sales、profit、rd、domestic_rd。`profit` 对应利润总额，缺项 `null`，研发及境内支出由程序汇总。

`rd_financials` 为 RD 编号到三个年度金额的数组。例如 `{"RD01":[84,55,0]}` 的三年合计为 139。`rd_external` 和 `rd_external_domestic` 采用相同结构。项目费用分年合计与 `annual_financials` 的 `rd` 核对。费用母版只有一张表时，原年度栏标明年份顺序，金额在原格按相同顺序填写，例如 `84/55/0`，缺项用 `—`。输入已有分年费用表时，按各表标题和项目列回填。每张表的合计列汇总该表项目。超出既有项目列的字段在回执中标为未识别。

`ps`按PS表顺序提供对象，字段使用母版完整表头：产品（服务）名称、技术领域、技术来源、上年度销售收入（万元）、是否主要产品（服务）、知识产权编号、关键技术及主要技术指标（限400字）、与同类产品（服务）的竞争优势（限400字）、知识产权获得情况及其对产品（服务）在技术上发挥的支持作用（限400字）。记录数量须与PS表一致。

`innovation`四项为知识产权对企业竞争力的作用（限400字）、科技成果转化情况（限400字）、研究开发与技术创新组织管理情况（限400字）、管理与科技人员情况（限400字）。按已确认事实写作，不扩展未知专利用途、制度全称、人员岗位或转化明细。

`personnel`使用人力资源总体情况行标题，如`{"总   数（人）":[60,12]}`，两值分别为企业职工、科技人员。分项未提供则不填。

`ip` 填有状态依据的知识产权数组，可含名称、类别、授权日期、授权号和获得方式，编号连续生成；待核日期、编号填 `null`，审中项单列。按空白 IP 表的原有行依次填写，超出原行容量的记录进入回执，余行保留。已填记录的数量按实际 IP 编号读回。`ip_counts` 按原数量表填已确认值，缺资料项保持待核。

## 严格保真校验

以整表回填入口接收的 DOCX 和另存输出为两端，在技能套件根目录运行[保真校验器](../../_runtime/template-fidelity/scripts/validate_docx_text_only.py)。

```bash
python3 _runtime/template-fidelity/scripts/validate_docx_text_only.py \
  回填前.docx 回填后.docx --allow-empty-cell-text --report 保真回执.json
```

该模式允许已有空白格的原段落补一个无格式的文字载体。原有字体、字号、样式、段落、换行、行列、合并和其余包部件继续核对。读取 `batch_check` 和保真回执，并对主文件逐页核对版式。

## 批次核对表

资料提取后，可在 `plan_hightech_inputs.py` 的输入清单中登记 `source_fields`。每项填 `source_file`、`source_location`、`original_value`、`target_field` 及 `reason`。例如源位置填 `经营台账!D8`，目标字段填 `/registration/注册资金`。无法识别的目标用 `null`，并保留源位置、原值及处理原因。

把盘点报告的 `batch_check` 原样放入回填 JSON 顶层。直接使用回填 JSON 时，脚本以该 JSON 路径和字段指针登记来源。同一批次沿用 `batch_id`。

写入回执的 `batch_check.rows` 记录 `source_file`、`source_location`、`original_value`、`target_field`、`converted_value` 和 `reason`。成品回读记录实际位置与 `actual_value`。按转换值逐格比对，合计行用 `kind: total` 标识。`counts` 按实际写入范围比对 RD、PS 表和 IP 记录的预期数量与回读数量。

每行状态为 `completed`、`incomplete` 或 `unrecognized`。有未完成项时批次为 `partial`，回执保留原值、转换值、实际值及 `intermediate_artifact` 路径。已完成项继续使用。回读结束后按盘点脚本的失败指纹决定是否重做相关分支。
