## 使用边界

本技能负责申请书正文和表格，不替代高企申报前评估。申报资格、评分与申报年度选择使用 `high-tech-enterprise-preassessment`。

按以下来源优先级工作：

1. 用户本轮提供的申请书、RD、PS、知识产权、成果转化、人员、财务与制度资料；
2. 本地知识库中的《高新技术企业认定管理办法》《高新技术企业认定管理工作指引》及空白模板；
3. 企查查等企业信息工具核验登记名称、经营范围等客观字段；
4. 专利检索工具、国家知识产权公开信息及企业公开专利，用于核验企业已具备的技术方向和知识产权基础；
5. 政府官方网页和同类产品公开资料，仅用于政策核验、领域匹配、企业规模校准与拟定技术指标。

未取得支撑材料的人员数量、科技人员占比、预算、研发费用、销售收入、验收结论、专利名称与编号不得补造。可用 `XXX` 或“待企业核定”保留位置，并列出需要的证据。

## 母版

每次复制 [高新技术企业认定申请书空白模板.docx](assets/高新技术企业认定申请书空白模板.docx) 到任务输出目录后填写，禁止直接改写技能内母版。正式流程不依赖个人模板技能。

用户提供模板并要求“按原格式生成”“完全按照模板”或同义表达时，默认进入严格原样填充模式。禁止使用 python-docx 重建版式，禁止重新创建段落、表格、样式、页眉页脚或页面结构；只允许替换既有 `w:t` 文字节点。模板的整体结构、字体、字号、颜色（包括红字）、抬头、页眉页脚、表格网格、列宽、行高、合并关系、边框、节属性和页面边距必须保持不变。交付前必须运行共享门禁 `skills/_runtime/template-fidelity/scripts/validate_docx_text_only.py`，并逐页视觉检查。文字过长引起分页、行高或边界漂移时，只能压缩文字，不得通过改字号、改行距、改边距或重新排版解决。

只有用户明确要求增加或减少RD、PS表时，才切换为结构扩展模式。结构扩展不得冒充严格原样填充；优先运行 `scripts/expand_rd_ps_tables.py` 批量处理，不手工重建近似表格。脚本深拷贝编号段落和完整表格的底层OOXML，保留列宽、合并单元格、边框、行高、段落格式、分页属性和页眉页脚，清空新增表的数据区，并按 `RD01`、`RD02` 或 `PS01`、`PS02` 连续编号。知识产权和成果转化表仍复制同类完整表格后扩展，IP按用户汇总表顺序编排。

RD核心技术及创新点的批量回填使用 `scripts/fill_rd_core_innovation.py`。该脚本只改目标RD的“核心技术及创新点”数据单元格，在单元格既有段落内加入内容换行，不改变表格、行列、合并关系、页眉页脚或节属性；这属于“受控单元格内容填充”，必须与严格原样填充门禁分开报告。脚本自动读取各RD表头的四级领域，禁止用一个统一领域覆盖全部项目，并生成字段、篇幅、指标、企业能力校准和高阶术语核验审计。

当实际项目数少于现有表数时，默认仍禁止缩表。只有用户明确要求按实际数量缩减，才可增加 `--trim-empty-tail`。脚本仅从末尾逐表检查并删除完全空白的RD、PS表；任何待删除表只要存在项目或产品名称、周期、正文、经费、销售收入、知识产权、勾选状态或其他填写值，就必须阻断整个缩表操作，不得部分删除，不得删除中间表。成功删除后重新连续编号，并在JSON审计报告中记录删除位置、原编号、删除原因和连续编号状态。缩表未显式指定 `--report` 时，脚本自动在输出DOCX旁生成同名 `.docx.audit.json` 审计文件。

使用示例：

```bash
python3 scripts/expand_rd_ps_tables.py \
  输入申请书.docx 输出申请书.docx \
  --rd-count 18 --ps-count 3 \
  --report 扩表审计.json
```

安全缩表示例：

```bash
python3 scripts/expand_rd_ps_tables.py \
  输入申请书.docx 输出申请书.docx \
  --rd-count 13 --ps-count 2 \
  --trim-empty-tail \
  --report 缩表审计.json
```

输出不得覆盖输入文件，已有输出只有在明确使用 `--overwrite` 时才允许替换。

## 工作流

### 1. 读取资料与建立事实表

先提取：

- 企业完整登记名、统一社会信用代码、注册信息、经营范围与企业简介素材；
- RD项目名称、周期、原始立项目的、技术路线、人员、预算、进度与验收资料；
- 知识产权名称、类别、编号、权利人、取得方式、授权或登记时间及RD、PS对应关系；
- 产品名称、销售收入、应用场景、技术指标、检测与销售材料；
- 科技成果转化、组织管理、人员与研发场地设备证据。

区分“已提供事实”“公开核验事实”“拟定技术目标”“待补字段”。立项报告只作为事实和技术背景来源，申请书正文必须重新组织，不逐句照搬。

### 2. 企业基础信息与简介

企业名称和经营范围优先用企查查同主体记录。无法取得经营范围时留空并说明，不凭行业印象编写。

企业简介按企业基本情况、主营业务与应用场景、研发技术体系、近三年研发活动、知识产权与成果转化、发展方向组织。具体年份、数量和收入只能引用已核定资料。

### 2.1 企业能力校准

正式写作前必须核验企业规模、主营产品、生产方式、研发人员和设备基础，并检索企业公开专利或软件著作权方向。企业规模与专利检索分别保留来源、检索日期和主体锚；当前检索层未命中只能写“当前检索层未命中”，不得写成企业没有相关能力。

技术复杂度以企业实际基础为上限。传统制造业和中小企业优先围绕材料配方、机械结构、工装夹具、制造工艺、参数窗口、质量检测、设备联动和过程控制撰写。人工智能、深度学习、数字孪生、大数据平台、区块链、云边协同、自主决策等高阶表述，只有在企业资料、已核验专利、现有产品、研发人员能力或测试记录能够形成证据链时才能使用。不得为了显得先进而把常规传感、规则判断、PLC控制、数据库查询或可视化包装成高阶技术。

完整校准规则和脚本输入格式见 [rd-core-innovation-format.md](references/rd-core-innovation-format.md)。

### 3. 技术领域

按当期《国家重点支持的高新技术领域》匹配到四级。完整写出一级、二级、三级和最末级技术点，不使用只到大类的笼统表述。优先采用企业资料已明确且与核心产品、RD和知识产权一致的领域。

未找到语义和技术因果均能成立的四级条目时，不强行匹配，明确提示“请企业自行确认四级领域”，并列出最接近的候选及差异。

### 4. RD研究开发活动

每个RD正文严格按以下顺序：

1. 立项目的；
2. 组织实施方式；
3. 所属领域；
4. 核心技术；
5. 创新点；
6. 四项阶段性成果。

核心技术固定写两条，均使用“XXXX技术：”开头并展开技术机理、实现路径、关键参数和适用条件。创新点应说明相对于既有方式改变了什么、为什么能改善性能以及如何验证。具体要求见 [writing-rules.md](references/writing-rules.md)。

“核心技术及创新点”栏固定使用以下七行顺序：所属技术领域、核心技术标题、两条核心技术、创新点标题、两条创新点。所属技术领域必须逐RD读取并与该表表头四级领域一致；核心技术和创新点正文合计不少于400字，所属领域不计入。两条核心技术都必须包含“拟定技术指标”或有来源的实测指标，拟定值不得冒充第三方检测结论。

### 5. PS高新技术产品

根据RD成果的共同技术载体划分PS，不机械按每个RD生成一个产品。PS至少填写产品名称、四级技术领域、技术来源、收入、主要产品判断、知识产权编号、关键技术及指标、竞争优势和知识产权支撑作用。

技术指标可检索同类产品现状后结合RD方向拟定，但必须标注为“拟定指标”或“待企业实测校准”。正式值以规格书、检测报告、合同技术条款或实际测试记录为准。

### 6. 企业创新能力

四栏均写成完整申报逻辑：

- 知识产权对企业竞争力的作用；
- 科技成果转化情况；
- 研究开发与技术创新组织管理情况；
- 管理与科技人员情况。

按“战略或管理逻辑—现有事实—对产品及经营的作用—证据缺口”展开。不得用制度名称替代执行情况，也不得在人员资料缺失时填入人数和比例。篇幅、证据边界与表达结构见 [writing-rules.md](references/writing-rules.md)。

### 7. 汇总表字段粒度

申请书正文和汇总表必须按用途分别撰写，禁止把RD、PS正文的长段技术说明直接塞入汇总表。

- 知识产权汇总表一项一行，只写IP编号、知识产权名称、类别、授权或登记日期、授权或登记号和取得方式；申请、受理、审中、授权和登记状态不得混写，未核实字段留空。
- 高新技术产品（服务）汇总表只填写原表已有字段；产品名称使用可核算的产品或服务名称，关键技术使用简短具名技术，所属领域写到四级，RD和IP只列连续编号，技术指标只列有来源或明确标为拟定的数值指标，证明材料只列材料名称。未取得高新收入时留空，禁止写“待核定”“XXX万元”或审计说明。
- 科技成果转化汇总表按原列填写成果名称、来源、转化方式、目标产品、时间、关键技术、成效、RD、IP和证明材料；一项成果占一行，保持一张连续表并允许自然跨页，禁止人为拆成一项一页。无法确认的RD、IP、收入和数量字段留空，不自造“某年项目”等编号。
- 汇总表的文字目标是让审核人员快速核对映射关系；详细机理、竞争优势、知识产权作用和400字正文仍写入申请书相应RD、PS栏。

完整字段契约见 [高企汇总表字段粒度契约](references/summary-table-contract.md)。交付前必须运行 `scripts/hightech_delivery_gate.py summary-lint`。门禁至少检查汇总表结构、连续编号、空白事实字段和禁用占位语；若模板表头超出脚本可识别范围，必须先扩展门禁识别规则并重新回归，禁止跳过。

### 8. 格式与强制交付流程

正文和表格统一宋体小四，即宋体12磅。保持原表尺寸与分页，不因内容扩充压缩到不可读字号。

所有正式DOCX固定按“原模板复制—字段粒度检查—WPS视觉验收—哈希核对”执行。禁止用Pages、LibreOffice或Quick Look的画面代替WPS验收；这些工具只能辅助诊断。

生成后必须：

1. 从用户指定模板或技能空白母版复制到新路径，禁止覆盖母版；立即运行 `scripts/hightech_delivery_gate.py template-copy` 记录模板与工作副本SHA-256。严格原样填充任务再运行共享模板保真门禁；结构扩展任务记录扩表审计，不冒充文本节点原样填充。
2. 运行 `scripts/audit_application_docx.py` 检查字体、字号、RD核心技术格式、逐项目领域一致性、创新能力篇幅和占位符。
3. 全部修改结束后运行水印脚本和品牌交付闸门；随后对知识产权、高新产品和科技成果转化汇总表运行 `scripts/hightech_delivery_gate.py summary-lint`，确认字段粒度和连续表结构。字段粒度回执必须绑定加水印后的最终候选哈希。
4. 使用本机WPS Office打开最终候选DOCX并逐页检查。检查页数、抬头、红字、表格边界、跨页重复表头、合并单元格、溢出、断裂、重叠、空白页、页眉页脚、连续编号和字段缺失；每页记录页码、结论和截图SHA-256，再运行 `scripts/hightech_delivery_gate.py record-wps-review` 生成绑定候选文件哈希的WPS验收回执。任何后续保存都会使WPS回执失效，必须重新用WPS逐页检查。
5. 最后运行 `scripts/hightech_delivery_gate.py finalize` 核对模板复制、字段粒度、WPS逐页回执、截图数量、当前DOCX哈希和品牌闸门状态，输出最终JSON回执；返回非零状态时禁止交付。
6. 对所有数字核对来源，对拟定指标和待补字段保留提示；保留不可修改的空白母版、正式输出文件、WPS截图和最终回执。
