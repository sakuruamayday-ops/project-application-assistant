## 使用边界

本技能负责申请书正文和表格，不替代高企申报前评估。申报资格、评分与申报年度选择使用 `high-tech-enterprise-preassessment`。

按以下来源优先级工作：

1. 用户本轮提供的申请书、RD、PS、知识产权、成果转化、人员、财务与制度资料；
2. 本地知识库中的《高新技术企业认定管理办法》《高新技术企业认定管理工作指引》及空白模板；
3. 企查查等企业信息工具核验登记名称、经营范围等客观字段；
4. 政府官方网页和同类产品公开资料，仅用于政策核验、领域匹配与拟定技术指标。

未取得支撑材料的人员数量、科技人员占比、预算、研发费用、销售收入、验收结论、专利名称与编号不得补造。可用 `XXX` 或“待企业核定”保留位置，并列出需要的证据。

## 母版

每次复制 [高新技术企业认定申请书空白模板.docx](assets/高新技术企业认定申请书空白模板.docx) 到任务输出目录后填写，禁止直接改写技能内母版。个人模板库中对应模板为 `$artifact-template-v1-3-1`。

用户提供模板并要求“按原格式生成”“完全按照模板”或同义表达时，默认进入严格原样填充模式。禁止使用 python-docx 重建版式，禁止重新创建段落、表格、样式、页眉页脚或页面结构；只允许替换既有 `w:t` 文字节点。模板的整体结构、字体、字号、颜色（包括红字）、抬头、页眉页脚、表格网格、列宽、行高、合并关系、边框、节属性和页面边距必须保持不变。交付前必须运行共享门禁 `skills/_runtime/template-fidelity/scripts/validate_docx_text_only.py`，并逐页视觉检查。文字过长引起分页、行高或边界漂移时，只能压缩文字，不得通过改字号、改行距、改边距或重新排版解决。

只有用户明确要求增加或减少RD、PS表时，才切换为结构扩展模式。结构扩展不得冒充严格原样填充；优先运行 `scripts/expand_rd_ps_tables.py` 批量处理，不手工重建近似表格。脚本深拷贝编号段落和完整表格的底层OOXML，保留列宽、合并单元格、边框、行高、段落格式、分页属性和页眉页脚，清空新增表的数据区，并按 `RD01`、`RD02` 或 `PS01`、`PS02` 连续编号。知识产权和成果转化表仍复制同类完整表格后扩展，IP按用户汇总表顺序编排。

当实际项目数少于现有表数时，默认仍禁止缩表。只有用户明确要求按实际数量缩减，才可增加 `--trim-empty-tail`。脚本仅从末尾逐表检查并删除完全空白的RD、PS表；任何待删除表只要存在项目或产品名称、周期、正文、经费、销售收入、知识产权、勾选状态或其他填写值，就必须阻断整个缩表操作，不得部分删除，不得删除中间表。成功删除后重新连续编号，并在JSON审计报告中记录删除位置、原编号、删除原因和连续编号状态。缩表未显式指定 `--report` 时，脚本自动在输出DOCX旁生成同名 `.docx.audit.json` 审计文件。

使用示例：

```bash
python3 scripts/expand_rd_ps_tables.py \
  输入申请书.docx 输出申请书.docx \
  --rd-count 18 --ps-count 3 \
  --report 扩表审计.json
```

安全缩表示例：

```bash
python3 scripts/expand_rd_ps_tables.py \
  输入申请书.docx 输出申请书.docx \
  --rd-count 13 --ps-count 2 \
  --trim-empty-tail \
  --report 缩表审计.json
```

输出不得覆盖输入文件，已有输出只有在明确使用 `--overwrite` 时才允许替换。

## 工作流

### 1. 读取资料与建立事实表

先提取：

- 企业完整登记名、统一社会信用代码、注册信息、经营范围与企业简介素材；
- RD项目名称、周期、原始立项目的、技术路线、人员、预算、进度与验收资料；
- 知识产权名称、类别、编号、权利人、取得方式、授权或登记时间及RD、PS对应关系；
- 产品名称、销售收入、应用场景、技术指标、检测与销售材料；
- 科技成果转化、组织管理、人员与研发场地设备证据。

区分“已提供事实”“公开核验事实”“拟定技术目标”“待补字段”。立项报告只作为事实和技术背景来源，申请书正文必须重新组织，不逐句照搬。

### 2. 企业基础信息与简介

企业名称和经营范围优先用企查查同主体记录。无法取得经营范围时留空并说明，不凭行业印象编写。

企业简介按企业基本情况、主营业务与应用场景、研发技术体系、近三年研发活动、知识产权与成果转化、发展方向组织。具体年份、数量和收入只能引用已核定资料。

### 3. 技术领域

按当期《国家重点支持的高新技术领域》匹配到四级。完整写出一级、二级、三级和最末级技术点，不使用只到大类的笼统表述。优先采用企业资料已明确且与核心产品、RD和知识产权一致的领域。

未找到语义和技术因果均能成立的四级条目时，不强行匹配，明确提示“请企业自行确认四级领域”，并列出最接近的候选及差异。

### 4. RD研究开发活动

每个RD正文严格按以下顺序：

1. 立项目的；
2. 组织实施方式；
3. 所属领域；
4. 核心技术；
5. 创新点；
6. 四项阶段性成果。

核心技术固定写两条，均使用“XXXX技术：”开头并展开技术机理、实现路径、关键参数和适用条件。创新点应说明相对于既有方式改变了什么、为什么能改善性能以及如何验证。具体要求见 [writing-rules.md](references/writing-rules.md)。

### 5. PS高新技术产品

根据RD成果的共同技术载体划分PS，不机械按每个RD生成一个产品。PS至少填写产品名称、四级技术领域、技术来源、收入、主要产品判断、知识产权编号、关键技术及指标、竞争优势和知识产权支撑作用。

技术指标可检索同类产品现状后结合RD方向拟定，但必须标注为“拟定指标”或“待企业实测校准”。正式值以规格书、检测报告、合同技术条款或实际测试记录为准。

### 6. 企业创新能力

四栏均写成完整申报逻辑：

- 知识产权对企业竞争力的作用；
- 科技成果转化情况；
- 研究开发与技术创新组织管理情况；
- 管理与科技人员情况。

按“战略或管理逻辑—现有事实—对产品及经营的作用—证据缺口”展开。不得用制度名称替代执行情况，也不得在人员资料缺失时填入人数和比例。篇幅、证据边界与表达结构见 [writing-rules.md](references/writing-rules.md)。

### 7. 格式与校验

正文和表格统一宋体小四，即宋体12磅。保持原表尺寸与分页，不因内容扩充压缩到不可读字号。

生成后必须：

1. 严格原样填充任务先运行共享模板保真门禁，确认除既有正文文字节点外没有任何结构或格式变化；
2. 运行 `scripts/audit_application_docx.py` 检查字体、字号、创新能力篇幅和占位符；
3. 渲染为图片或PDF；
4. 逐页检查页数、抬头、红字、表格边界、合并单元格、溢出、断裂、重叠、空白页、页眉页脚、编号连续性和字段缺失；
5. 对所有数字核对来源，对拟定指标和待补字段保留提示；
6. 保留一份不可修改的空白母版和一份本次输出文件。
