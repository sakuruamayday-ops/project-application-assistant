# 专精行动型报告算法流程

适用于专精及小巨人现状评估，申请书逐字段核稿沿对应流程。

## 输入与处理

1. 结合材料、政策和资质确定产品及财务口径；已有资格安排复核、升级或建设，客户数据保存在对应任务。
2. 根据真实业务给主导产品首选及必要备选，收入、专利、技术与推荐项目使用同一产品边界。
3. 检索具体同行及产品原文，按本企业实际比较四列。
4. 按产品属性提出下一年度培育：工业新产品、装备或部件首台套、独立软件首版次、新材料首批次。建议基于已有事实继续形成，达标状态按具体条件分别核对。
5. 研发机构按已核政策档位及固定资产参考上限筛选，来源状态如实记录；数据缺项先给建设建议，其他事实继续分析。

省级报告按既定正文和表格聚焦本轮结论，前置资格在内部核验中记录真实状态；小巨人路径保留省级专精特新称号及企业实际状态。
6. 补强及软提升表同步写指标作用、价值和动作。PCT、质量、认证和数字化按当期条件，科咨说明先进性证据，CE 据机构、方式及范围核验。
7. 使用 `project-feasibility.generate-report`、`report_layout=sme-action`，沿五章19块和原表型填稿；评价与后台状态按对应展示规则处理。主导产品和同行据现有资料写，缺项集中说明；用户修订直接更新受影响 JSON 并生成新版本，申请书沿独立 Word 编辑。

## 报告内容输入

增长率按真实公式分两步记录：原值1200、现值1800，`subtract [1800,1200] = 600`，再 `ratio [600,1200] = 50`，正文50%。两步 `evidenceIds` 均引用原财务证据；比率 `ratio [1800,1200] = 150` 与增长率分别命名。

首次和修订均复用事实 JSON 及 `project-feasibility.generate-report`。修订只更新受影响的 `report_sections`、事实和计算，另存文件名，保留母版章节表型及既有来源；新增或改变事实补核，计算按实际公式记录。

同时要求省级评估和小巨人差距时，在既有 `known`、`next_tasks` 或 `conclusion` 写出“小巨人培育差距”、省级称号状态及有依据的动作。补强表与两年软提升表逐项对应，省级主报告沿自身展示规则。

每块填 `paragraphs` 文本数组，无段落填 `[]`；`rows` 每行为指定列数的文本数组，可选 `notes` 也用文本数组。固定字段如下：

| 内容块 | 表格列数 | 列序 |
|---|---|---|
| conclusion | 4 | 主导产品首选、申报主线、立即要做、最大风险 |
| policy | 2 | 条件组、申报条件怎么要求 |
| known | 4 | 关键指标、企业现有数据、判断、谈单时怎么说 |
| roadmap | 3 | 近期准备、年度建设、申报前 |
| current_tasks | 6 | 项目、安排、现行条件、已有数据、差距、立即动作 |
| next_tasks | 6 | 项目、安排、现行条件、已有数据、差距、建议动作 |
| acceptance | 4 | 内部验收项、现行明确条件、企业当前判断、申报前验收目标 |
| soft | 4 | 软提升项、现有情况、对专精线的作用、两年动作 |
| product | 4 | 口径、候选名称、结论、理由与使用条件 |
| product_boundary | 3 | 层级、本企业建议口径、取证方法 |
| peers | 4 | 对标企业或产品体系、已核验产品与能力、与本企业的异同、对本企业的启示 |
| ip | 3 | 技术簇、现有基础、需要解决的产品问题 |
| ip_topics | 3 | 技术簇、建议发明主题方向、要证明的产品价值 |
| ip_time | 3 | 近期、建设期、申报前 |
| finance | 3 | 指标万元、现有数据、期间与口径 |
| metrics | 3 | 指标、数值、含义 |
| finance_conclusion | 0 | 仅填写 paragraphs，rows 为 [] |
| finance_missing | 4 | 数据、当前状态、用途、补强时间 |
| tasks | 3 | 补强动作、补强价值、建议节点 |

`project_object` 填正文出现的推荐主导产品原名。生成器校验失败后修正输入可重用未生成的目标路径；已存在文件保留，新修订另取版本名。

## 研发设备输入字段

`research_equipment_screen` 按实际设备推荐需求提供；传入时补对应机构行，其他章节复用原内容，金额据结构化输入。

```json
{
  "research_equipment_screen": {
    "fixed_assets_yuan": null,
    "existing_basis": "来自企业材料的具体研发基础",
    "tiers": []
  }
}
```

`fixed_assets_yuan` 填基准年度固定资产期末额，支持十进制字符串，单位元。`tiers` 逐项填 `name`、`equipment_threshold_yuan`、`source`，仅列本企业地区、类型和申报状态适用的已核验档位；暂无档位时填空列表。

`screen_research_equipment` 用 Decimal 逐档比较估算上限，缺值或异常保留实际状态。内部存 status、estimate_yuan、recommended；正文给推荐及专精作用，实际设备和其他条件另据资料。

## 实现边界

设备及文档结构由程序处理，产品、政策、同行与技术由当前模型结合资料判断，直接交付可用稿和实际状态；签名、权限与发布机制按既有流程执行。
