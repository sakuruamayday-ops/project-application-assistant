# 专精行动型报告算法流程

适用专精特新中小企业与小巨人企业现状评估；不替代申请书逐字段审核。

## 输入与处理

1. 读取企业材料、适用年度政策及既有资质，锁定产品和财务口径。已有资质不重复推荐首次申报。客户数据不进入公共技能目录。
2. 根据真实业务给主导产品首选及必要备选，收入、专利、技术与推荐项目使用同一产品边界。
3. 查询数据库的具体同行，再核产品原文，形成四列比较，不用方法说明替代实际对照。
4. 填写下一年度项目。围绕专精佐证推荐工业新产品，装备或关键部件择优培育首台套，独立软件匹配首版次，新材料才匹配首批次。不得因为尚缺全部正式材料而停止给合理培育建议，也不能只因取了产品名就认定已达标。
5. 研发机构设备档位使用下述输入，由生成器计算固定资产的50%。只有适用政策已核实的档位进入 tiers；计算不验证来源真实性，来源核验仍由业务步骤负责。人员、场地、设备明细不足不阻止推荐。金额缺失或未覆盖档位时保留建设建议，不输出虚构的匹配层级。

省级正文与各表格不写前置称号、前置身份、科技和创新型中小企业等同义事项，不在其他句子补写“该称号决定能否申报”的解释。后台资格核验保留，不能因不展示而断言资格全部满足。小巨人对照行仍保留省级专精特新称号及企业实际状态。
6. 补强表与两年软提升表同步填写定性加分作用和业务价值。PCT、质量管理能力、权威产品认证、数字化按官方指标适用条件处理。科咨支撑有依据的先进性，不等同独立加分资格；CE不以标志或自我声明自动认定。同项不重复累加，不输出具体分数。
7. 使用 `project-feasibility.generate-report`，`report_layout` 为 `sme-action`。程序固定五章19块、表头、品牌与呈现过滤；隐藏条件触发块、资格与专注、具体评分及相关解释。评分过滤保留同句技术事实和补强任务的定性加分价值，不按整句或整条任务删除。主导产品、同行对照完全为空或过滤后无正文时返回具体缺口；可保留有依据的资料不足说明，不虚构内容补齐。省级不显示前置称号，小巨人保留省级专精状态。渲染检查修改处及受分页影响部分后交付。用户仍可直接修改Word；局部修改只更新相关数据。

## 报告内容输入

增长率拆成可复算的两步。例如原值1200、现值1800，先登记 `subtract`、inputs `[1800,1200]`、result `600`，再登记 `ratio`、inputs `[600,1200]`、result `50`，对应正文50%。两步的 evidenceIds 都引用原始财务证据，不引用另一个计算ID。`ratio [1800,1200]` 的结果是150而不是50；`subtract [1200,1800]` 的结果是-600。不得为了通过校验改写已正确的正文比例。

首次生成和用户后续修订均使用同一份事实 JSON 与 `project-feasibility.generate-report`。修订时读取原 JSON，仅修改受意见影响的 `report_sections` 内容、关联事实与计算；另取输出文件名，保留其他内容块。不要把整份报告重写成 Markdown 后改用通用 `evidence-ledger.create-docx` 或 `create-docx-from-file`，否则会丢失本母版的固定章节、表名与过滤规则。已取得的来源沿用，新增或改变的事实才补核；计算引用须表达实际公式，增长率不能用终值除初值的比率冒充。

用户同时要求省级报告与小巨人培育差距时，在既有 `known`、`next_tasks` 或 `conclusion` 内容块中明确写出“小巨人培育差距”及其省级专精特新称号状态、其他有依据的差距与行动；不能仅引用小巨人通知就宣称已完成该部分。省级主报告不展示自身前置称号的规则，不删除明确属于小巨人路径的省级称号对照。补强任务表和两年软提升表逐项对应，不能只在一张表里出现制造业质量管理能力评价等已要求的任务。

每块必须包含 `paragraphs` 文本数组，没有补充段落时填 `[]`，不能省略该字段。`rows` 每行都是指定列数的非空文本数组，不使用带键对象；可选 `notes` 也是文本数组。固定字段如下：

| 内容块 | 表格列数 | 列序 |
|---|---|---|
| conclusion | 4 | 主导产品首选、申报主线、立即要做、最大风险 |
| policy | 2 | 条件组、申报条件怎么要求 |
| known | 4 | 关键指标、企业现有数据、判断、谈单时怎么说 |
| roadmap | 3 | 近期准备、年度建设、申报前 |
| current_tasks | 6 | 项目、安排、现行条件、已有数据、差距、立即动作 |
| next_tasks | 6 | 项目、安排、现行条件、已有数据、差距、建议动作 |
| acceptance | 4 | 内部验收项、现行明确条件、企业当前判断、申报前验收目标 |
| soft | 4 | 软提升项、现有情况、对专精线的作用、两年动作 |
| product | 4 | 口径、候选名称、结论、理由与使用条件 |
| product_boundary | 3 | 层级、本企业建议口径、取证方法 |
| peers | 4 | 对标企业或产品体系、已核验产品与能力、与本企业的异同、对本企业的启示 |
| ip | 3 | 技术簇、现有基础、需要解决的产品问题 |
| ip_topics | 3 | 技术簇、建议发明主题方向、要证明的产品价值 |
| ip_time | 3 | 近期、建设期、申报前 |
| finance | 3 | 指标万元、现有数据、期间与口径 |
| metrics | 3 | 指标、数值、含义 |
| finance_conclusion | 0 | 仅填写 paragraphs，rows 为 [] |
| finance_missing | 4 | 数据、当前状态、用途、补强时间 |
| tasks | 3 | 补强动作、补强价值、建议节点 |

`project_object` 使用报告所推荐的主导产品原名，并在 `product` 正文或表格出现；不能填一段未在正文出现的通用评价维度。生成器检查失败不会留下占用最终路径的文件；修正输入后可使用原目标路径重试。已存在的用户文件仍禁止覆盖，另取新版本文件名。

## 研发设备输入字段

顶层字段 `research_equipment_screen` 用于需要研发机构推荐的行动型报告。未传该字段的既有输入保持原有行为，不从自由文本猜测金额。传入后，程序替换或补入“企业研发机构”行，不改动其他章节。

```json
{
  "research_equipment_screen": {
    "fixed_assets_yuan": null,
    "existing_basis": "来自企业材料的具体研发基础",
    "tiers": []
  }
}
```

fixed_assets_yuan 使用基准年度资产负债表固定资产期末金额，支持十进制字符串，单位元。tiers 每项为 name、equipment_threshold_yuan、source，表示适用项目名称、设备门槛元值、已核验的当期政策来源；不得把不适用地区、企业类型、已取得的首次认定放入其中。空列表表示尚无已核实档位，不预置全国统一门槛。

`screen_research_equipment` 用 Decimal 计算估算上限并逐档比较，等于门槛时纳入推荐，低于时不纳入。缺值不使用其他资产字段补位；负数和非有限值直接返回明确输入错误，不循环重试。内部结果包含 status、estimate_yuan、recommended；报告只输出推荐方向及对专精的作用，不输出比例、估算金额或内部方法说明。估算不回填实际科研设备原值，不证明其他认定条件已满足。

## 实现边界

设备计算与文档结构为程序执行；产品推荐、政策适用、同行事实和技术判断仍需要资料分析。本流程没有把这些判断伪装成全自动算法，也不新增发布或任务结束门禁。保留原有签名、完整性、授权与发布机制。
