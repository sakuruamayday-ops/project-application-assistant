# 可行性判断模型

## 规则台账

每条规则记录：`rule_id`、规则类型、原文、来源、地区、项目、申报年度、申请类型、有效状态和一票否决标记。

规则类型仅使用：

- `exclusion`：命中即排除；
- `hard-threshold`：满足的硬门槛；
- `scored`：有明确评分细则的项目评分项；
- `competitive`：无明确分值但影响竞争力；
- `submission`：程序、材料和时间要求。

依次核对排除项、硬门槛、评分和竞争力；门槛回指当期正式规则，历史名单、培训和解读用于参考。

## 条件状态

- `passed`：适用规则存在且证据足以证明满足；
- `failed`：适用规则存在且证据足以证明不满足；
- `pending`：存在可补证事实或待确认口径；
- `unknown`：缺少规则原文、项目版本或关键事实；
- `not-applicable`：规则明确不适用于当前主体或申请类型。

硬门槛 `failed` 时说明当前未满足及改进路径；`pending`、`unknown` 时交付条件判断和待核事项，评分与优势分别说明。
