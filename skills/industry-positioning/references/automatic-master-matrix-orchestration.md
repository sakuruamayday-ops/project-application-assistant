# 企业技术—产品—收入母矩阵自动调用协议

## 定位

母矩阵是 Agent 内部共享底稿，不是客户表单，也不是业务人员必须理解或填写的交付件。用户只需提供企业目录、申请书或技术资料；Agent 自动建立、更新、校验并调用母矩阵。

Excel仅用于以下内部场景：

- 人工抽查结构化结果；
- 大批量技术或产品记录的内部维护；
- 调试JSON往返一致性；
- 主人明确要求查看或编辑底稿。

除主人明确要求外，不主动交付Excel，不要求客户填写Excel，不把“完善母矩阵”列入客户行动清单。

## 自动触发场景

以下任务在读取企业材料后自动执行本协议：

1. 分析企业未来可申报项目、年度申报规划或项目池；
2. 多项目并行评估、企业申报体检和项目路径分析；
3. 省级专精特新、小巨人等材料体检；
4. 首批次、首台套、首版次、工业新产品、制造精品、科技计划、科技奖、高企等专项可行性分析；
5. 主导产品选层、补短板、填空白、国产替代、知识产权关联或收入边界判断。

## 自动执行顺序

1. 定位企业目录下 `reports/technical-product-revenue/enterprise_master.json`。
2. 若不存在，优先从申请书、技术文件、产品资料、研发资料和企业自述自动提取技术、产品及性能关系；技术链成立后，再从销售资料提取终端收入和客户范围。
3. 若已存在，检查本次新增材料、资料日期、产品版本和年度收入是否超出母矩阵资料范围；存在增量时只更新变化记录。
4. 执行 `validate`。校验失败时优先回到原材料修复结构；只有会改变主导产品、收入边界或项目优先级的高影响歧义才询问主人。
5. 执行 `build --projects all` 或仅生成当前项目视图。
6. 当前技能只读取对应项目视图，再叠加当期政策原文、目录和专项门槛。
7. 母矩阵和项目视图作为内部证据底稿保存；报告只输出当前决策需要的结论。

## 报告降噪规则

客户报告默认不展示完整母矩阵、JSON字段、适配器代码、哈希值和生成命令。只呈现：

1. 建议申报对象处于材料、部件、整机、软件、器械、成果或终端产品中的哪个层级；
2. 核心技术为什么能决定终端性能；
3. 收入或应用结果如何归因；
4. 对当前项目的适用、需换层或不适用判断；
5. 只列会改变结论的材料缺口。

专精特新和小巨人体检中，如需证明判断过程，可展示精简的“核心技术载体—终端产品—收入归因”三列表；完整版本矩阵仍留在内部底稿。

## 禁止事项

- 不让客户先填Excel才能开始分析；
- 不把Excel是否完整当作项目资格门槛；
- 不因没有现成母矩阵而停止任务；
- 不从发票品名反向否定内部核心技术；
- 不为每个项目重复建立平行底稿；
- 不把自动视图状态解释为项目达标结论。
