# 跨项目技术载体—终端应用—商业化证据门禁

## 适用目的

当企业核心创新位于配方、基材、核心部件、嵌入式软件、算法、控制模块或关键工艺层，而销售收入由终端材料、制品、装备、系统或服务形成时，用本门禁判断：

1. 核心技术载体是否与企业实际研发、生产和交付挂钩；
2. 核心技术如何决定终端产品性能；
3. 终端商业化收入、应用效益或成果转化如何与核心技术同边界归因；
4. 如何证明先进性而不泄露商业秘密。

## 通用原则

- 技术真实性优先依据申请书、技术文件、研发记录、产品结构、工艺流程、BOM或模块映射及企业自述判断。
- 销售台账、合同和发票用于核对终端销售、客户、收入和总量，不用于反向否定未独立销售的核心技术载体。
- 内部自产、自用核心配方、基材、部件或嵌入式软件，不以独立销售为成立前提。
- 不确认内部虚拟转移收入。商业化贡献归因到稳定搭载核心技术的终端产品、装备或系统。
- 技术层和收入层必须通过版本到终端产品映射汇合，不能把全部终端收入无差别归入。
- 采用匿名版本代号和可公开工艺窗口，不披露配方比例、原料牌号、添加顺序、关键单点参数及可复现的连续操作步骤。

## 固定审核顺序

1. **产品分层**：区分销售交付物、核心技术载体、项目申报对象和政策评价对象。
2. **技术建链**：形成“版本或技术模块→可公开工艺窗口→终端嵌入→性能贡献”。
3. **项目选层**：根据项目政策定义选择材料、部件、整机、软件、医疗器械或成果边界。
4. **商业化核对**：核对承载该技术的终端产品、客户、收入、应用效益或成果转化。
5. **两链汇合**：输出“核心技术载体→稳定生产或部署→终端应用→性能贡献→商业化结果”。

## 固定技术矩阵

| 内部版本或模块代号 | 技术目标 | 可公开技术路线 | 可公开工艺或部署窗口 | 终端应用产品或产品族 | 终端应用性能 | 材料依据 | 保密边界 |
|---|---|---|---|---|---|---|---|
| V1、A型或已有内部代号 | | | | | | | |

## 企业级母矩阵与自动转换

同一企业只维护一份内部机器底稿 `reports/technical-product-revenue/enterprise_master.json`，再由 `scripts/technical_product_revenue_matrix.py` 自动生成共享底稿和项目视图。Agent按 `automatic-master-matrix-orchestration.md` 从企业材料自动建立或更新；Excel仅作可选内部审计界面。字段结构、命令及目录规范见 `master-matrix-generator-guide.md`，项目适配规则见 `project-view-adapters.json`。

固定执行规则：

1. 技术、产品、技术产品关联、商业化、知识产权关联只在企业内部母矩阵中维护，Agent从原始材料提取并保留来源；
2. `manifest.json` 记录母矩阵 SHA-256，项目技能读取前必须校验新鲜度；
3. 哈希变化、视图缺失或适配器版本变化时统一重建全部视图；
4. 专项技能只读取自己的 `project_views/<project_id>.json`，不得另造一套平行技术矩阵；
5. 自动转换只完成申报对象选层、技术因果链与收入边界转换，不自动形成资格达标结论，也不替代当期政策核验；
6. 禁止字段和内部转移收入在生成前即判退，避免敏感配方泄露和虚假商业化归因。

## 跨项目适配矩阵

| 项目类型 | 申报对象边界 | 核心技术载体如何使用 | 商业化或应用口径 | 不得替代的专项门槛 |
|---|---|---|---|---|
| 省级专精特新 | 主导产品或产品族 | 可以采用稳定嵌入终端产品的自产自用基材、部件、软件或工艺层，重点核对专业化、创新性和一致性 | 对应终端产品收入及占比 | 当期省级评价指标、评分口径和表单要求 |
| 专精特新小巨人 | 能承载专业化、创新性、补短板和产业链价值的最小充分产品单元 | 技术载体可以直接作为主导产品，也可以采用技术载体加终端产品复合口径 | 稳定搭载技术载体的终端产品收入 | 当批次门槛、产业链要求和主导产品收入占比 |
| 首批次新材料 | 政策定义的材料产品 | 内部配方或基材必须最终形成符合目录或申报定义的材料，终端制品销售不能自动把制品变成材料 | 依当期政策核对材料销售、应用示范或保险补偿口径 | 目录品类、材料属性、检测、查新、首批次和TRL要求 |
| 首台套装备 | 整机、成套装备或政策认可的关键成套系统 | 核心部件、控制算法和嵌入式软件用于证明整机技术突破，不自动取代整机申报边界 | 整机或成套装备销售及示范应用 | 首台套定义、查新、检测、销售或应用证明 |
| 首版次软件 | 独立软件产品或政策认可的嵌入式软件 | 嵌入式软件不要求独立销售，但需建立软件版本、软著、检测、硬件载体和功能性能映射 | 按当期审计和政策认可口径归集软件产品收入 | 目录类别、软著时效、检测、研发投入和专项审计 |
| 省工业新产品、浙江制造精品 | 申报的新产品或产品族 | 内部基材、核心部件、工艺和软件用于证明新产品先进性 | 对应新产品销售、客户应用和产业化效益 | 鉴定、检测、标准、投产时间和当期评价要求 |
| 科技计划、尖兵领雁 | 项目任务或技术成果 | 技术载体与课题任务、考核指标、样机或示范应用建立映射 | 项目阶段可使用应用效益、样机验证和成果转化，不强求已有销售 | 指南方向、TRL、创新平台、企业牵头比例和任务书指标 |
| 科技进步奖 | 科技成果及其应用 | 核心技术版本与成果创新点、知识产权和应用单位建立映射 | 应用效益、经济社会效益和推广范围 | 奖励办法、完成单位、完成人、应用年限和成果评价 |
| 创新医疗器械 | 注册申报的医疗器械产品 | 核心材料、部件或算法用于证明器械创新性，不能绕过注册产品边界 | 临床或应用价值按注册和审评口径表述 | 分类、注册、临床评价、安全有效性及审评要求 |
| 高新技术企业 | 高新技术产品或服务 | 核心技术与高新产品服务、知识产权和研发活动建立对应 | 高新收入必须按专项审计口径归集，不能自动采用全部终端收入 | 高新领域、知识产权、研发费用和高新收入比例 |

## 决策输出

每个项目至少输出：

| 判断项 | 结论 |
|---|---|
| 核心技术载体是否与企业实际挂钩 | 成立／不成立／材料不足 |
| 技术载体是否决定终端性能 | 成立／不成立／材料不足 |
| 项目申报对象应选哪个层级 | 明确产品或成果边界 |
| 商业化或应用结果如何归因 | 明确终端产品、应用效益或专项审计口径 |
| 保密型技术矩阵是否需要 | 必须／不适用 |
| 项目专项门槛是否另行满足 | 逐项说明，不得被本门禁替代 |

## 判退情形

- 从发票品名直接判断核心配方、基材、部件或嵌入式软件不存在；
- 只因上游技术名称先进，就无视政策要求的材料、整机、软件、器械或成果边界；
- 将所有终端收入无差别归给某一核心技术版本；
- 虚构内部转移收入；
- 为证明先进性披露足以复现的配方或工艺；
- 用本门禁替代目录、检测、注册、专项审计、查新、TRL或其他项目专属要求。
