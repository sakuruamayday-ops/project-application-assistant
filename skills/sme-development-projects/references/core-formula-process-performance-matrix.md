# 核心配方版本—工艺窗口—终端应用性能对应矩阵

## 目的

内部自产自用载体通过“技术版本—公开工艺窗口—终端应用—性能结果”说明稳定因果，商业秘密留受控资料。

## 证据顺序

1. 先读取申请书、技术说明、研发文件、产品结构、工艺流程和企业自述，识别核心技术载体及产品层级。
2. 再建立技术因果链：核心版本解决什么问题、在哪个可公开工艺窗口稳定生产、嵌入什么终端产品、形成什么性能。
3. 最后读取销售台账、合同和发票，只核对承载该核心技术的终端产品收入、客户及总量。
4. 将两条链汇合为：`核心技术载体→稳定生产→终端嵌入→性能贡献→终端销售收入`。

核心配方、基材和内部使用技术据研发与产品资料判断；发票用于核对终端销售，技术实体的商业化可通过稳定搭载关系说明。

申请书列示的参数、产能、客户、应用、销售及专利状态沿事实锁用于本轮推导。材料冲突或计算差异保留原值，标明影响并核对；补证按实际缺口和当期政策确定。

## 固定矩阵

| 内部版本代号 | 技术目标 | 可公开技术路线 | 可公开工艺窗口 | 终端应用产品或产品族 | 终端应用性能 | 技术资料或申请书依据 | 保密边界 |
|---|---|---|---|---|---|---|---|
| V1、A型或企业已有代号 | | | | | | | |

### 填写规则

- **版本代号**：用企业研发代号或 V1/V2 等匿名名，配方细节留内部。
- **技术目标**：写需要解决的产业问题，如界面相容、耐溶剂、阻隔稳定、抗冲击或可回收。
- **可公开技术路线**：写相容增强、梯度微相、多层共挤等机理级描述，配方细节留企业受控资料。
- **可公开工艺窗口**：引用已公开的温度、层数、材料或控制目标；敏感参数用“企业内部受控窗口”表达。
- **终端应用产品或产品族**：填实际生产销售、稳定搭载该技术版本的产品；概念场景另标研发设想。
- **终端应用性能**：引用申请书或技术资料中的量化指标、验证结果或明确效果；目标值与已实现值分开。
- **技术资料或申请书依据**：写文件名称、章节、页码、表格或企业自述位置，确保可以回查。
- **保密范围**：逐行注明企业受控的信息类别。

## 保密红线

以下敏感信息保留在企业受控资料中；企业已正式公开并确认本轮可用的内容按授权引用：

- 配方组分的精确比例、添加顺序和混合时间；
- 关键原料供应商、牌号及替代关系；
- 关键温度、压力、转速、停留时间、模头间隙等单点设定值；
- 设备专有改造尺寸、控制算法参数和质量判定阈值；
- 能够与公开信息组合后直接复现核心配方或工艺的连续操作步骤。

当精确参数属于商业秘密时，可采用区间、等级、相对改善幅度、控制目标或“企业内部受控窗口”表述。体检报告评价的是技术因果是否成立，不评价企业是否公开全部秘密。

## 技术链先行、收入链后置审核流程

| 审核阶段 | 核心问题 | 优先材料 | 固定输出 | 证据用法 |
|---|---|---|---|---|
| 技术链一：产品层级 | 企业实际研发和生产的核心技术载体是什么 | 申请书、技术文件、产品结构、工艺流程 | 产品层级图或战略选层表 | 从发票品名直接确定或否定基材 |
| 技术链二：技术因果 | 核心版本如何决定终端性能 | 本矩阵、研发说明、检测或企业自述 | 技术版本到终端性能的对应关系 | 为求证明而披露敏感配方 |
| 收入链一：终端映射 | 哪些销售产品稳定搭载核心版本 | 产品目录、BOM映射、企业自述 | 核心版本到终端产品族映射 | 把全部产品收入无差别归入 |
| 收入链二：收入核对 | 对应终端产品形成多少收入 | 销售台账、合同、发票 | 终端产品收入及占比 | 确认内部虚拟转移收入 |
| 两链汇合 | 技术实体、终端应用和收入是否同一边界 | 前述两链底稿 | 主导产品、收入边界及四项判断结论 | 以收入证据替代技术真实性判断 |

## 决策使用

- 技术链成立且终端应用、收入归因成立：可保留核心配方、基材或部件层主导产品。
- 技术链成立但终端产品族映射范围不清：技术定位可以保留，收入占比标记为待完成同口径归集。
- 稳定自产、内部嵌入或性能贡献待核时，列具体缺口和技术验证动作，当前判断与证据强度相称。
- 销售资料没有核心基材品名：不构成否定理由，只需核对其终端商业化承载关系。
- 技术链和收入链共同进入 `four-judgment-decision-table.md`，分别给出保留、替换或补证后保留结论。
