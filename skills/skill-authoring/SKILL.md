# 技能创建

按用户维护目标直接建立候选，保留稳定版本及可恢复快照。候选修改、正式签名、安装和发布按本轮范围及宿主权限分别执行。

## 需求采集示例

只对当前缺口使用以下七组问题，提问时带上对应示例。已有信息的组直接复用，长期保存按用户明确的保存目标办理。

1. 角色问谁在什么岗位使用，例如申报工程师核稿。
2. 任务问拿什么输入交什么成品，例如把申请书整理成逐项意见单。
3. 知识问依什么规则，例如管理办法及表单。
4. 流程问先做什么再做什么，例如核版本后核指标。
5. 输出问成品长什么样，例如一项问题一行。
6. 工具问用什么读取或复算，例如本地文档解析器。
7. 记忆问哪些状态需要延续，例如本轮已确认的表单版本。

## 方法

1. 从真实使用示例和已核问题识别职责、触发、输入输出、分工、失败场景和依赖。
2. 提炼有价值的领域规则，入口简短，详细方法放一层 `references/`，共享方法集中复用。
3. 每个业务步骤写明任务、输入、处理方法和输出，并将输出明确为下一步所需的具体字段或产物；没有新增判断、产物或状态变化的步骤合并到相邻步骤，缺输入时注明跳过该步后仍能交付的内容。
4. 可重复或需要复算的工作使用确定性脚本，并以独立预期结果测试；缺失、冲突记录分别运行、调整顺序核对状态隔离，业务分支与结构结果分列。
5. 记录来源、作者机构、许可、可再分发范围和脱敏结果，采用权利来源明确的内容。
6. 运行适配的结构、依赖、脱敏与真实任务测试，记录差异、影响及未验证部分。
7. 按任务需要衔接 `skill-curator`、`skill-evolution`、`evolution-governance`，发布流程负责签名、完整性、安装回归和回滚。

成熟度参考 `references/skill-maturity-rubric.md`，结构初筛用 `scripts/validate_skill_structure.py`；各类验证按实际结果分别说明。
