# 一致性检查

优先处理主体、项目版本、资格、核心数字、财务勾稽、专利状态和产品收入对应，分别说明影响及最小修正。

重大问题包括：四关联断裂、政策口径混用、同一指标跨章节不一致、时间线冲突、关键证据仅有推断。

一般问题包括：术语不统一、单位缺失、来源位置不清和非核心数字差异。

提示问题包括：表达冗余、格式细节和可提升但不影响结论的证据。

任何问题均记录文件、章节、原文、证据编号、影响和建议动作。

## 跨章字段

提取文本保留章节标题、`P049` 段号或 `T01R20` 表行号。扫描可比较正文中带会计年度和单位的财务陈述，并回查主导产品、分类标签和国产替代对象的交付形态。

需要合并原表和正文定位时，`--fields` 接收 JSON 数组。每行有 `source` 文件代号、`chapter` 章节、`position` 段落或单元格、`field` 字段名和 `value` 原值。同主体跨文件需提供相同 `subject`。按真实口径填写 `period` 会计年度、`scope` 项目或统计范围、`unit` 单位。例如把申报正文的 2025 年营业收入与营收明细表 2025 列登记为同主体、同口径，元、万元、亿元统一单位后比原值。销售收入和营业收入分别登记。

回执 `observations` 可逐条定位原值，`findings` 关联冲突双方或交付形态需复核的原文。产品分类以目录条目和实际交付证据完成最终判断。

## 工程时序与证据定位质检清单（审查客户已有材料时使用）

本清单用于对客户已提交或拟提交的申报材料开展**质检与合规挑刺**（给用户输出可定位的整改与补件意见，不用于阻断撰写类技能生成正文）：

1. **三首 / 工业新产品 / 科技项目工程时序核查**：
   - `立项设计日 ≤ 样机/首件/软件开发完成日 ≤ 第三方 CMA/CNAS 检测报告日`；
   - `立项设计日 ≤ 首次销售合同日`（防止“还没立项先开卖”或“检测早于样机完成”的倒挂硬伤）；
   - 科技查新报告须由具备资质的查新机构出具且在有效期内（通常近 1 年内）。
2. **高企 RD 与专利时序核查**：
   - 知识产权申请日一般应晚于对应 RD 立项开始日；检测报告日应晚于试制或结题节点；结题验收评审签字人不得与被验收项目的研发人员重合。
3. **证据定位要求**：
   - 无论最终质检/预审结论为通过、条件通过还是不通过，每条重大缺陷与关键结论必须附精确来源位置（文件名 + 章节/页码/表号），方便顾问直接核改。
