# 数据源三级联动与知识库 MCP 对接约定

本技能套件采用**“取数与算账解耦”**设计：外部知识库与企业数据通过宿主已连接的 MCP 或本地库取得，确定性复算、红线核验、目录匹配、事实黑板落盘与成稿校验由技能包内置脚本独立完成。技能包不绑定特定域名、账号或密钥，未连接任何 MCP 时亦可完全独立运行。

## 一、三级取数优先级（自动适配三类环境）

按当前宿主实际可用能力从高到低自动选择，前一级不可用时平滑降级，不得因缺少 MCP 或本地库中断任务：

1. **第一顺位 · 已连接知识库 MCP（团队/联机模式）**
   - 当当前宿主工具列表中存在以下知识库 MCP 工具（如 `knowledge_search`、`policy_search`、`recognition_search` 等）时，**优先直接调用服务器 MCP 获取企业身份、历史名单、可比同行与政策原文**，无需先跑本地只读库。
   - 若同时连接了企查查 / 天眼查 MCP，工商股权、专利状态与司法风险优先交叉取证。
2. **第二顺位 · 本机只读企业库（单机主力离线模式）**
   - 未连接知识库 MCP、但本机已配置本地企业库（`LOCAL_KB_DB_PATH` / `LOCAL_KB_DATA_ROOT` 或默认发现路径）时，调用 `scripts/run_checkup.py profile / policy / peers` 直连本机只读库。
3. **第三顺位 · 纯单机独立模式（零外部依赖）**
   - 既未连接知识库 MCP 也无本地企业库时，直接基于用户上传的审计报告、专利清单、申请书等原始材料 + 宿主联网检索（查官方公开政策与专利全文）完成全流程；《产业链架构》与《产业基础创新发展目录（2021）》直接由包内内置索引离线检索（`scripts/run_checkup.py catalog`）。

## 二、知识库 MCP 真实工具能力映射

当宿主已连接知识库 MCP 时，按任务场景直接调用对应工具，并把返回事实送入本地复算与黑板脚本：

| 业务需求 | 优先调用的 MCP 工具 | 衔接的技能包本地能力 |
|---|---|---|
| 确认 MCP 连通性与索引状态 | `knowledge_service_status` | 连通即走第一顺位，不可用时降级 |
| 核验企业现名、曾用名与身份血缘 | `enterprise_identity_lineage_lookup` | 配合 `fact_ledger.py` 做 GB 32100 信用代码校验并落盘黑板 |
| 查专精特新、小巨人、三首等专表权威名单 | `authoritative_list_search` | 核对企业与同行历史资质、批次与认定时点 |
| 查一般公示与认定名单 | `public_list_search` | 补齐荣誉资质清单与历年认定记录 |
| 按项目/地区/主题找可比同行 | `recognition_search` | 结合 `peer-point-in-time-rules.md` 按申报当年回溯对标 |
| 查省市区县现行政策与有效期 | `policy_search` | 核验现行门槛，省外补「当年+上年」联网核对 |
| 按地区与关键词初筛理论可报项目 | `project_catalog_match` | 结合 `run_checkup.py hightech / sme` 做硬条件复算 |
| 全文检索政策原文、通知与范本 | `knowledge_search` + `knowledge_document` | 命中摘要后务必用 `knowledge_document` 回读关键原文 |
| 调取同类项目历史案例包 | `knowledge_case_pack` | 用于结构、指标口径与论证参考（严禁照搬他企数据） |
| 查首台套/首批次/首版次历史获评与产品 | `three_first_analysis` | 衔接 `general-grant-writer` 的三首合规核验 |

## 三、联动纪律

- **取数走 MCP，算账走脚本**：MCP 返回的企业数据、财务数、专利数和政策门槛，进入正式体检、写稿或质检前，仍须经过包内脚本做确定性复算、专利有效期校验与主体隔离黑板落盘。
- **回读原文不拍脑袋**：调用 `knowledge_search` 仅拿到片段时，涉及关键门槛、年限或加减分口径，须再用 `knowledge_document` 回读原文。
- **未命中如实说明**：任何一层未命中时如实说明检索范围并自动切入下一顺位，不编造资质、文号或数据。
