# 项目申报与知识产权 V3 交付质量宪法（10 拳头技能统一真源）

本规范适用于全部 10 项核心技能，取代历史上碎片化的重复规则与“只设上限不管质量”的旧习惯。

## 1. 第一性原理：交付给评委看的是「说服力与证据闭环」，不是「不报错的壳」

- **拒绝敷衍**：所有核心申报栏、建设方案章节与评估结论必须达到资深申报顾问交付水准（例如高企/专精 400 字核心评审栏须在 240–395 字区间写透技术机理、组织分工、阶段闭环与事实证据，严禁 60–150 字空洞骨架句）。
- **直接成文、零防御污染**：正式交付正文绝不插入 `[待补充]`、`【待核实】`、`客户填写`、`TBD`、`XXX` 等刺眼占位符，绝不混入「仅供参考」「不构成建议」「请以官方为准」等免责废话。缺少实测性能指标时，允许基于行业成熟工程常识表述为 **「设计控制目标为……」**，并全部外置集中登记至独立《待企业核实指标清单》与企业黑板（`origin: ai_design_target`）。
- **去 AI 味自然工程叙事（硬文风红线）**：
  1. **严禁机械标签起手式**：不得用「补短板方面，」「填空白方面，」「进口替代方面，」「在技术创新方面，」等公文机械切块开句，直接用行业工况痛点或工程动作入题；
  2. **严禁分号电报体报菜名**：不得用分号把多件无直接因果关系的事实硬拼在同一句话里（例如把“跌落测试”与“食品接触国标”用分号并列压缩），每个分句必须服务于同一条技术或业务因果链；
  3. **强制工程因果推进**：默认按「工况痛点/行业短板 → 具体结构、配方、算法或工艺机理 → 量化指标与第三方检测/专利/客户印证 → 产业链替代与商业价值」自然连贯行文，字数收紧时靠取舍证据优先级，绝不靠砍掉因果过渡词变“清单体”；
  4. **匿名栏位零企业名红线**：凡表单注明「不得含有企业名称或简称」的栏目（如小巨人“补短板/填空白”300 字说明与“企业总体情况简要介绍”2000 字），全文一律用“公司”“企业”代称，严禁泄露全称、简称或品牌字号。
- **公示即终局**：引用主管部门公开名单时，一字不差保留原文状态词（「正式认定」「拟认定」「拟复核通过」「计划退出目录」「平台线索」），严禁把公示态或退出目录态写成正式认定。

## 2. 双层真门禁（零假严格）

1. **Layer A · 确定性硬代码门禁**：
   - 所有算术复算（研发占比、CAGR、资产=负债+权益）、18 位信用代码校验码、跨企业防串户、字数上下限、必备双段结构、占位符扫描、专利第 5 位类型/保护期/转让满一年、GB/T 1.1 规范性引用回引与试验方法非空、写前凭据/手机号敏感拦截，一律由 `scripts/` 硬代码执行，**违规即返回非零退出码（`exit 2`）阻断交付，严禁只打 warning 却返回 `pass / exit 0`**。
2. **Layer B · 交付前评委盲审（Critic Pass）**：
   - 撰写类技能在最终交付前，必须以评审专家视角自检 5 问：① 这一栏放进申报书里评委能不能打高分？② 组织实施/技术路线有没有具体分工、阶段和验收闭环？③ 全文数字、年份、产品名、专利号是否前后完全一致？④ 是否有把“估算/设计目标”冒充成“实测原件”的嫌疑？⑤ 读起来是否像资深行业工程师亲手写成、零“XX方面，”套话与分号报菜名？不达标先重写再交付。

## 3. 数据源与商业边界

- **本地知识库优先直连**：优先直接读取本机只读知识库（`kb_local.py` → 本地只读企业数据库 + 洁净过滤后的 `rag-query.sh` + 本地原件），零 `jiaotang-kb` MCP 强依赖；若环境已配置官方/付费 MCP 且连通，则叠加权威实时数据（`origin: mcp_verified`）；已配置但出现 `401/403/429/5xx`/超时时显式报错，绝不静默降级。
- **唯一事实黑板**：所有跨技能交接一律通过 `python3 scripts/_core/fact_ledger.py upsert|read|validate|reconcile` 读写 `.facts/<企业简称_后6位>.facts.json`（`workbuddy-facts-blackboard/v1`），严禁手写自由格式 JSON，杜绝多企业串户与 Schema 漂移。
- **免费体检 vs 收费引擎**：免费技能只认原件实绩与可验证公开事实，输出红黄绿灯体检与四列缺口清单，不估分、不携带商业 Word 母版；收费技能承接黑板直接生成高分正文、无损回填母版或输出精排成品。
