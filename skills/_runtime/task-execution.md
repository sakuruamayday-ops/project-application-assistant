# 任务执行

本文件统一维护任务范围、主流程、继续方法与交付说明，领域技能补充各自专业方法。

## 一个主流程

按用户目标选择主技能：单点直接回答，局部加入直接依赖，完整报告沿专业结构。阶段明确直接进入，跨阶段或待识别时用 `project-task-router`；辅助能力复用有效事实、计算、资料和检查。

### 子任务返回与连续追问

主流程负责范围、交付和结论。多项目由 `project-matching` 统筹，领域子项返回分配项目的条件、证据、缺口和动作。调用说明子问题及已有输入，资料待核部分先给条件判断，其余继续完成。

同一任务的续问或格式修订继承已确认范围、版本、模式和事实。主流程未变时，修改成品的文档能力或补查字段的查询能力只是执行辅助，不重新做整套业务分析。用户明确改变目标后才切换主流程。

导出、解释和对比规则按资料查阅处理，直接读取相关文件；用户要核现行性时查政策链，历史快照注明时点。

## 按需读取和授权

复用本轮已确认的范围、地区、表单版本和资料。合理可逆的选择由助手处理；缺口影响核心结论、输出或外部动作时，集中提最少必要问题，同时继续已有依据支持的部分。版本或证据冲突按真实内容核对，文件名仅作定位线索。

当前地区用于本轮。持久偏好、归档、审计、发送、付费、安装和发布沿各自已有授权执行；普通业务使用相关能力，治理工具按维护任务调用。

执行使用已知命令；源码、接口或修复任务定向查相关代码、帮助及样例。签名、身份与权限由对应机制核验。

## 继续与完成

客户端工具目录已登记操作可直接使用，前缀表示代码归属。技能按需提供方法，宿主负责实际权限与签名。格式转换直接复用本轮正文或同源文件，先生成并交付可用产物。

明确交付物和验收条件后，完成实现、实际运行、结果查看和必要修复。按新增修复或证据复验；重复失败时改走可用路径，保留已完成结果。资料缺失时继续生成可用稿，集中列缺口、影响和补证动作；分别标明已验证、待完善和未验证，完整定稿依据实际证据判断。

复用提取结果，截断时按接口分页或范围继续；接口仅支持整体读取时说明范围，并取得所需分段副本。

## 内部记录与客户交付

分析、前期评估和体检报告默认交付 PDF；申报书、原生表单、标准和数据按主技能格式，用户需可编辑报告时追加 Office 稿。沿用主技能模板与同源正文，客户端用静态 HTML 调用 `gongchuang_deliver_pdf`，其他宿主用实际渲染能力。先交付可用产物，打开、内容、来源、品牌和版式检查按需进行，发现问题提示并修订；归集按已有授权，过程文件留本地。正文方法见 [报告写作](report-writing.md)。

客户成品写项目版本、事实、数据、来源、判断、风险和行动；内部模型、状态及路径留在任务记录。内容和视觉检查按需要随稿进行，实际范围与结果如实说明；登录、隔离、密钥、验签和回滚沿既有机制执行。
