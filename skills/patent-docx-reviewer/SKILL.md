# 专利申请文件核稿（patent-docx-reviewer）

本技能承接中国专利申请 Word 保护范围审查、精准批注（支持同段落 `occurrence_in_paragraph` 锚点定位及必填「保护范围影响」校验）与 OOXML 完整性核验，遵循本地 `references/v3-delivery-constitution.md` 质量宪章。

记录法域、基准日、原文件 SHA-256、证据来源和保密级别，默认法域中国。法律依据按基准日核对《专利法》《专利法实施细则》《专利审查指南》及修改决定。

## 核稿流程

命令行批注及 OOXML 核验依赖 [lxml](requirements.txt)。在对应 Python 环境执行 `python3 -m pip install -r requirements.txt` 后，运行下列脚本。

用户明确要求“快速体检”或“先看形式与结构”时，核对编号、引用方向、章节、摘要长度、术语及附图标记，输出覆盖清单、发现项和未进入的实质审查项后结束该分支；必要技术特征、支持、公开充分性及保护策略按完整核稿流程处理，完整核稿请求直接沿既有授权连续完成。

1. 保留原文件，在副本计算 SHA-256 后核稿。文字转 Word 时忠实转录输入，原始输入缺少的材料另列。
2. 用 `scripts/patent_extractor.py` 提取正文、表格、文本框、脚注、尾注、OMML 公式、OLE 对象、附图和关系。完整稿回读摘要、权利要求书、说明书和附图说明。片段提取使用 `--allow-partial`，读取 `missing_sections` 并按实有材料核稿。
3. 按 `references/review-method.md` 逐条核稿并记录依据层级。每条核稿意见在原文定位、类型、依据、建议和置信度之外，标明“保护范围影响：限缩、扩大或不动”并说明所依据的权利要求特征；影响尚缺原稿依据时写“缺范围判断依据：具体材料”，补齐前保留原文，批注文字与意见单使用同一标注。确定错误、需要核实的风险、可选建议、未提供材料分别计数。结合原文完整结构判断问题。
4. 默认以 `scripts/review_adder.py` 在副本批注。读取 `expected`、`applied`、`skipped`，修复未定位的意见后再验收。按用户提出的修订范围修改技术内容。
5. 执行 `scripts/verify.py 原稿.docx 批注稿.docx --reviews-file review.json`，核对应批数量与实际新增数量，比较 OOXML 部件、媒体、关系和正文。结合实际渲染检查复杂表格、文本框、公式及附图。待解析 OLE 列人工复核项，结构问题保留原副本并修复、复验。

## 判断方法

- 分层标注法定要求、审查指南规则、保护中心规则和撰写建议。模糊词、数值、功能性限定及“由……组成”等结合上下文判断。
- 按每条从属路径累积特征，择一引用、多项引用分别追踪；语义等同结合说明书、附图及本领域通常含义复核。
- 实施例、实验数据、技术效果、标记和特征引用原稿依据；功能判断对应原文结构及动作关系，疑问定位具体待补关系。
- “固定夹块”记部件名称，“固定于底座”记连接关系；“包括”按开放式限定解释。主题名称的功能修饰词结合实际特征评价。
- 螺杆支承或轴向限位待明时，提出机构约束核实项；必要技术特征判断结合完整结构、附图和通常含义，修改建议对应原稿支持的结构。
- 片段及合成短稿中缺少的附图、章节、申请信息归未提供材料组。同一摘要附图缺口合并记录；相同动作的不同措辞结合语义判断。

## 输出

意见单与批注逐条沿用核稿流程第3步的保护范围影响标注及权利要求依据。

交付核稿范围、问题与修改建议、批注副本及核验结果：`review.json`、`review.md`、`commented.docx`、`verification.json`。公司级全面审查按请求衔接 `patent-strategy-assistant`，各项结果注明范围；引用政策文号时绑定适用依据和来源。

报告表达采用[报告写作规则](../_runtime/report-writing.md)。
