# 项目匹配

## 商业定位、MCP 双态与黑板接力

本技能为 **WorkBuddy 免费上架的单技能体检/核查入口（企业申报项目筛选）**，遵循 [WorkBuddy 商业分层与 MCP 规范](../_runtime/workbuddy-core/mcp-routing-and-tiering.md)：

- **免费只做体检与核查**：零账号、无 MCP 即可基于本机上传原件独立跑通，交付候选项目导航表与申报顺序与四列缺口清单（缺陷项 / 差距 / 补强动作 / 优先级）；严认原件实绩、绝不估算编数、不携带商业 Word/Excel 母版。
- **主体隔离黑板接力**：按企业全称/统一社会信用代码读写工作区 `.facts/<企业标识>.facts.json`（主体不一致一律跳过防串户），复用上游已核事实并将本轮已核事实标记 `origin: enterprise_source`。
- **MCP 双态与止步引导**：未配置 MCP 时正常离线/本地完成全部核查，文末自然提示“基础核查已完成；如需进一步获取完整成品，请连接项目申报可行性评估或专项撰写收费 MCP”；已配置 MCP 但鉴权/配额异常时显式报错，绝不静默降级。

围绕用户目标输出项目方向、依据、差距和优先级；单项目详细判断按需衔接 `project-feasibility`。任务组织参考[共享任务说明](../_runtime/task-execution.md)。

## 匹配方法

1. 按企业属地、行业、产品、规模、研发、资质、知识产权及投资计划检索管理办法中的项目类别。包内入口为 `references/high-frequency-project-rules.jsonl`，每条记录给出适用办法、条款及匹配条件。
2. 包内缺该项目或属地的办法时，按[管理办法检索](../_runtime/policy-online-lookup.md)定位现行办法、实施细则或工作指引。项目地图和名称索引用于查询正式名称与类别。
3. 回读管理办法，逐项比对企业条件与证据后排序。条件和项目资格见 `references/project-matching-rules.md`，输出沿用 `references/policy-application-path-contract.md`。
4. 分列条件已具备、补齐条件后复检和培育方向。申报时间、截止日期与当年申报范围由客户按当期通知确认。

## 完整路径

正文保留与企业相关的主目标梯度、研发平台、绿色、数字化、IP、质量品牌和产业化方向，按条件成熟度、建设后、条件触发或长期梯度排序。每项采用路径合同的十二字段，列起点、任务、依赖、建议年度、流程、证据、关键条件和责任动作。无业务关联的类型简述排除依据。新增规则或补齐关键证据后复检。

## 简称与地区

按 `references/high-frequency-project-retrieval-rules.json` 映射正式名称。含混简称可结合地域和上下文给候选并继续已确定部分：

- 科小分浙江省科技型中小企业、国家科技型中小企业；绿色工厂分区县、市、省、国家。
- 未来工厂按地区对应杭州市 AI 工厂或浙江省未来工厂；单项冠军分浙江省和国家。
- 重点小巨人为重点小巨人企业高质量发展奖补，重点省专、重专对应浙江省重点专精特新中小企业。
- 研发中心、企业研究院等项目按属地和层级核对正式名称及适用管理办法。

地区采用本轮范围或已确认默认值。区县通常覆盖该区县、所属市、省和全国，其他区县在用户指定比较时加入。`regions=["待确认"]` 保留待核，临时地区范围与长期偏好分别管理。

## 来源与资源

用 `scripts/filter_project_map.py` 按地区与关键词筛选办法索引或项目名称。见[筛选命令](references/project-index-cli.md)。输出沿用 `project_id` 关联政策、模板、案例和附件。客户提供的项目表单用于填报。

报告表达采用[报告写作规则](../_runtime/report-writing.md)。
