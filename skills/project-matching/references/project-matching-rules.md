# 项目匹配规则

## 四道判断门

| 判断门 | 回答的问题 | 主要输入 | 允许的结论 |
|---|---|---|---|
| 项目地图召回 | 这家企业理论上应关注什么 | 项目名称、类别、级别、主管部门 | 候选项目类型 |
| 企业画像匹配 | 企业与项目方向是否相关 | 地区、行业、产品、规模、资质、研发、知识产权、投资 | 高、中、低关联度 |
| 动态索引检查 | 当前是否存在通知 | 本地索引、增量索引、发布日期、截止时间 | 当期线索或培育方向 |
| 官方原文核验 | 企业最终能否申报 | 管理办法、当期通知、附件、企业证据 | 可重点申报、补充后申报、持续培育、暂不建议 |

## 召回逻辑

1. 从企业注册地与实际经营地确定国家、省、市、区县检索范围。
2. 用主营业务、主导产品和所属产业匹配项目名称、分类与主管部门。
3. 用企业规模和发展阶段召回梯度项目，例如初创、科技型中小企业、专精特新、小巨人和单项冠军。
4. 用研发、有效授权知识产权、研发机构和产学研情况召回科技创新类项目。审中专利不得当作授权成果。
5. 用设备投资、数字化改造、节能降碳、绿色生产和产线建设计划召回技改、数字化和绿色发展项目。
6. 用外贸、跨境电商、服务贸易、品牌、标准、人才、农业等特征召回对应专项。

## 排除逻辑

- 地区明确不符且不允许跨区申报时排除。
- 企业类型、成立年限、规模或行业属于硬性否决项时排除。
- 已获得同等级资质、不允许重复申报或处于限制期时排除。
- 存在严重失信、安全、环保、税务或重大质量风险，且政策明确否决时排除。
- 财务数据无可靠来源时不推算，标记“待企业提供”而不得自动判定达标。

## 排序逻辑

候选项目按以下因素排序，不伪造精确成功率：

1. 硬性条件已满足且证据完整。
2. 当期通知有效且时间充足。
3. 主导产品、产业方向和有效授权知识产权关联度高。
4. 已有材料、历史项目和资质能够形成完整证据链。
5. 项目之间无重复申报、资金冲突或时间冲突。

## 时效与降级

- 先检查索引最后成功更新时间；索引过期则先增量更新或补采。
- 高频规则卡中 `rule_status=historical-reference` 的条件只能用于召回和预判，不得直接作为当期资格结论。
- 当高频表格与专用新版规则卡冲突时，优先使用 `rule_status=current` 的规则卡。市级征求意见稿不得当作已生效条件。
- 索引不可用时直接查询政府官方来源，不得凭经验补造当期项目。
- 第三方索引命中但未找到官方原文时，只能标记“待官方核验”。
- 项目地图命中但动态索引和官方来源均未命中时，只能作为培育方向。

## 输出要求

对每个项目同时输出：项目类型、匹配理由、不匹配或待补条件、当期状态、索引来源、官方原文、下一步动作。
