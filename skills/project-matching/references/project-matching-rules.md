# 项目匹配规则

## 四道判断门

| 判断门 | 回答的问题 | 主要输入 | 允许的结论 |
|---|---|---|---|
| 项目类别匹配 | 这家企业应关注哪些项目 | 适用管理办法列出的项目类别、申请对象、所属行业和地域 | 候选项目类型 |
| 企业画像匹配 | 企业与项目方向是否相关 | 地区、行业、产品、规模、资质、研发、知识产权、投资 | 高、中、低关联度 |
| 规则定位 | 该项目有哪些稳定依据 | 官方政策库、原文文号、管理办法及其附件 | 管理依据或培育方向 |
| 条件核验 | 企业条件和证据是否齐备 | 管理办法、指引、企业证据 | 条件已具备、补充后复检、持续培育、暂不建议 |

## 召回逻辑

1. 从企业注册地与实际经营地确定国家、省、市、区县检索范围。
2. 用主营业务、主导产品和所属产业匹配管理办法规定的项目类别和申请对象。项目地图用于定位标准名称与主管部门。
3. 用企业规模和发展阶段召回梯度项目，例如初创、科技型中小企业、专精特新、小巨人和单项冠军。
4. 据研发、有效授权 IP、机构和产学研召回科技项目，审中专利按实际状态列后续布局。
5. 用设备投资、数字化改造、节能降碳、绿色生产和产线建设计划召回技改、数字化和绿色发展项目。
6. 用外贸、跨境电商、服务贸易、品牌、标准、人才、农业等特征召回对应专项。

## 排除逻辑

- 按管理办法规定的地域及跨区规则筛选，地域差距列迁移或其他适用路径。
- 企业类型、成立年限、规模或行业属于硬性否决项时排除。
- 已获同等级资格或处限制期的项目，按管理办法的复核、升级、重复申报及间隔规则确定后续路径。
- 存在严重失信、安全、环保、税务或重大质量风险，且政策明确否决时排除。
- 财务来源待取得时标“待企业提供”，先完成其他有依据的匹配。

## 排序逻辑

候选按以下因素排序，说明依据、缺口和优先级：

1. 硬性条件已满足且证据完整。
2. 适用管理依据可回查，关键证据能够补齐。
3. 主导产品、产业方向和有效授权知识产权关联度高。
4. 已有材料、历史项目和资质能够形成完整证据链。
5. 项目之间无重复申报、资金冲突或时间冲突。

## 时效与降级

- 先查包内管理办法，按项目及属地补查现行管理办法、实施细则或工作指引。
- 核对原文效力、适用对象和随文附件，再决定候选项目及条件状态。
- 只有名称线索时，列出培育方向及缺少的适用办法。

## 输出要求

对每个项目同时输出：项目类型、匹配理由、不匹配或待补条件、条件状态、管理办法及条款、下一步动作。
