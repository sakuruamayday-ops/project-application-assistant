# 经验记录

经验摘要使用可泛化方法、核验依据和适用条件，敏感材料以脱敏摘要表达。个人习惯交 `first-run-configuration` 的偏好接口，通用纠正交后续聚合；技能候选由维护流程处理。

## 四问复盘

适用成果在最终对话结合实际结果回答一组，客户交付正文保持读者内容：

1. 最没有把握之处及现有证据。
2. 最大遗漏或仍需检查之处。
3. 最有价值的改进；客户产品任务可给最值得增加的功能。
4. 更高效的做法。

相关性较低的项简述原因。可泛化候选按需交 `skill-curator` 查重、`skill-evolution` 形成差异、`evolution-governance` 管理验证与发布。

## 纠正记录

用户纠正、回归失败和核验质量问题先形成本轮摘要。按用户明确的记录、记住、沉淀或审计日志要求，使用 `scripts/record_correction.py` 写入 JSONL，记录技能、稳定规则键、脱敏任务标识、摘要及核验状态；相同任务、技能、规则和摘要去重。

```bash
python3 scripts/record_correction.py   --skill <技能名> --rule-key <稳定规则键> --task-id <脱敏任务标识>   --summary <脱敏问题摘要> --verified
```

单条记录作为证据；自主聚合参考 `skill-curator`，用户指定修复直接形成对应候选。
