# 结果交付契约

## 业务层与表现层

同一业务结果以固定 result 保存事实、计算、结论、证据引用及实际完成状态，按 result-delivery-contract.md 约定的键序、UTF-8 编码和保留数据类型的序列化计算 SHA-256 作为 result_digest；文字、卡片和朗读适配只改变 presentation 与 representation_id，适配后重新计算业务摘要，业务字段变化时建立新结果版本。

## 摘要规范

- 只对 `result` 计算摘要。对象键保持唯一并按 Unicode 码点升序递归排列，数组保持原顺序。
- 使用紧凑 JSON，分隔符周围无空白。字符串中的双引号和反斜杠分别写成 `\"`、`\\`，U+0000 至 U+001F 使用小写十六进制的 `\u00xx` 转义，其余字符原样输出。
- 保留 JSON 数据类型。数字使用无指数的精确十进制表示，小数去掉尾零及多余的小数点，零统一写成 `0`。布尔值和空值使用 `true`、`false` 和 `null`。
- 序列化结果采用无 BOM、无末尾换行的 UTF-8 编码，计算 SHA-256 后以小写十六进制记录 `result_digest`。

## 结果取回

跨端或跨轮取回已有结果时，同时比对本次返回的业务结果标识、结果版本和 result_digest 与原记录，并对取回的 result 重算摘要；身份或摘要任一不一致时列出差异，停止将其复用为原结果，访问凭证由宿主安全接口处理，结果标识和摘要只用于比对。

业务结果标识、结果版本和摘要任一缺失时，列出缺项并停止按原结果复用。
