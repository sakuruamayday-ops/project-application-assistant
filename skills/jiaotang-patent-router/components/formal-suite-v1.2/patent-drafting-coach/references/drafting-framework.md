# 专利撰写框架

## 技术交底书

1. 技术名称和应用场景。
2. 现有技术及其具体缺陷。
3. 拟解决的技术问题。
4. 核心方案及必要组成。
5. 工作原理或处理流程。
6. 区别于现有技术的关键特征。
7. 技术效果及证据。
8. 实施例、参数范围和附图说明。
9. 可替代结构、步骤、材料或算法。
10. 已公开情况和申请时间要求。

## 权利要求层次

- 独立权利要求保留解决技术问题所必需的特征。
- 从属权利要求依次加入结构关系、步骤顺序、参数范围、材料选择、控制方式和优选实施方式。
- 装置、方法、系统、介质或用途等类别必须有真实技术基础和说明书支持。
- 每个术语在权利要求、说明书和附图中保持一致。

## 说明书检查

| 检查项 | 问题 |
|---|---|
| 支持 | 权利要求的每项概括是否能在说明书中找到依据 |
| 清楚 | 相对词、功能词和参数是否有可判断边界 |
| 充分公开 | 本领域技术人员能否据此实施 |
| 一致性 | 名称、编号、步骤和附图是否一致 |
| 变体 | 是否覆盖合理替代方案而非仅有单一实施例 |
| 效果 | 技术效果是否有实验、测试、实施或机理支持 |

## 审查意见分析

按“审查结论—法律依据—引用文件—对应权利要求—争议特征—可用说明书依据—可选答复路径—修改风险”建立表格。不要在未阅读完整审查意见、引用文件和原申请文本时直接生成正式答复。
