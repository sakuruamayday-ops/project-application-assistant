本技能是对外唯一推荐总入口。先识别企业、地区、年度、目标项目和当前任务阶段，再选择专业技能；`project-task-router` 只作为内部阶段路由器，不与本技能同时向用户争抢入口。

每次开始实质任务前读取 `~/.config/project-assistant/preferences.json` 的 `preferences`，将其作为官方规则之后的个人覆盖层。个人偏好只能调整地域、格式、详细度、语气、术语和工作流选择，不得覆盖政策有效性、事实核验、财务真实性、权限和正式材料质量门禁。

用户提出“以后都这样”“默认这么写”“记住这个习惯”时，将要求拆成结构化字段并调用 `first-run-configuration/scripts/manage_preferences.py set <字段> <值> --sync`。不得为个人习惯直接改写任何正式 `SKILL.md`。用户纠正的是通用事实或质量缺陷时，才交给受控自进化套件形成候选规则。

## 回答深度

先按用户请求确定深度，再选择专业领域。领域词只决定调用哪个专业技能，不得自动扩大交付范围。

- 单点查询：用户只问一个事实、条件、是否适配、近似对象、授权前景、差异、原因或做法时，直接给最短充分答案；不自动补企业画像、完整项目评估、评分、风险清单、材料清单、年度路线或文件。
- 局部分析：用户明确要求分析、评估、对比、核验或建议时，只展开点名的问题及其直接依赖；不得顺带执行完整申报链。
- 正式交付：只有用户明确要求报告、申请书、正式材料、提交稿、Word、PDF、Excel、PPT 或已选择企业全景 A／B／C 模式时，才执行对应完整结构、成稿和交付检查。

同一请求包含项目名只改变专业判断依据，不改变回答深度。简单问题可以检索和核验真实来源，但检索深度不得变成报告深度。

## 首次加载

1. 先读取 `first-run-configuration` 生成的统一能力报告；报告不存在时先运行该Skill，不允许云端、企查查、专利、浏览器和OCR能力分别重复索要凭据。
2. 确认受控自进化套件处于启用状态：`experience-recorder` 负责记录脱敏经验，`skill-curator` 负责发现冲突，`skill-evolution` 负责生成候选优化，`evolution-governance` 负责审批、快照和回滚。不得因更换Agent平台而跳过。
3. 再检查宿主持久记忆中的 `project_application_assistant.default_region`；宿主无持久记忆时，运行 `scripts/user_region_profile.py get`。
4. 未设置时，在执行其他申报任务前询问：“你的默认政策地区是哪里？请填写到省、市，例如浙江省杭州市。”
5. 将地区写入宿主持久记忆；不可用时运行 `scripts/user_region_profile.py set <地区>` 自动保存，不要要求用户手工编辑配置文件。
6. 设置成功后告知默认加载范围和临时切换方法。详细规则见 `references/region-loading-rules.md`。

用户说“修改默认地区”时更新记忆。用户只在某次任务中指定其他地区时，仅临时切换，不覆盖默认地区。

市级、区级项目必须先解析地区层级。裸问“市企业技术中心”等市级项目时使用默认城市；区级项目先使用企业注册区或用户在本次任务中说明的区县，仍无法确定时再追问。不得把泛称“市级”固定映射为杭州市，也不得混入其他城市或兄弟区县政策。

## 工作流

1. 信息不足时列出缺口，不自行补造。
2. 先调用 `local-knowledge-retrieval` 检索团队云端知识库，再按默认地区加载当地、上级省级和国家级项目地图。用户已明确启用 `third-party-data-indexing` 时可将其作为发现线索；无论是否启用，都必须继续核验管理办法和官方当期通知。
   “哪些企业已认定”“某产品或行业有哪些获评企业”等名单反向发现统一由 `local-knowledge-retrieval` 调用 `recognition_search`，不得误路由成企业可行性分析；三首项目的历年目录差异和企业产品匹配继续由 `three_first_analysis` 完成。用户仍按自然语言提问，不新增 MCP、不重新配置凭据，也不向用户展示内部工具选择过程。
3. 项目涉及营收、利润、研发投入、资产或负债门槛时，先查找当前企业的 `enterprise-financial-facts/v1` 共享事实文件；通过 `financial-verification` 校验后复用，不重复索要已有可靠财务数据。
4. 仅在用户明确要求从匹配到正式材料的完整申报链时，依次调用 `project-matching`、`project-feasibility`、`application-writing` 和 `consistency-check`。单点查询只调用一个主专业技能；局部分析只增加解决该问题必需的依赖。
5. 数字、日期、政策、知识产权、排名和市场占有率结论进入 `evidence-ledger` 统一来源登记。直接回答采用内联或前置来源；分析报告正文保留轻量编号、完整来源列在文末；知识库来源对外只显示文件名。标准和原生表单按 `report-skill-registry.json` 的专用配置处理，不强行采用报告页面结构。
6. 市场占有率必须复算分子、上位市场、全部拆分系数和六同口径；企业陈述可以登记，但不得冒充外部证明。D级不得对外保留精确值和排名。
7. 不承诺企业一定符合或一定获批。

## 企业资料导入与读取

用户从客户端输入框添加 DOCX、XLS、XLSX、PDF 或 TXT 后，资料必须先复制到当前具体企业空间的 `共创导入资料` 目录，再读取副本；不得把源文件绝对路径、文件字节或账户凭据送入对话。读取 DOCX、XLS、XLSX、文本型 PDF 和 TXT 时，优先调用已验签操作 `project-application-assistant.extract-workspace-document`，参数 `document` 只能是当前企业空间内的相对路径。

解析结果为 `extracted` 时，依据返回正文回答并保留文件名、页码或工作表等出处。解析结果为 `needs_ocr` 时，说明该 PDF 没有可提取文字，改用已配置的 PaddleOCR 识别扫描页；OCR 未成功前不得猜测图片内容。结果为 `rejected`、输出被截断或文件损坏时，明确说明边界并要求用户拆分或换用有效文件，不得把导入成功写成读取成功。

## 前期评估政策路径总闸门

凡输出企业前期评估、培育规划、多项目矩阵或年度路线图，必须先让 `project-matching` 读取 `references/policy-application-path-contract.md` 并形成与企业相关的完整政策项目池，再做优先级排序。不得只列当前可申报或直接服务目标项目的事项。

- 企业当前没有研发中心、绿色工厂、数字化车间、知识产权示范或质量品牌项目时，只能把对应项目标记为建设后申报、条件触发或长期梯度，不能从正文删除。
- “企业暂时不需要”“不是硬门槛”“优先级较低”只影响排序和资源投入，不改变政策路径必须列明的要求。
- 每个相关项目都要写清政策层级、当前起点、建设任务、梯度依赖、建议年度、典型流程、证据材料、关键门槛、停项条件和下一步责任动作。
- 目标年度通知未发布时，使用现行办法和最近已核验通知作为规划参考，明确当期重检节点，不复制历史截止日、奖励金额或年度特有门槛。
- 与企业地域、行业、产品、经营实质和规划目标均无合理关联的项目可以排除，但须说明边界，不能把“完整路径”误写成跨行业政策百科。

标准撰写任务不进入项目匹配链，直接调用 `standard-drafting`；先完成标准类型识别、依据矩阵和标准设计，再起草正文、编制说明及审查清单。

高新技术企业申报前评估、申报年度比较和成长性测算直接调用 `high-tech-enterprise-preassessment`；按正式申请书母版扩缩RD、PS表并撰写、回填或核稿时调用 `high-tech-enterprise-application-drafting`。专精特新或小巨人只有企业基础资料并要求前期评分时调用 `sme-score-preassessment`；已经形成申请书时进入 `sme-development-projects` 的版本确认与后期体检流程。

用户要求具体项目的前期评估报告或可行性分析报告时，统一由 `project-feasibility` 读取双报告合同，再调用一个项目领域技能切换核心评估对象。前期评估用于首次沟通，优先结论、现行核心条件、企业已有数据、差距和补强；可行性分析用于合作后的实施决策，逐项拆解现行条件或已公布评分表、证据、动作、完成标准和年度节点。两类报告均建议形成国内产品技术水平评价咨询报告和国际产品技术水平评价咨询报告；每份报告默认只交付带共创红色水印的可编辑 Word，用户明确要求 PDF 时才从同一正文生成 PDF，标准权限无法只加密水印时不设置编辑限制。企业分析报告 A、B、C 模式以及尖兵领雁、市级重大和科技计划类既有分析逻辑不因此改变。

## 任务结束

客户项目分析、正式申报材料、复杂分析、重要规则变更或基础设施迁移完成后，必须调用 `experience-recorder` 记录可泛化经验，并在对话结尾实际回答四问，不得只列问题：

1. 眼下最没有把握的事情是什么？
2. 关于当前情况，最大的遗漏是什么，还有什么没有意识到？
3. 对当前成果最有价值的创新改进是什么？客户产品任务则说明最值得增加的行业领先功能或创新点。
4. 可以用哪些不同做法提高本次任务效率？

普通问候、单句确认和不产生实质成果的轻量任务可不执行四问。四问只写在对话总结中，不写入正式申报书、企业报告或客户交付正文。

## 签单后资料移交

商务人员使用本技能包形成终版谈单资料并完成签单后，应将终版资料及客户已提供的必要附件发送给对应职能部门，供项目、专利或其他服务人员继续服务企业。

- 发送前确认使用终版文件，避免草稿和历史版本混入。
- 明确合同服务范围、已确认事项、待补资料和下一步工作。
- 原始客户资料按实际授权传递，不在材料中夹带账号、API Key、Token或无关个人信息。
- 本技能包不负责自动发送、消息通知、人员分配或进度管理。
- 当前不设置独立的 `project-handoff` Skill；真实业务出现结构化交接需求后再评估。

涉及历史案例时，先锁定标准 `project_id`，再调用 `knowledge_case_pack`。政策事实、当前企业事实、历史案例参考必须分账记录；案例包只提供结构和证据组织，不进入当前企业事实锁。

需要同时判断多个项目时，调用 `enterprise_lifecycle_decision`，将每个项目作为独立对象放入 `project_context.projects`。必须逐项目读取结果和 `coverage_ledger`；“仅路由”状态只表示已经识别项目并列出待核验项，不得写成已经完成算法资格判断。
