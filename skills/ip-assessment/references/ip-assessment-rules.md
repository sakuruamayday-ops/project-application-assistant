# 知识产权评估规则

有效授权可按当期政策规定判断是否计入。审中申请只作技术分析，除非政策明确认可申请状态。

转让取得单独记录转让时间、原权利人、当前权利人、实施情况和政策认可风险。

关联性依次核验权利要求或作品功能、产品模块、核心技术、实际实施和收入贡献；只看名称或分类号不足以证明关联。

输出类别：直接使用、技术分析、待补权属或实施证据、不建议用于申报。

## 面向主导产品的业务三级分流（v1.2）

除权属与法律状态外，结合企业主导产品（`rawAnchor`）与业态（装备/模具制造型 vs 制品/材料制造型），同步输出业务支撑分流标签并写入企业黑板 `patentTierReport`：
- `direct_support`（一档核心支撑）：直接覆盖主导产品核心配方、结构、算法或工艺机理的有效专利；
- `production_support`（二档自用工艺装备支撑）：制品/材料企业自用的生产设备、模具、工装或检测装置专利，仅用于制造工艺支撑，严禁抢占主导产品名；
- `weak_or_unrelated`（三档凑数/弱相关）：跨领域或无技术因果关联的专利，仅计数量不污染核心技术段。当一档为空时明确提示补做围绕主导产品的发明专利。

清单中的权利人和基准日据原件填写。将权利计为可用授权时，`status` 取 `granted-active` 或等义的「有效授权」。已有的 `granted` 记录用 `effective: true` 明确基准日有效。审中、失效、权属缺项和无效日期均进入缺陷项、差距、补强动作、优先级四列。转让取得和项目适用口径继续分别核对。

## 结构化清册核验

执行 `scripts/validate_ip_inventory.py 清册.json --registry 基准日登记.json`。清册逐项登记 `id`、`number`、当前 `owner` 及 `cutoff_date`。多法域数据使用带法域标识的规范权利编号。清册 ID 或同一权利编号重复均报出原位置。填报 `registry_owner` 时核对当前登记，历史 `original_owner` 保留取得沿革。

独立登记快照提供 `id`、`right_id`、`number`、`snapshot` 和 `owner`，清册用 `registry_evidence` 回链。当前权利人冲突的记录暂停计入。只传清册时仍检查行内和跨行冲突及原有状态条件。
