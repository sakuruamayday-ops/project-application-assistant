## 交接清单与接手核对

用户要求交接、准备换会话继续或交给其他执行者时使用本节；日常检查点仍沿用前文四项。以最近检查点和已核验材料为底稿，只补影响接手的内容；不适用项省略，未知项标待确认。

1. **目标与状态**：明确交接对象、适用版本或阶段、下一轮目标，区分已完成、待做与未验证；保留影响后续执行的决定、假设和已否决方案。
2. **资料入口**：列出关键文件的绝对路径或可访问链接；涉及开发时按需附分支、提交、PR、问题链接。已有方案、计划和证据直接引用位置，不复制整份正文。跨设备或平台时注明本机路径的可达性及需转交材料。
3. **执行与验证**：摘要列出影响接手判断的已执行命令、测试或操作、对应对象或版本、核验日期、关键结果与证据位置；区分实际运行、模拟和未执行，避免复制整段日志。
4. **待办与缺口**：按建议顺序列出剩余任务、首个动作、依赖或阻塞、已知风险、验证缺口与完成条件；已有明确分工时注明负责人，不凭空补齐。
5. **必要技能**：只列下一步确实需要的技能及入口，区分已可用与待配置，不默认在接手环境安装或重新配置。

- 请求会话总结时直接在对话提供；已要求保存、生成交接文件或已有对应保存授权时，按指定或项目目录保存并告知绝对路径。交接不自动写入长期记忆、知识库或对外共享。
- 交接内容、命令参数及结果均沿用现有脱敏和时效规则，隐去口令、密钥、令牌及不必要的个人信息；写交接本身不扩大操作授权。
- 交付前核对关键引用能否访问、重要状态是否有对应证据。接手时先读相关材料，核对目标、首个动作和关键限制；未获接手反馈时标明“接手未确认”，文件写好不等于对方已读取或工作已完成。
