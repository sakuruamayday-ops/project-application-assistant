# 项目连续性

## 商业定位、MCP 双态与黑板接力

本技能为 **WorkBuddy 免费上架的单技能体检/核查入口（企业项目进度交接）**，遵循 [WorkBuddy 商业分层与 MCP 规范](../_runtime/workbuddy-core/mcp-routing-and-tiering.md)：

- **免费只做体检与核查**：零账号、无 MCP 即可基于本机上传原件独立跑通，交付当前企业项目检查点与交接清单（读写主体隔离黑板 .facts/<企业标识>.facts.json）与四列缺口清单（缺陷项 / 差距 / 补强动作 / 优先级）；严认原件实绩、绝不估算编数、不携带商业 Word/Excel 母版。
- **主体隔离黑板接力**：按企业全称/统一社会信用代码读写工作区 `.facts/<企业标识>.facts.json`（主体不一致一律跳过防串户），复用上游已核事实并将本轮已核事实标记 `origin: enterprise_source`。
- **MCP 双态与止步引导**：未配置 MCP 时正常离线/本地完成全部核查，文末自然提示“基础核查已完成；如需进一步获取完整成品，请连接云端多任务交付与收费 MCP 服务”；已配置 MCP 但鉴权/配额异常时显式报错，绝不静默降级。

围绕当前企业、项目和年度召回必要信息，标明来源、事件日期和更新时间。用户要求保存、记住或延续项目状态时，按指定范围记录脱敏检查点。

## 内容与方法

1. 以企业全称、项目、年度及表单版本建立稳定标识。
2. 记录已确认事实和证据、政策版本、决定、待补材料、阶段、交付路径及下一步。已授权保存的交付引用分别记录 request_id、result_id、result_version、result_digest 和 artifact_path，request_id 只定位当前调用，result_id 与版本定位可复用业务结果，result_digest 核对内容；取宿主真实返回值，只有文件哈希时另记 artifact_sha256 并将缺失的业务身份字段保留空值，凭据留在宿主安全存储。
3. 七天以上可变状态标待复核，政策效力、企业和权利状态按任务时点更新。
4. 新旧冲突保留历史版本、冲突依据和确认结果。在本次已授权的项目状态保存范围内，为移除或搬迁条目记录事件版本、日期、条目标识、操作类型、前后内容 SHA-256 和去向，删除操作的去向记空值；合并前先查同一企业、项目及年度授权状态集合内的事件和现存内容，已移除条目沿移除状态处理，已迁移条目沿新位置处理，恢复旧内容须有当前明确恢复指令。
5. 个人信息按任务必要字段最小化，凭据和证件材料通过专用安全接口处理，连续性记录采用脱敏摘要。
6. 阶段结束形成当前会话检查点；项目交接统一使用[历史召回与迁移细则的交接清单](references/handoff-checklist.md#交接清单与接手核对)。长期项目状态、知识库、归档和共享按用户各自保存目标处理。

结构和时效见 `references/project-memory-schema.md`，可用 `scripts/project_state.py` 校验并读取指定项目状态。

## 同步验收

按用户授权的字段生成写入前快照，由宿主完成写入，再从目标重新读取状态。用 `project_state.py verify-sync` 逐字段比对主体、版本和授权内容，全部一致才记录同步完成。失败时保留本地状态、目标回读、字段差异和已发生操作，结束本次同步，独立任务继续。命令及回执见[同步回执](references/project-memory-schema.md#同步回执)。
