# 项目 Profile

选择一个主 profile。需要交叉使用时，以主 profile 决定实体和审计重点。

## application-evidence

适用：专精特新、小巨人、首台套、首批次、高新技术企业等申报材料。

重点实体：企业、项目、审核版本、申报条件、申请书字段、主导产品、核心技术、财务指标、经营指标、客户案例、知识产权、证据、风险、判断。

重点关系：`requires`、`supports`、`evidences`、`measured_by`、`used_by`、`conflicts_with`、`lacks_evidence_for`。

强制检查：

- 项目类型与审核版本；
- 主导产品、补短板、填空白、国产替代四项待审判断；
- 主导产品收入边界和知识产权关联；
- 总量与分项、期间、单位和财务勾稽；
- 同一事实在申请书、审计报告、专项说明中的冲突。

## policy-corpus

适用：管理办法、工作指引、当期通知、附件表单、申报指南和政策解读的专题图谱。

重点实体：政策、条款、发布机关、文号、地域、适用对象、申报条件、截止日期、材料要求、版本。

重点关系：`issued_by`、`applies_to`、`requires`、`supersedes`、`interprets`、`conflicts_with`。

强制检查：

- 标题、文号、发布机关、发布日期、施行日期、失效日期；
- 国家、省、市、区县地域层级；
- 管理办法、当期通知和表单版本是否配套；
- 非官方解读不得覆盖官方原文。

## ip-evidence

适用：专利、软著、商标与主导产品、核心技术、研发项目、产业化案例的关联分析。

重点实体：产品、技术、专利、权利要求主题、软著、商标、权利人、发明人、法律状态、客户案例、风险。

重点关系：`protects`、`implements`、`owned_by`、`used_by`、`supports`、`transferred_from`、`conflicts_with`。

强制检查：

- 有效授权、审中、转让取得分别标记；
- 不补造材料未列示的专利和法律状态；
- 专利名称相似不等于与产品直接关联；
- 法律状态现实核验与材料事实锁分层保存。

## client-dossier

适用：长期客户的多年度、多版本综合资料导航。

重点实体：企业、人员、产品、技术、项目、年度、客户、供应商、财务指标、知识产权、风险、文档版本。

重点关系：`owns`、`controls`、`supplies_to`、`uses`、`derived_from`、`supersedes`、`consistent_with`、`conflicts_with`。

强制检查：

- 一个客户一个图谱根目录；
- 年度和版本不得静默合并；
- 第三方企业公开数据与客户提供数据分层；
- 七天以上的动态状态重新核验。
