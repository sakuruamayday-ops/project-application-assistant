# 绿色工厂自评价报告工作合同

## 适用范围

用于绿色工厂或绿色低碳工厂的前期盘点、自评价报告编制、评分复算、证明材料整理和既有报告核稿。零碳或近零碳工厂、绿色供应链、清洁生产审核及单项节能技改仍使用各自当期规则；只有当目标项目确为绿色工厂且评价表已确认时，才套用本合同的评分链。

## 一、先锁定项目版本

建立版本卡并保持到交付结束：

- 企业法定主体、统一社会信用代码、实际生产场所和工厂边界；
- 申报地区、行政层级、目标年度、批次以及新申报、升级或复核；
- 管理办法或评价导则、年度通知、附件评分表、报告模板和官方答疑；
- 每份文件的标题、文号、发布机关、发布日期、适用范围、原文位置、核验日期和替代关系；
- 核心满分、加分满分、推荐阈值、基本要求和必选项的阻断规则。

项目名称相近不能证明规则相同。未取得目标年度通知或当期评分表时，允许按最近已核验导则做结构预研，但必须标记 `policy_status=unknown` 或 `stale`，不得输出确定得分、推荐结论、截止日期或当年度材料清单。

## 二、报告与评分共用一张底稿

当期模板另有强制结构时以模板为准。没有冲突时，报告按以下对象组织，并与评分表细分栏目一一对应：工厂基本情况、基本要求、基础设施、管理体系、能源与资源投入、产品、环境排放、绩效、加分项、下一步工作、自评表和证明材料。

每条评价要求建立唯一 `criterion_id`，同时登记：

- 原文及原文位置、要求类型、最高原始分和一级指标权重；
- 正文小节、企业结论和适用性；
- 证据记录编号、附件编号、证据状态和期间；
- 原始分、确认加权分、条件加权分和计算过程；
- 冲突、限制、补证动作和责任节点。

基本要求使用 `pass`、`fail`、`unknown`、`not_applicable`；评分项使用 `pass`、`partial`、`fail`、`unknown`、`not_applicable`。只有已核验事实或可复算计算可以进入确认分。企业自述、待取得证明、过期材料或冲突数据进入条件分或待核，不得写成已确认得分。

## 三、证据矩阵

以下是常见证据类型，不是固定材料清单；当期导则和通知优先。

| 对象 | 重点核验 | 常见证据 |
|---|---|---|
| 基本要求 | 主体与实际生产、近三年经营和合规、环境信息披露适用性、现场管理、最高管理者职责、管理机构、三年以上规划、培训考评 | 营业执照、生产许可、环评及验收、排污许可或登记、信用记录、主管部门或企业事故核查材料、现场记录、任命与制度、目标方案、培训签到和考评 |
| 基础设施 | 建筑与用地、采光照明、设备准入及能效、分类计量、污染治理能力与生产负荷匹配 | 权属和总平图、建筑材料或声明、现场照片及测量、设备台账和铭牌、淘汰目录核对、计量器具清单和检定、治理设施设计运行记录 |
| 管理体系 | 建立、实施并保持与第三方认证分别成立；社会责任报告是否真实公开 | 体系手册、程序文件、内审管理评审和运行记录、有效认证证书、公开网页及发布日期 |
| 能源与资源 | 能源结构、绿电或可再生能源、余能利用、用水定额和循环利用、原材料减量、绿色采购 | 能源账单和计量台账、绿证或合同、光伏发电记录、节能诊断或技改验收、水量平衡、材料台账、采购制度和供应商评价 |
| 产品 | 产品边界、生态设计、有害物质、用能产品适用性、碳足迹、可回收利用 | 产品标准、设计评审、检测报告、物料声明、能效检测、碳足迹核算或核查、改进记录 |
| 环境排放 | 许可范围与实际产污一致、总量控制、废水去向、一般固废与危废、噪声、温室气体核算核查和改进 | 排污许可或登记、监测报告、在线和运行台账、处置合同资质及联单、噪声检测、温室气体清单和核查声明、公开记录 |
| 绩效 | 用地、绿色物料、污染物与废气废水强度、原材料、固废和水循环、综合能耗、碳排放 | 分子分母原始记录、法定报表、计量和检测数据、附录公式底稿、行业限额或先进值、可比样本来源 |
| 加分项 | 亩均最近评价、碳管理、三年强度变化、碳效档位或信息系统、诊断与技改投资及入库 | 官方评价结果、制度和年度报告、三年工业增加值与碳排、碳效码或系统运行记录、诊断报告、合同发票付款验收、储备库文件 |

同一附件可以支撑多条相关要求，但必须在附件记录的 `supports` 中逐条列明。附件编号在内容定稿后生成，不从其他企业报告复制；正文、评分表和目录中的编号必须回指同一材料。

## 四、计分与计算

逐行计算 `确认加权分 = 确认原始分 × 一级指标权重`。先汇总评价指标分，再汇总加分项，最后计算总分；保留未四舍五入值并按当期表格要求展示。离散档位只能取当期规则允许的原始分，不得自行插入中间分。

同时输出：

- `确认分`：全部证据已核验且无冲突；
- `条件分`：材料可合理补齐但当前尚未核验；
- `不计分`：不满足、不适用且规则不允许折算，或无可靠证据。

总分达到阈值只是必要条件之一。基本要求不全为通过、任一必选项未通过、政策版本未知或评分证据未闭合时，不得写“可以推荐”。

绩效计算先读取 `references/green-metrics-boundaries.md`。对行业平均、前20%或前5%的判断必须取得可回溯的可比基准；没有可靠基准时保留企业指标值并标记对标待核，不计确认分。年均下降率必须固定公式并完整使用三年数据。

## 五、交付前回查

1. 基本信息表、正文、自评表、加分表和附件中的企业名称、期间、数值、单位、产品名称和分母一致。
2. 原始分不超过最高分，离散分值属于规则允许集合，加权分、分项合计和总分可复算。
3. 正向得分至少有一条已核验证据或可复算指标；“无数据”“待补”“不符合”不能同时取得正向确认分。
4. 每个被引用附件真实存在并支持对应要求；附件目录、页码和正文引用无断链。
5. 管理制度、计划、设计值和建设照片不冒充持续运行记录或已实现绩效。
6. 行业先进性、第三方认证、公开披露和项目入库均回到可识别原件，不使用口头咨询代替。
7. 使用 `scripts/validate_green_metrics.py` 检查指标边界，再使用 `scripts/validate_green_factory_ledger.py` 检查评分、证据和汇总。

## 六、校验台账最小结构

校验器读取一个 JSON 对象。`ledger_scope=partial` 用于逐段核稿，`complete` 用于完整评分表，并要求台账理论满分与政策满分闭合。以下只演示字段关系，不代表任何年度政策或企业得分：

    "verified_on": "2026-09-02",
    "status": "current",
    "evaluation_mode": "current_application",
    "ledger_scope": "partial",

    "bonus_max_score": 10,

  "factory": {
    "organization_boundary": "申报工厂法人边界",

## 七、不同任务的输出

- 前期盘点：版本卡、基本要求阻断项、确认分区间、关键缺口和补证顺序。
- 正式编制：正文、自评表、计算底稿、证明材料索引、证据台账和未闭合项；没有证据的文字不得包装成已完成。
- 报告核稿：按“位置—原值或原结论—问题—影响—修正建议—所需证据”输出，区分阻断、影响得分、索引断链和一般编辑问题。

样本报告仅用于学习结构和失败模式。不得将样本企业的名称、人员、联系方式、财务经营数据、指标值、附件编号、技术事实或结论写入公共技能、测试或其他客户材料。
