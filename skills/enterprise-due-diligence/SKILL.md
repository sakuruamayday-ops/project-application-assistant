# 企业全景尽调与合规核查（enterprise-due-diligence）

本技能合并了企业合作前全景调研与法律合规核查能力：
- **GB 32100 18 位信用代码硬校验**：生成报告时自动校验 `credit_code` 长度、合法字符集与第18位模31校验码。
- **新《公司法》5 年实缴过渡期核算**：运行 `python3 scripts/check_company_law.py paid-in --company-type <llc|jsc> --founded <YYYY-MM-DD> --subscribed-deadline <YYYY-MM-DD> --registered-wan <N> --paid-in-wan <M> --strict` 核算 2027-06-30 调整窗口与 2032-06-30（有限公司）/ 2027-06-30（存量股份公司）实缴红线，并可通过 `search-law` 直查本地知识库法规（零 MCP 依赖）。
- 法律合规参考手册见 `references/legal/`。

全景、合作前尽调和全景报告按本技能组织；单字段查询按具体问题使用专业能力。同行比较是全景章节，后续提供新企业时沿用本轮已选模式并重新核验主体。

## 模式与事实复用

| 模式 | 用途 | 规范 |
|---|---|---|
| A 第一版｜标准分析版 | 客户沟通，简洁直接 | [version-a-standard.md](references/version-a-standard.md) |
| B 第二版｜深度分析版 | 深度研判与顾问服务 | [version-b-deep.md](references/version-b-deep.md) |
| C 全生成 | 共用事实底稿，分别生成 A、B | 同上 |

按用户选择继续，未指定时用 A。共用同一调研时点、事实和来源，成品生成后提供对应 PDF。Word 按请求从同一正文追加，生成源保留在任务目录。

## 三级取数顺序（同一技能包无缝适配所有环境）

查询企业画像、历史荣誉认定名单、可比同行、法规条款与项目政策时，按以下三级顺位自动择优取数，逐级顺延、不卡死：

1. **第一顺位（内部团队 / 已连接服务器知识库 MCP）**：检测到当前软件已连接服务器知识库 MCP 时，优先直接调用服务器 MCP 查企业画像、历史认定名单、同行与政策，拿回结果后再运行包内脚本执行信用代码校验、新《公司法》实缴复算与事实底稿整理。
2. **第二顺位（本机离线直连数据库）**：未连接服务器 MCP 但本机存在本地企业/政策数据库时，自动直连本机库秒查（含 `scripts/check_company_law.py search-law` 检索本地法规及衔接 `gov-project-checkup` 查本地企业库）。
3. **第三顺位（纯外部单机用户）**：服务器 MCP 与本机数据库均不可用时，自动基于用户上传的企业资料，结合当前可用的工商检索工具与联网搜索补齐公开事实、同行对比与当期政策，照常跑完复算并交付完整报告。

## 共同事实底稿

1. 用企业全称或统一社会信用代码锚定主体。按 [enterprise-info-verification.md](references/enterprise-info-verification.md)、[企业数据源有限降级协议](../_runtime/enterprise-source-fallback.md)和 [public-source-map.md](references/public-source-map.md)，用当前可用工具核验工商股权、司法信用、经营合规、知识产权、战略布局、经营销售、同行竞争、项目政策八个维度。
2. 天眼查开展主体和全维度分诊，企查查补齐未覆盖、缺失、状态不明及高影响字段，冲突和权威终值回到官方来源。关键事实交叉验证，精确数字、日期、编号与名称绑定来源。
3. 区分公开事实、计算、判断、待核事项及动作。核心工商、执行失信、处罚异常和知识产权标记已验证、单源待核、冲突待裁决或当前未命中；缺少来源时使用其他可用来源继续。
4. 财务及内部经营数据取自用户提供的可靠资料。营收、利润、未分配利润、研发费、客户占比、毛利、负债、产能和市场份额按实际资料列示，缺项列所需资料。对商业平台提示的风险线索核对其事项原文、主体、期限和处置状态，按事实差距、影响及处理顺序输出。
5. 业务状态与证据状态分开。称号、评价、核验记录待补时保留未知；内部研发部门与政府认定机构分别记录。各项目使用对应年度、收入分母和政策；预测与实际值分列，资格依赖引用明确条款。
6. 同行名单证明所列身份，产品可比性和其他荣誉单独核验；企业存续与产品从业年限分别计算。知识库摘要、检索摘要和政策全文分层记录，来源状态在摘要、表格、规划和结论保持一致。
7. 五年规划写准备、建设、申请和评估安排；成果数量、材料类别与逐项证据完整度分别评价。资料待补项保留在对应位置。

## 分析方法

- 风险按“事实或信号—影响—核验或处理动作—关联项目—时间”表达。融资租赁、抵押及诉讼数量结合实际事实判断；关联方风险结合控制、担保、资金、业务或人员传导路径评价。
- 项目标记“公开信息已支持、具备培育可能、请企业提供资料后判断”，正式申报时更新当期政策。风险整改与高企、技改、绿色制造、研发机构、专精特新等计划写入同一风险表、项目启动条件和年度行动。
- 专利区分有效授权、审中、终止、驳回、转入及转出。画像统计与专利性、权利要求、FTO、规避设计、壁垒、挖掘交底、预审分析分别处理，专项请求衔接 `patent-strategy-assistant`。
- 战略覆盖产品、区域、主体、资产投资、技术绿色及五年发展；产品、人员、质量和经营控制信息归入主营业务、风险、项目章节。客户、渠道、报价、账期和回款的专项分析按用户提供资料及目标展开。
- 同行选择参考 [peer-selection-rules.md](references/peer-selection-rules.md)，核验目标企业省级专精特新身份后，内部动态选择近身同行、短期可追对象和行业标杆。报告呈现有解释力的对象与差距，选择方法留在工作记录。
- 同行荣誉核验创新型中小企业、专精特新、小巨人、高企、研发平台、绿色制造、数字化智能制造、标准、知识产权、单项冠军和上市状态等，归入“已有荣誉资质及项目”。名单未命中注明本轮范围，大型企业通过高阶能力反推目标培育证据。
- 项目对标回到政府公示或原文，分别标记备案、公示、拟补助、认定和拨付。模式 A 状态采用红黄绿圆点加文字、风险程度用彩色标签；模式 B 按实际信号在战略风控中分析股权、关联交易、股东往来、未分配利润和税务一致性，基础股东信息保留。
- 结尾按优先级给出客户能理解的问题、影响、动作和对应服务。四问复盘、生成过程、工具回执及修订说明留在对话；正文保留事实、判断、来源和行动。

## 模式 A 生成

1. 采用模式 A 规范、[母版规则](references/standard-master-lock.md)、`assets/standard-master-template.html` 和 `assets/standard-style.css`。保留橙色封面、章节图标、工商两列表和表格类型。
2. 按[结构化输入说明](references/standard-html-input.md)准备本企业 JSON。第七章经营财务数据使用用户提供资料，缺项待补；程序复用母版的 HTML、CSS、图标和 DOM。
3. 将事实 JSON 回填到模式 A 的 HTML 母版，再从同一内容渲染 PDF。
4. 其他宿主运行 `python3 scripts/render_standard_pdf.py --input <JSON路径> --out <PDF路径> --title <报告标题>`。已有回填文件时可用 `--html <HTML路径>`。用 `python3 scripts/validate_report_pdf.py <PDF路径>` 核对每页正文或表格，空白及仅尾注页应重新排版。依实际完整度标记初稿或定稿。

## 模式 B 生成

1. 采用模式 B 规范、[report-spec.md](references/report-spec.md) 和 `assets/report-style.css`。
2. 项目政策与历史案例按需调用 `gov-project-checkup` 与本地知识库检索能力，原文或官方来源核验结果进入报告。股权及未分配利润服务机会按已知信号、待取资料和服务方向展开，财税结论对应真实资料。
3. 从静态 HTML 生成 PDF 并核对实际版式。

```bash
python3 scripts/render_html_report.py --html <HTML路径> --out <PDF路径>
python3 scripts/validate_report_pdf.py <PDF路径>
```

`--html -` 从标准输入读取自包含的 HTML。受限宿主仅允许本地 Chromium 单进程时，可设置 `REPORT_CHROMIUM_SINGLE_PROCESS=1`。

文件名：`<企业全称>_企业全景调研报告_标准分析版_<YYYYMMDD>.pdf` 或 `<企业全称>_企业全景调研报告_深度分析版_<YYYYMMDD>.pdf`。

## 能力衔接

财务复算与制造财税风险使用 `manufacturing-tax-risk`；项目资格与多项目规划使用 `gov-project-checkup`；专利专项使用 `patent-strategy-assistant`，专利 Word 文件核稿使用 `patent-docx-reviewer`。网页看板使用当前前端能力与共同底稿，发布按用户指令和宿主权限执行。

外部数据和渲染使用宿主当前能力，缺项时先说明缺口并继续可完成部分。团队知识服务通过安全凭据接口读取 `KB_API_ENDPOINT`、`KB_API_TOKEN`，日志与交付物使用脱敏信息。资源相对本技能目录解析，输出写当前任务目录。

报告表达采用[报告写作规则](../_runtime/report-writing.md)。
