# 专利任务两路径路由矩阵

| 主意图 | 唯一活动技能 | 内部阶段 | 退出条件 |
|---|---|---|---|
| 公司专利审查意见、全面建议 | `patent-router` | P1 检索分析 + P2 挖掘交底 + P3 预审推荐 | 检索、专利点、保护策略、单一目标中心建议和缺口已记录 |
| 查新、专利性、FTO、布局、权利要求策略 | `patent-router` | P1 | 检索式、范围、证据、差异表和缺口已记录 |
| AI或软件发明专利 | `patent-router` | 技术特征证据图 + P1 + P2 | 已检查技术因果链、AI充分公开、数据治理、自然人贡献线索和现有技术对照 |
| 从项目资料挖掘专利点或形成技术交底 | `patent-router` | P2，可调用 P1 作子步骤 | 专利点清单已确认，交底书已自检并版本化 |
| 撰写并交付完整专利申请案卷 | `patent-router` + 独立核稿技能 | P0 全案清单 + 技术特征证据图 + P1 + P2 统一生成器 + B 核稿 + P3 + P4 提交门禁 | 唯一清单内十三类角色齐备，哈希和依赖均为当前案件版本，`filing-ready` 通过 |
| 地方保护中心预审推荐 | `patent-router` | P3 | 已比较候选池并推荐一个主目标中心；备案、IPC、文件和时限已核验 |
| 对中国专利申请 Word 核稿并加批注/修订 | `checking-patdocx-cn-single-agent` | Documents 渲染与 OOXML 结构核验 | 跳过数为 0，完整性和全页渲染通过 |
| 政府项目知识产权关联 | `patent-router` 后接对应项目技能 | 只读取已核验专利结果 | 状态分类、技术关联、政策口径和风险已写明 |
| 软件著作权登记材料 | 不启动本技能 | 转其他专门能力或说明当前未配置 | 不把软著要求、代码页数或截图模板混入专利案卷 |

## 多意图请求

公司级多意图在一个技能内有序运行：

1. P1 确定检索和保护策略。
2. P2 形成专利点与交底策略。
3. P3 比较浙江、杭州后推荐一个目标中心。
4. 最后把已核验结果映射到项目申报。

完整申请案卷在上述业务阶段外增加一条版本控制主线：

1. P0 初始化 `patent-case-manifest/v1`，每案只保留一个当前清单。
2. 把任务头和用户技术材料转换为 `technical-feature-map/v1`，记录问题、特征、效果、出处与待补项。
3. 每个阶段产物按唯一角色登记路径、SHA-256、案件版本和上游哈希。
4. `build_patent_application.py` 只从已确认事实锁的统一 JSON 输入生成申请 Word 和附图规范。
5. 独立核稿轨返回核稿记录与验证记录，两者继续登记进同一清单。
6. P4 生成提交清单并运行 `filing-ready`；任一上游变化都会使旧下游文件失效。

缩小任务仍可只运行 P1、P2 或 P3，不强制创建完整案卷。只有用户要求完整申请、正式成文或提交前交付时，才启用 `filing-ready` 交付契约。

P3 默认数据策略：注册地由企业登记查询取得；浙江、杭州备案状态按用户常设指令默认均为已备案；技术主题和拟申请 IPC 由 P1/P2 从用户材料分析生成。除主体无法识别或材料不足以形成 IPC 外，不把这些字段作为启动前反问项。

申请书 Word 核稿不属于上述串行链。用户说“检查申请书”时单独执行 `checking-patdocx-cn-single-agent`；如还要公司级审查意见，必须显式形成另一个综合任务记录。

预审中心候选池可以包含两个中心，但案件执行时只选择一个主目标中心；双中心比较属于 P3 内的两个独立评估结果，不得混并规则。
