# P1 检索与法律分析

## 输入

- 技术材料、申请文件或现有权利要求；
- 法域与基准日；
- 检索目标：查新、无效风险、FTO、审查意见或布局。

## 流程

1. 先生成 `technical-feature-map/v1`，提取保护客体、必要技术特征、技术效果和来源定位。缺少出处的候选特征不得自动进入正式权利要求。
2. 从证据图生成单项特征、核心组合和分类号交叉检索单元。同义表达、外文表达、IPC/CPC、申请人和发明人线索分字段记录，不将模型推荐词写成已核验分类。
3. 中国专利首轮发现优先调用 `scripts/cnipa_epub_search.py`，每次只发送 1 至 8 个脱敏短技术词。国知局结果固定标记为发现级线索，不能直接进入新颖性、创造性、FTO 或法律状态结论。
4. 国知局详情、全文或其他对应法域官方原文负责复核公开日、说明书、权利要求、附图与法律状态。Google Patents、WIPO、EPO 和商业数据库只补充外国文献、同族、引证和全文，不替代中国专利官方复核。
5. 保存检索库、检索式、访问日、结果数量、浏览器安全策略和未覆盖范围。依赖缺失、验证码、页面改版或超时必须记为提供器失败，不能记为零命中。
6. 将命中文献按公开日过滤，并回到权利要求、说明书段落和附图核对。
7. 生成权利要求引用图、必要技术特征树和 claim chart；把申请文件特征编号与证据图特征编号保持可追溯对应。
8. 新颖性按单一文件逐项判断；创造性记录最接近现有技术、区别特征、技术效果、实际技术问题和技术启示。
9. FTO 只分析目标市场内有效或待决权利要求，明确不等同于可实施法律意见。

## 输出

每条结论附公开文本定位、权利要求号、段落号、附图标记、法律状态来源和查询日期。未命中只能写“当前检索范围未命中”。

国知局提供器的安装、输出字段、HTTP 隐私边界和人工降级规则见 [国知局公布公告首轮检索提供器](cnipa-epub-provider.md)。
