# 专利 Word 回归验收门禁

## 适用范围

单份申请 Word 核稿交付执行当前文件的批注、结构完整性与全页渲染检查。下述脱敏结构副本、增强夹具和提供器回归用于对应实现发生变化的研发验证，不因用户只要求核稿而额外触发。用户输入已有完整官方对比文件时，不以在线提供器能否访问阻断这份 Word 的独立核稿。

## 必测对象

1. 原始真实文件副本：验证真实排版、现有表格、文本框、附图和附图标记。
2. 批注或结构处理实现变更时，使用脱敏结构副本验证可共享回归，不含原技术内容和个人元数据。
3. 批注或结构处理实现变更时，使用受控增强夹具：在脱敏副本中加入 OMML 公式、合并单元格表格和唯一定位锚点。

## 通过条件

- 输入与输出均能通过 ZIP 完整性检查。
- 输出保留输入全部非预期删除的 ZIP 部件、媒体和关系。
- 每条批注在 `comments.xml` 有正文，在 `document.xml` 有 start、end、reference 三类锚点。
- 批注目标文本与审查 JSON 的 `context`、`highlight_text`、`occurrence` 一致。
- `review_adder.py` 跳过数量为 0。
- `verify.py` 三项验证全部通过。
- 表格数、文本框数、公式数、Drawing 数和媒体数达到夹具清单预期。
- 渲染生成所有页面 PNG，逐页检查无截断、重叠、缺字、表格破坏或附图错位。
- 评论不可仅凭渲染判定，必须通过 OOXML 结构审计。

## 国知局提供器变更回归

提供器或实际影响该检索链的共享实现发生变化时，必须执行以下全部相关回归；本次任务实际需要在线检索时也须验证该调用的业务结果，不把提供器失败写成零命中。

- 国知局离线结果卡解析、四类复选框、跨词去重、发现级证据标记、敏感词拒绝、零结果和提供器失败语义全部通过。
- 国知局实时门禁至少覆盖发明、实用新型和外观设计各一条公开记录，并对其中一条回到官方详情或全文核对公开号和公布日。
- 国知局提供器连续多轮执行不得复用用户浏览器配置、不得关闭 Chromium 沙箱；验证码或页面异常必须返回结构化失败。

## 失败处理

当前 Word 的批注、完整性或渲染硬门禁失败时不得交付审查版 Word；保留失败产物与日志，修复后重新运行受影响检查。提供器变更回归失败时阻止该提供器候选发布，不阻断不依赖它的单份核稿。当前结论确实依赖失败检索时，暂停该结论并报告证据缺口。
