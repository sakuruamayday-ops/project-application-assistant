# AI 发明专利专项方法

本文件只补充人工智能发明专利的专项判断，不处理软件著作权登记。它不提供“一套模板适用所有 AI 方案”的保证。

## 一、从研发材料到专利点

先判断技术贡献位于哪一层，再决定检索和保护客体：

| 技术贡献层 | 重点提取 | 常见证据 |
|---|---|---|
| 数据取得与表示 | 采集方式、预处理、特征编码、标签或对齐 | 数据设计文档、处理脚本、字段说明 |
| 模型结构与训练 | 必要模块、连接关系、目标函数、更新机制 | 模型定义、训练流程、配置与实验记录 |
| 推理与工程化 | 计算顺序、缓存、量化、调度、边缘部署 | 调用链、时延与资源记录、部署图 |
| 知识检索与 Agent | 索引、检索、证据组装、工具选择、返回控制 | 检索日志、工具调用链、异常分支 |
| 生成与多模态 | 条件构建、模态对齐、生成控制、一致性处理 | 模块图、推理流程、对照实验 |
| 物理世界交互 | 传感、状态估计、决策、执行和反馈闭环 | 硬件接口、时序、任务记录、安全约束 |
| 安全、隐私与治理 | 检测、约束、处置、审计和可追溯机制 | 威胁模型、安全测试、审计记录 |
| 行业应用 | 行业约束导致的模型、数据或处理改变 | 行业数据定义、设备或业务接口、对照验证 |

文件名、开源库名或商品名只能帮助定位材料，不能单独证明创新点。

## 二、客体、创造性与充分公开

1. 客体判断时整体分析权利要求限定的技术手段、解决的技术问题和获得的技术效果，不把“使用了计算机”当作足够理由。
2. 仅更换处理对象或应用场景时，必须说明场景约束为何导致模型、数据、参数、计算或系统结构的实质变化。
3. 只有对解决技术问题作出贡献的特征才能支撑相应创造性主张；特征数量多不等于创造性强。
4. 模型构建或训练类方案通常需要把必要模块、连接关系、训练步骤与必需参数记入底稿。
5. 具体场景应用类方案通常需要说明模型如何与场景结合，以及输入、模型处理和输出的内在关系。

## 三、权利要求策略

- 先以受真实材料支持的最小可保护特征组合作为独立权利要求候选。
- 从属层级可按模块内部结构、数据处理、训练或部署方式、替代方案与参数范围递进，但每一层都需要原始记载支持。
- 方法、系统、设备、介质或计算机程序产品等主题不是固定“套餐”。根据技术事实、商业实施方式、侵权可识别性、单一性和篇幅决定。
- 模板只能用于检查结构遗漏，不能代替技术特征选择、现有技术对照和上位概括支持性判断。

## 四、质量关卡

进入正式撰写前，至少复核：

- 技术问题、核心特征和效果是否形成因果链；
- 每项核心特征是否有来源定位；
- 检索是否同时覆盖单项特征、核心组合、分类号、引证和同族扩展；
- 新颖性是否仅按单一在先文件的逐项公开判断；
- 创造性是否同时记录区别特征、效果、实际技术问题和技术启示；
- 申请文件是否引入未在证据图中确认的参数、效果、实施例或替代方案；
- 数据治理、发明人和充分公开的缺口是否已显式处理。
