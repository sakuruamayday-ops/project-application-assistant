# 政策变化影响模拟器

## 目标

当管理办法、年度通知、属地细则或生命周期规则发生变化时，系统不全量重抓、全量编译，也不改写已经由官方名单确认的企业历史事实。系统只定位变化政策的依赖项目，重编对应规则包，并标记需要重算的派生结果。

## 输入与依赖

每个项目编译单元由四类输入共同确定：

1. 项目规则包，包括稳定规则、年度层和属地层。
2. 生命周期规则，包括认定、复核、重新认定、撤销和有效期迁移。
3. 统一企业事实契约。
4. 编译器架构版本和共享执行内核版本。

编译器对上述内容计算 `compile_input_hash`。哈希未变化的项目直接复用上次 IR 节点和算法卡；哈希变化的项目才重新编译。
每个政策层还必须声明 `stable-management`、`annual-notice` 或
`jurisdiction-detail` 时间类型及生效窗口。政策层级或窗口变化会触发政策追溯关系重连，
但不会改写官方名单事实。

## 影响定位算法

1. 对比新旧政策依赖图中的政策节点内容哈希，识别新增、删除和内容变化的政策文件。
2. 从变化政策节点沿反向依赖边遍历，找到直接或间接依赖该政策的项目。
3. 对比项目新旧规则层，输出新增、删除、修改的规则 ID 和受影响事实字段。
   原生 `all/any` 规则会递归定位到叶节点事实字段，无需依赖上游派生布尔值。
4. 对受影响项目分别形成四类结果：
   - 项目规则包：重新编译。
   - 企业身份事件：官方名单事实保持不变；生命周期派生状态按需回放。
   - 预测结果：按新政策版本失效并重算。
   - 历史回测：按新规则版本重新计算，输出必须标记为回测模拟，不能覆盖历史事实。
5. 如果提供团队数据库，报告会统计需要回放的企业身份事件和企业项目身份数字孪生数量。

## 不变量

- 官方认定、复核通过、撤销等名单事实不会因后续政策变化被改写。
- 2025 年年度通知不会被当作 2026 年现行规则；只能用于 2025 年回放或明确标注的下一年度预测。
- 属地规则未解析时，市级项目保持待核验，不用省级或其他城市规则代替。
- 每项影响均回指政策节点、规则差异、事实字段和政策版本哈希。

## 运行方式

编译入口会自动读取上次 IR 并生成影响报告：

```bash
python3 scripts/compile_project_rule_ir.py \
  --database /path/to/team.db
```

也可以独立比较任意两个 IR：

```bash
python3 scripts/simulate_policy_change_impact.py \
  --before references/compiled-project-rule-ir.before.json \
  --after references/compiled-project-rule-ir.json \
  --database /path/to/team.db \
  --output references/policy-change-impact.json
```

报告中的 `affected_project_ids` 是最小重编译集合；`incremental_compilation.reused_project_ids` 是直接复用集合。

共享内核版本升级会在首次发布时使 29 个项目全部重编，这是预期的一次性迁移。之后只要
共享内核版本不变，单个项目的政策内容、生效窗口或生命周期规则变化只会重编依赖该变化的
项目，其余项目继续复用原内容哈希。
