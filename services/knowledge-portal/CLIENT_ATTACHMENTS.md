# 客户端上传原件留存

V0.7.6 起，客户端仅从真实用户上传入口登记新上传文件，并传送当时的原始字节。服务器不会扫描员工磁盘、历史附件或模型生成文件，也不从聊天中提取原文。

原件与业务分析定稿分开：独立表 `client_attachments`，私有目录 `DATA_DIR/client-attachments/<attachment_id>/content`。原件先保留；没有自动删除、日报收取确认或清理入口，不进入知识索引、诊断或原文搜索。

## 登记与传输

`POST /v1/client-attachments` 接受以下 JSON；`session_id`、`task_title` 可缺省或为 `null`，不接受其他字段：

```json
{
  "request_id": "ddfb0058-72c4-45b1-80c2-ea10e6355a22",
  "filename": "用户上传的原件.pdf",
  "size_bytes": 12345,
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "uploaded_at": "2026-10-20T02:00:00Z",
  "client_version": "0.7.6",
  "session_id": "当前任务的已有编号",
  "task_title": "可选任务标题"
}
```

返回 `{"attachment_id":1,"next_offset":0,"complete":false}`。同一成员、同一 `request_id` 重试返回原记录及进度；元数据变化返回 409。成员身份取自现有客户端密码登录鉴权，不接受请求指定的账号。沿用设备校验和全局最低版本检查，同时只接受 V0.7.6 起的客户端及上传元数据版本。

`filename` 仅为显示文件名，不含本机路径；原件跟随真实上传入口，允许非报告后缀及无后缀文件。仅收集 0 至 100 MiB（100 × 1024 × 1024 字节）的用户原件：等于 100 MiB 接收，大于 100 MiB 跳过收集，原文件仍可用于员工本机分析。服务端登记拒绝超过上限的元数据，分块接口也拒绝已有超限登记继续上传；不删除已有记录。业务分析定稿的 256 MiB 边界保持不变。合法空文件在登记时保存空原件并返回 `next_offset:0,complete:true`，无需发送空分块，摘要必须为空文件的真实 SHA-256。文件逐块落盘，完整性验证逐块读取，不把大文件一次读入内存。空间不足或传输失败时，客户端保留待保存队列并重试，不阻断员工本机分析，也不改变其他上传或生成能力。

`POST /v1/client-attachments/1/content` 接受 `{"offset":0,"content_base64":"..."}`，每块原始数据最多 1 MiB，返回 `{"next_offset":1048576,"complete":false}`。复用现有报告分块落盘、SHA-256 校验及 2 GiB 磁盘保留空间。重复或错位分块返回当前进度；SHA-256 不一致返回 422，重置进度为 0 以便重新上传。只有完整接收且校验通过后才会返回 `complete:true` 并开放下载。

元数据请求体最多 32,000 字节，分块请求体最多 2,000,000 字节。请求不包含本机路径、聊天、密码或任意 `extra` 数据。

## 查看与按需下载

网页 `/client-attachments` 仅管理员可访问，展示文件名、上传时间、任务标题、大小与状态，同时显示上传者姓名和账号。普通成员没有原件入口；直接访问列表或下载接口均返回 403。员工客户端不显示存档记录、状态、提示、确认或开关，原件留存完全在后台自动进行。

`GET /client-attachments/<attachment_id>/download` 使用现有网页登录及管理员权限，管理员可下载全部，不完整文件不可下载。下载前验证大小与 SHA-256，强制以附件形式下载，避免把 HTML、脚本等原件作为站点内容执行。重复下载保留原件，不会触发报告的 `acknowledge` 或 `cleanup`。当前成员的客户端上传接口保持可用，仍按登录账号归属保存。

部署沿用整包 `app/` 与 `templates/` 的现有清单；`app/client_attachments.py` 加入现有编译检查，模块与页面都加入切换前必需文件验收。
