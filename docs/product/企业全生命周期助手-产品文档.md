## 2. 背景、用户与问题

### 2.1 背景

十二类双平台问答包已具备项目分析与报告能力，但短提示词没有稳定进入专业路由。2026-08-19 的“做阀门手轮的浙江省专精特新企业帮我查”被通用联网规则抢先处理，首步直接调用网页搜索，未先查询团队知识库，违背了企业数字身份证和既有认定名单应优先复用的设计。

### 2.2 目标用户与使用场景

| 用户或角色 | 使用场景 | 当前痛点 | 期望结果 |
| --- | --- | --- | --- |
| 政府项目申报工程师 | 给出企业名称、已有材料和“前期评估/可行性分析”短提示 | 被要求补填重复的企业基本信息，或无法稳定触发专业报告 | 直接启动主体补全、政策核验和受控报告流程 |
| 知识产权与项目顾问 | 查询某产品或行业的浙江专精特新/小巨人同行 | 先联网导致本地已核验名单未被复用，搜索结果混入非认定企业 | 先返回本地知识库中已核验名单，再按需要补足公开来源 |

### 2.3 要解决的问题

本版本解决“短提示词不能稳定进入专业报告”和“同行检索未遵循本地知识优先”的问题。它不将公开第三方数据当作客户财务事实；未核验字段仍须在报告中标为待核验。

## 3. 产品定位与目标

### 3.1 产品定位

面向政府项目申报顾问的企业分析与报告技能套件。用户从企业名称和现有资料出发，系统先补齐可公开核验的主体信息，再按项目规则、团队知识库和官方来源形成可追溯报告。

### 3.2 本版本目标

| 目标编号 | 目标 | 衡量方式 | 目标值或完成条件 |
| --- | --- | --- | --- |
| OBJ-01 | 十二类项目报告可由短提示进入主路由 | 路由回归测试 | 受控正例均命中 `project-feasibility` 和对应领域技能 |
| OBJ-02 | 同行检索不先调用网页搜索 | 历史失败提示词的路由测试与技能流程核验 | 首步为本地知识库；仅未命中、覆盖不足或不可用时降级 |
| OBJ-03 | 企业基本信息不再是报告启动前提 | 技能正文与回归测试 | 企业名称加现有资料可启动，缺口在输出中标识 |

### 3.3 非目标

- 本版本不补造企业财务、研发、客户或知识产权事实。
- 本版本不改写十二类项目各自的政策门槛、报告模板或结论标准。
- 本版本不替代本地知识库未覆盖时所需的官方原文核验。

## 4. 范围与用户体验

### 4.1 范围

| 范围项 | 本版本处理方式 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 专业报告短提示触发 | 修改 | P0 | 覆盖“前期评估”“可行性分析报告”“高企/专精特新/小巨人评估”“双报告”等常用表达 |
| 企业主体补全 | 修改 | P0 | 企业名称为检索键；天眼查优先、企查查补足，高影响缺口标待核验 |
| 同行名单检索顺序 | 修改 | P0 | 固定本地知识库、天眼查、企查查、官方网页/联网的降级顺序 |
| 泛化对话保护 | 新增回归 | P1 | “给朋友出报告，写得幽默一点”等普通请求不误走专业链 |
| 技能包正式发布 | 发布 | P0 | 重新构建、验签、上传和提升为 V1.6.8；V1.6.7 保留为不可覆盖的缺陷历史 |

### 4.2 核心流程

1. 用户输入“企业名称＋现有资料＋项目或报告类型”。
2. 路由选中 `project-feasibility` 和一个项目领域技能；主体信息按天眼查、企查查补齐。
3. 涉及同行或获评企业时，先查询 `jiaotang-kb` 的已核验名单和原文；只有本地资料不足时才进入第三方与联网层。
4. 依据当期政策、证据状态和受控模板生成前期评估或可行性分析；不能核验的项目如实列为待核验。

## 6. 产品与技术方案

### 6.1 信息与交互设计

用户不需要记住技能名或填写前置基本信息表。最简输入为“企业名称＋现有资料＋项目/报告类型”，例如“杭州示例科技有限公司，现有资料如下，出具专精特新双报告”。同行检索可使用“做阀门手轮的浙江省专精特新企业帮我查”。

### 6.2 架构与依赖

| 层级或组件 | 方案 | 依赖 | 变更影响 |
| --- | --- | --- | --- |
| 专业路由 | `delivery-contracts.json` 与 `project-task-router` 维护短提示词和任务归属 | 50 个技能的路由契约 | 影响技能选择，不改变政策条件 |
| 报告主流程 | `project-feasibility` 接收企业名称、资料和项目目标 | 天眼查、企查查、领域技能、政策技能 | 公开主体缺口可自动补齐，财务仍需用户资料 |
| 同行对标 | `peer-benchmarking` 强制先调用 `local-knowledge-retrieval` | `jiaotang-kb`、天眼查、企查查、官方网页 | 提升已核验名单优先级，联网为降级层 |
| 发布 | 套件构建、Ed25519 签名、门户发布与 GitHub Release | 发布者密钥、GitHub、知识门户 | 版本与资产必须同一签名事务 |
| 深度澄清 | 当前会话中的依赖决策树；主动结束与连续两轮无进展收束 | 会话历史、可靠事实工具、用户明确确认 | 不新增隐藏访谈状态或普通对话 Host 硬门禁 |

### 6.3 数据、安全与合规

本版本不新增数据持久化。企业公开主体信息按天眼查、企查查和官方来源核验；团队知识库用于已核验名单与原文。用户提供的财务和经营资料不由第三方过期数据替代。发布包不包含个人令牌、企业资料或私钥。
