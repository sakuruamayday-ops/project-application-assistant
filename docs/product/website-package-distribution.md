# 网站与客户端技能分发策略

状态：正式执行

更新日期：2026 年 9 月 5 日

## 产品入口

知识门户的“Skills → 版本与下载”负责通用签名 Skills 包、版本、SHA-256 和发布说明。共创独立客户端从自己的签名更新源获取客户端安装包，并通过同一发布事务绑定的客户端技能投影更新内嵌能力。两个入口共享技能身份，但不能用其中一个入口的成功替代另一个入口的验收。

## 包型

| 包型 | 内容 | 用户选择 |
|---|---|---|
| 通用签名 Skills 包 | 套件清单声明的全部有效 Skills、共享运行资源、逐文件哈希与 Ed25519 签名 | 支持标准 `SKILL.md` 的兼容 Agent |
| 独立客户端技能投影 | 从同一技能源按有效清单生成的根级签名投影，不包含清单外技能目录 | 共创独立客户端内嵌及独立技能更新 |

不再发布现行宿主专用插件包，也不要求独立客户端用户导入 Skills、粘贴安装指令或重复安装已经可用的文档、OCR 和联网能力。历史发布包与审计记录保持只读，不作为当前下载入口。

## 当前发布矩阵

| 平台 | 官方能力基线 | 网站状态 |
|---|---|---|
| 通用 Agent Skills | `SKILL.md` 目录或导入机制 | 正式版可下载；候选版不覆盖正式入口 |
| 共创独立客户端 | 内嵌签名技能与独立技能更新 | 通过客户端签名更新源按系统架构分发 |

正式发布矩阵固定为以上两个同源产物，不复制技能清单或业务规则。macOS 与 Windows 只在客户端安装包、签名和更新协议层分别验收。

## 版本号授权

- 正式版本号由主人在发布范围确定后明确指定；开发、合并和预发布准备不得自行递增版本号。
- 已正式发布的版本号、Git 标签、包 SHA-256 和签名记录不可覆盖。
- 指定版本若已存在，发布流程必须停止并报告冲突，等待主人指定尚未使用的版本。
- GitHub、门户和本机安装必须使用同一份签名事务清单；同一版本只允许一个任务持有
  发布租约，其他任务自动进入只读监控。
- 租约过期后的接管只允许继续完全相同的事务哈希；同版本换包、换提交或单独补发
  某一通道均被阻断，必须改发新的补丁版本。

## 双产物发布验收

两个正式包必须同时满足：

1. 技能清单、实际技能目录、签名索引和客户端可发现的内置技能集合一致。
2. 通用包完成安全解压、逐文件哈希、逐技能签名和隔离安装验证。
3. 客户端投影只能包含四个根级签名伴随文件与签名索引声明的 `skills/**`。
4. 当前运行时首次启动按实际工具探测能力，不生成旧宿主安装或统一补装提示。
5. 客户端安装包、更新、回滚、凭据保持和真实模型调用由客户端发布事务独立验收。
6. 发布清单、候选包 SHA-256 和发布者完整性校验全部通过；这是发布侧验收，不转嫁给用户。
7. 正式提升前，以通用签名包在独立验收目录执行原子升级模拟，并完成开发源、正式包、隔离安装目录三方哈希比对和全量验签。不得覆盖发布者正在使用的 Codex Skills。
8. 发布事务状态必须依次证明 GitHub 暂存、门户暂存、本机同步、门户正式、GitHub
   正式和最终完成，任一步证据都写入同一事务审计链。

任一项未满足即阻断对应正式包发布，不生成第三种替代产物。

## 兼容与回滚

- 通用 Skills 回滚恢复上一份已验签目录，并重新执行安装完整性检查。
- 客户端技能更新失败恢复上一签名技能包；客户端整体更新失败恢复上一签名应用。
- 回滚不覆盖企业资料、会话、个人偏好、凭据或第三方连接。
- 历史 Release 不删除、不替换，只从当前入口退出；所有清理使用可恢复回收路径。
