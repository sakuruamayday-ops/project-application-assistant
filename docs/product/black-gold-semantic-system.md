# 无红色黑金语义系统

## 目的

网站保持黑、象牙白与古金色主视觉。风险不依赖红色表达，而由文字、警示图形、边框强度、斜纹密度和确认层级共同表达；颜色不能成为唯一提示。

## 语义令牌

| 令牌 | 用途 | 视觉表达 |
|---|---|---|
| `--risk-caution` | 一级注意 | 暗金细边、空心警示图形 |
| `--risk-confirm` | 二级确认 | 金色边框、细斜纹、实心警示图形 |
| `--risk-verify` | 三级核验 | 浅金高亮、双层边框、强化斜纹 |
| `--risk-surface` | 普通风险底色 | 低密度金色透明面 |
| `--risk-surface-strong` | 高风险底色 | 更高密度的浅金透明面 |
| `--risk-line` | 风险边界 | 高对比浅金边框 |

成功状态可以继续使用克制的绿色辅助色，但普通主操作与风险操作不得只靠颜色区分。

## 三级确认

### 一级注意

适用于清除当前标签页配置、进入可恢复操作的确认页面等即时可逆动作。界面使用空心警示图形和暗金细边，不弹出二次确认。

### 二级确认

适用于撤销、回滚、恢复默认、移入回收站、停用账号和更换绑定设备。界面使用深色底、金色斜纹、警示图形与明确动词；提交前必须显示确认提示。

### 三级核验

适用于彻底清除账号、凭据、调用记录等不可恢复动作。除二级确认的视觉规则外，还必须要求输入账号或其他核验值，并再次确认。

## 组件约定

- 普通主按钮使用实心金色。
- 风险按钮使用 `.button.danger`，不得与普通主按钮同构。
- 风险文本操作使用 `.text-danger` 或 `.text-button.danger`，必须保留警示图形和明确动词。
- 风险区域使用 `.danger-zone` 或 `.danger-panel`，必须提供风险说明。
- 错误与告警使用 `.notice.alert` 或 `.alert-item`，使用图形、边框和纹理共同表达。
- JavaScript 通过 `data-risk-level="caution|confirm|verify"` 标记风险等级；含 `confirmation` 输入项或 `/purge` 动作的表单自动进入三级核验。

## 无障碍与发布门禁

- 警示图形由 CSS 图形绘制，不向读屏器重复朗读无意义符号。
- 风险按钮必须使用“删除到回收站”“彻底删除”“撤销”“回滚”等明确文案。
- 正文和功能标签不得低于 11px；描述性文本优先使用 12px 以上。
- 构建脚本会阻止未经批准的红色令牌进入正式 `app.css`。
- `tests/test_black_gold_design_system.py` 检查语义令牌、三级确认、进度条兼容规则、Tabs 关系和微字号门禁。
