# 企业全生命周期助手产品路线图

状态：V1.6.17 正式技能版本；客户端发布独立验收

更新日期：2026年9月5日

## 1. 阶段目标

当前阶段只保护一件事：让套件清单声明的全部 Skills 和团队知识库形成可信、可恢复、可验收的顾问作业闭环。

本路线图保护的稀缺资源是产品焦点和专业信任。当前不以扩大功能面为目标。

## 2. 优先级

### P0 产品口径与契约

- 确认产品定位、核心用户和明确不做项；V1.2 PRD 作为历史建议稿留档。
- 当前技能内容基线以 `skills/suite-manifest.json` 为唯一来源。网站发布通用签名 Skills 包，独立客户端消费同源的签名技能投影；两者不重复计算或维护技能清单。
- 不再维护当前宿主专用插件包或相关安装指令。历史产物只用于审计，不进入现行发布矩阵。
- 网站“Skills → 版本与下载”是唯一正式产品分发入口。
- 以门户 Skills 管理中心承接能力发现、版本核验、安装包下载和本地 Agent 安装验收，不把目录浏览误当成业务任务闭环。
- 定义项目作业包、阶段状态、质量状态和关键结论证据契约。
- 选定三条端到端金标准任务。

完成条件：团队能够用同一套语言回答“产品为谁服务、下一版只解决什么、什么不做、如何验收”。

### P1 最小闭环原型

- 只接入少量核心 Skills，不一次改造正式清单中的全部能力。
- 打通统一入口、项目作业包创建、阶段更新、恢复和统一任务摘要。
- 建立本地优先存储与云端最小字段边界。
- 为三个金标准任务补齐可执行规格和测试夹具。

完成条件：三个任务可以从自然语言入口推进到可复核结论，且中断后能恢复。

### P2 质量与业务验收

- 将政策有效性、财务勾稽、证据覆盖和一致性阻断纳入闭环门禁。
- 增加文档单一事实源校验。
- 记录最小产品事件并完成敏感字段扫描。
- 由真实顾问完成小范围试用，记录首次有效判断时间、重复追问、返工和恢复成功率。

完成条件：产品能证明真实任务质量改善，而不只是模块运行正常。

### P3 V1.2 发布治理

- 根据试用结果修正契约和交互，不扩张非必要范围。
- 更新 README、发布说明和升级路径。
- 执行通用包、独立客户端技能投影、MCP、门户和金标准任务的联合发布验收；Skills 包必须通过完整清单、签名材料和逐文件 SHA-256 校验，页面截图不替代真实业务结果。
- 形成已知问题、回滚方式和下一阶段候选清单。

完成条件：版本口径一致，安装与升级流程可验证，三条业务闭环通过，隐私边界有审计记录。

## 3. 当前明确不做

- 新增非阻断性的领域 Skill。
- 自研跨平台原生安装客户端或通过管理员权限绕过操作系统信任策略。
- 把全部 Skills 改造成独立网页按钮。
- 全量重构门户视觉设计。
- CRM、合同、回款、工时和人员排期。
- 自动提交政府申报和自动联系客户。
- 面向普通企业的一键申报 SaaS。
- 为追求指标而上传客户原始材料或可识别业务内容。

## 4. 何时可以改变路线图

只有以下证据足以触发重新排序：

- 三条金标准任务证明现有正式技能清单存在无法绕开的能力缺口。
- 真实用户无法理解项目作业包，且使用成本高于原有自由对话方式。
- 跨宿主兼容要求使统一契约不可行，需要先处理平台适配。
- 出现政策真实性、客户数据安全、安装完整性或生产稳定性的高风险问题。

单个界面偏好、新仓库热度或“再加一个 Skill 看起来更完整”不能改变本阶段主线。

## 5. 评审节奏

- 后续版本范围确认后进行一次规格评审，确认三条金标准与数据边界。
- 最小闭环跑通后进行一次用户任务评审，只看真实输入、输出、耗时和返工。
- 两周基线形成后确定下一阶段数值目标。
- 发布前进行范围复核，任何新增项必须说明它阻断哪条金标准任务。
