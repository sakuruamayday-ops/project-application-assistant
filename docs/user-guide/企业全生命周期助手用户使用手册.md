# 企业全生命周期助手用户使用手册

适用版本：Skills V1.4.1；网站安装包下载中心

本手册面向共创团队成员。企业全生命周期助手由49个平台无关 Skills、团队云端知识库、REST API和MCP组成，可导入支持 Skills 的 Agent 使用。焦糖网站统一提供通用 Skills 包和经实机验收的平台增强包。

## 1. 注册方式

### 注册前提

管理员须先将你的中文真实姓名和企业微信绑定手机号后四位加入注册邀请名单。批量导入的名单同样有效，不必等待管理员单独发送邀请链接。

### 自助注册

1. 打开团队网站，进入“注册账号”。
2. 填写英文登录账号。账号长度为3至32位，可包含数字、点、下划线和连字符。
3. 填写中文真实姓名。
4. 填写企业微信绑定手机号后四位。同名成员使用手机号后四位区分。
5. 输入公司全称 `共创集团` 完成团队验证。
6. 设置不少于9位的登录密码并提交。

每位成员只能注册一个账号。姓名或手机号后四位未命中邀请名单时，页面会提示联系管理员；管理员删除或停用成员后，该账号不能继续访问，重新加入名单后方可恢复注册资格。

### 登录

- 使用英文账号和密码登录。
- 私人设备可勾选“七天自动登录”；公共电脑不建议勾选。
- 登录后显示中文真实姓名，右上角菜单可进入账号安全或退出登录。

### 找回密码

1. 在登录页点击“验证身份并重置”。
2. 填写英文登录用户名、中文真实姓名和所属公司全称。
3. 三项信息与注册资料完全一致后，设置不少于9位的新密码。
4. 重置成功后，原有网站登录会话立即失效；个人 API 访问凭据不受影响。

### 留言反馈

登录后进入“留言反馈”，可提交故障与 Bug、知识内容纠错、功能建议或其他意见。成员可以查看自己的处理进度和管理员回复；管理员可以查看全部留言并更新为待处理、处理中、已解决或已关闭。

## 2. 下载与安装及使用方法

### 网站直接使用

登录后可在智能驾驶舱直接提问。系统优先检索团队知识库，未命中时才按宿主能力联网核验。普通成员使用团队大模型时遵守网站显示的每日额度；管理员不限次数。用户填写自己的兼容模型 API 后，不占团队问答额度。

### 从网站选择安装包

1. 登录网站，进入“Skills → 版本与下载”。
2. 只选择一个包：需要基础能力时下载通用版；需要对应宿主 Hooks、插件和 MCP 配置时下载该平台增强版。平台增强版已经包含通用 Skills，不要重复安装。
3. 只有显示“正式包已发布”的平台包可以下载。“专用包适配中”表示尚未完成真实宿主验收，不是可安装版本。
4. 正式发布固定为通用版与 WorkBuddy 跨平台版，不再维护其他宿主的平台专用版本。
5. 下载后核对网站展示的版本、SHA-256 和发布说明，再按对应平台的官方 Skills 或插件导入方式安装。
6. 网站不会扫描本机磁盘，不运行动态命令，也不会通过管理员权限绕过 Gatekeeper、SmartScreen 或企业安全策略。

### 安装 Skills

1. 登录网站，进入“Skills → 版本与下载”。
2. 根据宿主选择 V1.4.1 通用 Skills ZIP 或 V1.4.1 WorkBuddy 跨平台插件市场 ZIP。通用包按宿主要求导入；WorkBuddy 包解压后，先把完整 `jiaotang` 市场持久保存到当前宿主的 `plugins/marketplaces/jiaotang`，再在 WorkBuddy 内通过 `/plugin marketplace add <持久保存的 jiaotang 目录>` 添加市场并安装 `jiaotang-workbuddy-skills@jiaotang`。macOS 与 Windows 共用一个 WorkBuddy 包，不再使用 Windows 专用包或固定安装器。两种版本业务能力相同，不要重复安装。
3. 通用包将 `skills` 文件夹拖入或导入当前 Agent 的 Skills 目录或工作区；平台增强包按网站对应卡片和平台官方方式安装。
4. 在 Agent 中输入：

```text
请检查企业全生命周期助手是否安装完整，并启动首次配置向导。
```

若Agent不能直接识别 `SKILL.md`，使用Agent提供的Skill导入或转换能力。

首次安装后先输入：

```text
检查下知识库连接状态
```

WorkBuddy 完成 `jiaotang-kb` 运行时连接并成功调用知识库状态工具后，再输入：

```text
帮我安装OCR、PDF、Word、PPT、Excel和联网检索这几个Skills
```

通用文档、OCR和联网能力由宿主 Agent 提供，不在企业全生命周期助手中重复打包。

V1.4.1 的 `jiaotang-kb` MCP 由已签名的插件清单内联声明。正式安装不需要创建插件根目录 `.mcp.json`，也不应改写用户级、项目级或全局 MCP 配置。安装时必须先把完整 `jiaotang` 市场持久保存到当前 WorkBuddy 实际用户目录的 `plugins/marketplaces/jiaotang`，再注册和启用；不得从临时下载或临时解压目录注册，安装后也不得清理已注册市场。Windows 使用当前用户 DPAPI，macOS 使用系统钥匙串；测试凭据文件不属于正式安装路径。

### 连接团队知识库

1. 登录网站，进入“连接我的 Agent”。
2. 点击第一步“复制给 Agent”，将审查说明粘贴给当前本地 Agent；这一步不会下载安装。
3. 核对审查结论后回到网站，点击第二步“我已审查，复制安装确认”，再粘贴给同一个 Agent。
4. Agent 使用一次性受限地址自动下载、校验并安装插件包，主人不需要提前手工下载。
5. 安装后让 Agent 检查知识库连接状态；实际调用任一只读状态或检索工具成功后，首次配置才结束。

只有选择“手工配置”时才需要自行前往 Skills 中心下载插件包。自动两步流程和手工下载是二选一，不需要重复执行。

普通成员无需查看或保存个人 API Key、设备私钥和 MCP 请求头。同一账号同时只能绑定一台设备；换机时先在门户点击“更换绑定设备”，再把新的配置发送给新设备 Agent。管理员账号不执行该设备限制。

### 从 V1.4.0 跨版本升级

1. 登录网站，进入“Skills → 安装与设备”。门户只有在已验收设备版本低于最新 WorkBuddy 正式包时才显示“升级到 V1.4.1”。
2. 点击第一步生成升级审查计划，并粘贴给当前设备的同一个 Agent。核对源版本、源包哈希、目标版本、目标包哈希、发布者指纹、身份复用范围和回滚方法。
3. 回到门户点击第二步明确授权，再把升级确认粘贴给同一个 Agent。
4. Agent 使用 WorkBuddy 内置插件管理器升级已签名插件，复用原设备标识、Ed25519 设备密钥、API Token、`bootstrap_url` 和 `jiaotang-kb` MCP，不重新登记设备。
5. 目标包验签、插件启用和任一只读 `jiaotang-kb` 调用全部通过后，Agent 回传目标版本和目标包哈希；门户只在二者与固定升级计划完全一致时更新设备版本。
6. 任一步失败时恢复升级前插件目录，保留原设备身份和系统凭据，并在门户显示失败阶段和下一步。

跨版本升级不要求用户删除旧插件、移除整个 `jiaotang` 持久市场或重新绑定设备。升级计划生成后固定目标包，不会在执行过程中自动切换到其他版本。

### 个人偏好与跨设备同步

右上角用户菜单进入“我的使用习惯”。日常只需修改页面选项并保存：

- 同一账号换电脑后自动继承地区、格式、详细程度、语气和术语习惯。
- 改错时可撤销上一版或恢复官方默认，历史记录不会删除。
- 对Agent说“默认这么写”或“记住我的习惯”时，Agent自动保存为个人习惯，不再修改正式Skill。
- 旧版Skill曾被手工修改时，对Agent说“请迁移我的旧版Skills个人习惯，并同步到云端”。系统自动备份旧文件、接收安全习惯并列出无法自动处理的内容。

本地文件、偏好API和三方合并属于后台实现，普通用户不需要手工操作。

### 知识库连接完整验收

可让 Agent 按以下顺序执行，不必把凭据发给管理员：

1. `GET /v1/me`：返回当前英文登录账号。
2. `POST /v1/search`：检索一个非敏感公开关键词。
3. `GET /v1/documents/{id}`：读取上一步命中的文档。
4. `GET /v1/usage`：返回当前用户调用记录。
5. MCP初始化并读取工具列表，再调用知识服务状态或知识检索工具。

五步全部成功才算REST与MCP完整端到端验收通过。OAuth 客户端还应确认能够自动打开登录授权页并在授权后加载工具列表。仅打开网站或仅返回401不算通过。

### 可选外部能力

- 天眼查：用于企业主体、工商变更、历年名称和当前登记地区的首轮分诊。
- 企查查：增强工商、股权、风险和知识产权画像，可通过网站保留的企查查入口注册并按供应商说明配置API或MCP。
- BigQuery Patents：增强全球专利批量检索、同族和引证分析。
- 浏览器或Playwright：用于政府官网核验和合法登录后的网页任务。
- 企策顾问：仅作项目发现线索，正式条件、金额、日期和名单必须回到政府原文核验。

所有外部能力由统一首次配置向导检测，避免每个 Skill 重复配置。

## 3. 能力边界

- 覆盖政府项目检索、匹配、体检、材料编写、企业分析、专利、法律法规、制造业财税风险和交付归档，但不承诺一定符合或一定获批。
- 系统后台自动执行政策来源排序与版本核验；用户只需核对结论引用的文件名称、来源链接、效力状态和当期通知。
- 云端知识库由管理员统一上传、修改、删除和重建索引；成员的地区政策增改删保存在本人本地工作区，不写入云端。
- 无可靠数据时不推算企业财务，不以第三方过期数据替代客户材料。
- 审中专利不能作为授权成果使用；专利任务必须区分有效授权、审中、失效和转让取得。
- 专利检索、FTO和侵权预警属于初筛，不替代专利代理师或律师的正式意见。
- 法律 Skill 可做法规检索、效力核验、公司法与项目合规自查，不替代执业律师针对具体交易、争议或诉讼出具的法律意见。
- OCR结果不是天然准确，企业名称、名单序号、金额、日期和表格列必须抽样复核。
- 当前检索层未命中只能说明“未命中”，不能据此断言资料或项目不存在。

## 4. 项目算法与政策版本

### 系统如何评估一家企业

系统按以下顺序执行：

1. 锚定企业主体和目标属地。
2. 识别标准项目名称、项目族和历史别名。
3. 选择任务时间类型，包括正式判断、当年申报前准备、历史回放、预测或回测。
4. 读取稳定管理办法、当年度通知、属地规则和适用的征求意见前瞻层。
5. 将企业事实送入项目规则树，执行叶节点阈值及 `all/any` 组合判断。
6. 输出符合、不符合、待补材料或当前无法判断，并列明政策来源和企业事实缺口。

系统不会因为政策库暂时未命中就断言项目不存在，也不会用省级政策替代必须由市、区县规则决定的结论。已核验且明确替代旧政策的征求意见稿，在申报尚未开放时作为准备与预测主基线，但始终标注为尚未正式生效。

### 企业项目身份数字孪生

系统把名单身份和规则判断分开保存。认定年度、认定时名称和认定时地区以名单原文为准；当前企业名称、统一社会信用代码、现注册地址和登记机关来自当前工商核验。更名、迁址、复评、复核、失效和重新认定形成独立生命周期事件，因此可以回放企业某一年为何具有某项身份。

### 交付契约负责什么

算法负责项目规则、政策版本和企业事实判断；交付契约负责最终文件是否完整。不同报告类型分别约束：

- 必填章节和结论顺序。
- 政策原文、企业事实、同行对比和证据台账。
- 内置表格、数据口径和文件格式。
- 焦糖品牌、Logo、水印和版式审计。
- 四问复盘和后续行动。
- 产物 SHA-256 与验证记录一致。

门禁失败时，自动修复器只生成缺失章节、表格、证据或重新渲染的精确任务，不会用一段“已完成”说明代替实际文件验收。

### 专利入口说明

用户提出专利任务时，先进入 `jiaotang-patent-router` 判断是查新、布局、挖掘、交底、预审、FTO、审查意见还是项目申报证据任务。需要检查中国专利申请 Word 文件时，再进入 `checking-patdocx-cn-single-agent`。授权、审中、失效和转让取得必须分别标注；FTO 和侵权预警仅作初筛。

需要形成完整申请文件时，系统先创建每案唯一的 `patent-case-manifest`，再从确认后的事实锁 JSON 通过同一个生成器形成申请 Word 和附图规范。交底、检索证据、权利要求现有技术矩阵、核稿验证、预审建议和提交清单均回写同一清单。提交前契约检查文件哈希、案件版本和依赖关系；任一阶段错版或缺失都会给出具体重建任务。匿名测试夹具只用于升级回归，不能作为真实申请案卷。

## 6. 法律 Skill 能做什么

`jiaotang-legal-regulations` 负责把企业事实与现行法律法规建立证据链，主要输出：

- 按国家、省、市、区县和行业生成法规适用矩阵。
- 识别政策或规范文件的现行、历史、废止、失效、替代和过渡状态。
- 检查项目承诺、重复申报、财政资金、信用惩戒、材料真实性和知识产权状态风险。
- 按新公司法检查注册资本与出资、章程、治理、董监高责任、关联交易、股权转让、利润分配、减资、清算和注销。
- 对研发财税、知识产权、客户资料和数据处理给出合规红线、补证清单和整改计划。

标准输出顺序为“事实、适用规则、判断、风险、补证材料、整改动作”。涉及具体合同、交易、争议、行政处罚或诉讼时，应转交执业律师复核。

## 8. 更新与问题处理

- 网站“Skills 下载”显示最新版、发布时间和更新说明。
- 管理器连接门户时自动检查已签名平台适配器。更新只改变扫描路径和既有导入模式，不改变客户端可执行逻辑；失败时回退内置版本。
- 管理器自身当前不会静默强制升级。下载新版本前核对版本、架构、SHA-256和发布审计，再按本机授权流程安装；原有 settings、registry、备份和设备凭据保持不变。
- 扫描、适配器更新、下载验签、导入和回滚都会追加写入本机审计日志；敏感字段自动脱敏。
- 升级时运行 `first-run-configuration/scripts/upgrade_inheritance.py`。新版官方核心、个人覆盖层和云端偏好分别继承，自动生成升级继承报告。
- 升级工具以旧官方、当前安装和新官方三份 `SKILL.md` 哈希识别用户直接修改；旧文件进入可恢复备份，不会覆盖新版核心。需要保留的个人习惯应转为结构化偏好。
- 出现401：检查个人凭据是否完整、是否已被吊销，再重新生成并执行五步验收。
- 知识库未命中：确认地区、年度、项目别名和政策版本，再请求官方联网核验。
- 文档无法解析：先使用宿主OCR或文档能力转换为可检索PDF或Markdown，再由管理员上传。
