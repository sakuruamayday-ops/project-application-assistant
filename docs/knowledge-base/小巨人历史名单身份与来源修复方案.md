# 小巨人历史名单身份与来源修复方案

## 修复目标

第四至第七批国家专精特新“小巨人”企业记录统一保留：

- 名单原始企业名称
- 当前企业名称
- 曾用名
- 认定时地区
- 当前登记地区
- 认定年度与批次
- 名单状态
- 统一社会信用代码
- 官方公示页面
- 官方附件
- 来源文件哈希与核验时间

## 统一社会信用代码补全

1. 以国家企业信用信息公示系统、企查查等合法授权企业数据或主管部门公开名录为权威来源。
2. 批量导入 `企业信用代码权威补全.csv`。
3. 仅在统一社会信用代码完全一致时自动合并跨年记录。
4. 企策 `eid`、现名和曾用名用于缩小候选范围，不直接生成统一社会信用代码。
5. 同名跨省、一个名称命中多个代码、吸收合并或主体注销后承继的记录进入人工核验。

## 更名、迁址和合并处理

- 更名：保留名单原名，将工商现名写入当前名称，建立曾用名别名边。
- 迁址：认定时地区保持不变，当前登记地区单独记录，不回写历史名单地区。
- 合并：原主体和承继主体分别建节点，通过合并事件关联，不直接视为同一获批主体。
- 注销：保留历史认定事实，当前主体状态单独记录。

## 官方链接恢复

1. 对每份本地附件计算 SHA-256，固定文件身份。
2. 按“地区＋批次＋项目全称＋公示名单”搜索省级工信部门和政府门户。
3. 同时保存公示页面和附件直链，申报通知不能替代公示名单。
4. 页面失效时使用政府网站迁移后的新链接，并保留旧链接、替代链接和恢复时间。
5. 只有标题、地区、批次和附件企业集合一致时，才把链接传播到企业记录。

待处理项分别输出到：

- `官方原始链接恢复队列.csv`
- `企业信用代码待补全.csv`
- `企业身份关联待核验.csv`
- `小巨人每周新增异常.md`

## 每周增量规则

每周流水线保存上周基线，仅输出：

- 新增批次数量差额
- 新增缺失或变更的官方链接
- 新增企业名称、信用代码或地区冲突
- 官方附件内容哈希变化

已存在且未变化的历史异常不重复进入本周待办。
