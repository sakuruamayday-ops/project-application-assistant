# 知识库检索与 Skills 调用路由

## 1. 索引层级

知识库保留三类互补索引：

1. 文档索引：保存文件标题、全文、来源路径、资料角色和更新时间。
2. 分段索引：按约 1,200 字切分正文，使用中文三元 FTS 检索具体条款和上下文。
3. 企业实体索引：从名单和正文中提取企业名称、原名单序号、上下文和来源文件。

政策版本索引独立保存政策的新旧关系、废止或替代依据和候选有效状态。正式回答政策要求时，必须将分段检索结果与政策版本索引合并判断。

## 2. 同行是否认定小巨人

用户问题示例：某家企业的同行中有没有专精特新“小巨人”？

执行顺序：

1. 获取目标企业画像，包括主导产品、应用行业、产业链环节、地区和可比口径。企业画像来自用户材料或已配置的企业信息工具，不能只根据企业名称推断。
2. 以主导产品和产业链环节生成同行候选。优先使用已建立的第三方企业项目索引；没有候选企业画像时，只能做“已知同行名单核验”，不能声称已找全同行。
3. 对每个候选企业调用企业实体索引，限定 `50_名单与对标/专精特新和小巨人公示名单与认定名单`。
4. 返回企业名称、认定或公示批次、名单序号、来源文件和原文位置；公示、认定和复核状态分别列示。
5. 对同名企业、历史名称和集团子公司进行二次核对，不把母公司资质自动归给子公司。

本地精确核验示例：

```bash
python services/knowledge-portal/scripts/query_knowledge_index.py \
  "杭州某某科技有限公司" \
  --mode enterprise \
  --layers "50_名单与对标" \
  --limit 20
```

## 3. 研究院申报要求

用户问题示例：这家企业想申报研究院，有什么要求？

执行顺序：

1. 先确认地域和项目层级，例如浙江省重点企业研究院、省级企业研究院、市级企业研究院或其他研发机构项目。
2. 第一轮只检索 `10_政策与目录` 和 `20_申报指南与规则`，查询项目名称、认定办法、申报通知、申报条件、评价指标和材料清单。
3. 通过政策版本索引剔除已废止或被替代版本；无法确认有效性的文件只能作为历史参考。
4. 从分段索引提取研发投入、研发人员、研发场地、知识产权、组织架构、经营指标、信用条件和申报材料等具体条款。
5. 再检索 `60_申报案例与建设方案`，仅用于理解填写方式、建设方案结构和常见证明材料，不用历史案例替代当前政策门槛。
6. 将企业可靠数据逐项对照门槛；缺少财务或人员数据时列为待补，不自行推算。

本地政策分段检索示例：

```bash
python services/knowledge-portal/scripts/query_knowledge_index.py \
  "浙江省 企业研究院 申报条件" \
  --mode passage \
  --layers "10_政策与目录,20_申报指南与规则" \
  --limit 12
```

## 4. Skills 接入约定

Skill 不携带知识库正文，只携带检索规则和用户自己的服务地址、设备凭据变量名。调用时至少传递：

- `query`：检索问题或企业全称。
- `mode`：`passage` 或 `enterprise`。
- `layers`：允许检索的知识库一级目录。
- `limit`：候选结果数量。
- `region`、`project_type`、`as_of_date`：政策类问题的地域、项目类型和判断日期。

云端 API 应返回标题、命中片段、来源路径、文件版本、原文位置和更新时间。Skill 对返回结果执行项目识别、版本校验、企业数据对照和答案编排，不在 Skill 内保存账号、Token、Cookie 或知识库全文。

## 5. 结果可信度

- 精确命中名单只能证明企业名称出现在指定来源中，还需判断文件属于公示、认定、复核通过或历史名单。
- “同行发现”依赖企业画像和第三方企业索引；只有名单文件时，无法仅凭企业名称可靠判断同行关系。
- “项目要求”必须优先使用有效政策和当期通知；历史案例只能补充材料写法。
- 所有正式结论应返回来源文件和原文位置，未命中写“当前检索层未命中”。
