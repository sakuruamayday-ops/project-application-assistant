# 企业全生命周期助手 V1.4.5

发布日期：2026年8月1日

V1.4.5 将 WorkBuddy 安装收敛为一次复制粘贴，同时完成 49 项 Skills、最小行为 Hook 和远程 jiaotang-kb MCP 连接。

算法程序化执行留作后续独立项目。

## 主要变化

- 门户一键安装指令同时完成 49 项 Skills 安装或覆盖升级、最小行为 Hook 启用、用户级远程 MCP 合并、一次重载和 knowledge_service_status 验收。
- 登录用户的手工配置页自动复用有效个人 Token；无有效 Token 时自动生成，并直接填入完整 MCP JSON。
- WorkBuddy 包不再内置本地 jiaotang-agent.mjs、.mcp.json、run-node 启动器、bootstrap、设备密钥、钥匙串或 Windows DPAPI 流程。
- 用户安装阶段不再执行安装包签名审查、用户侧签名校验或每轮插件目录哈希检查；受控发布链仍在服务器侧校验候选产物。
- 49 项 Skills 均有行为覆盖门禁；WorkBuddy 包只保留业务 Skills、插件清单、最小行为 Hook、必要参考资料和业务脚本。
- 49 项顶层 Skills 的业务规则、路由和交付契约与 V1.4.3 保持兼容。
- 旧版用户通过同一段指令自动覆盖插件、移除旧本地 MCP 连接，仅替换 jiaotang-kb，并保留其他 MCP 条目。
- Windows 热修明确将自定义连接器写入 `%USERPROFILE%\\.workbuddy\\mcp.json`，macOS 写入 `~/.workbuddy/mcp.json`；两端均禁止修改 WorkBuddy 托管的 `.workbuddy/.mcp.json`。
- 覆盖升级先把旧插件目录移到带时间戳的可恢复备份，再安装干净目录，防止旧版 `.mcp.json`、`bin` 或 `mcp` 本地启动器残留重新注册失效连接器。
- 新连接器首次出现后仍须由用户在 WorkBuddy 界面手动信任；安装流程不得绕过宿主安全确认。
- 新增简化安装端到端验收，覆盖新装、旧版覆盖、Token 复用、保留其他 MCP、工具枚举和真实状态调用。

## 已删除的安装机制

- 不再包含本地`jiaotang-agent.mjs` MCP服务、`.mcp.json`、`run-node`或`run-node.cmd`。
- 不再使用bootstrap、设备登记、设备公私钥、逐请求签名、macOS钥匙串、Windows DPAPI或四阶段绑定。
- 用户安装和普通提问不再执行签名审查、插件目录哈希或`plugin.json`完整性阻断。
- 最小Hook只负责Skill调用与交付检查；Hook内部或路径异常时继续普通提问。

## Token边界

- Token只出现在当前登录用户的手工配置页和一键安装指令中。
- 配置页面使用`Cache-Control: private, no-store`。
- 公共插件包、公共代码、普通日志和Agent最终回复不得包含完整Token。
- Token明文保存在当前用户的WorkBuddy MCP配置中；怀疑泄露时撤销旧Token，重新打开配置页即可生成新Token。

## 完成标准

- 49项Skills已经安装并可识别。
- `tools/list`出现`knowledge_search`、`knowledge_document`、`knowledge_service_status`。
- 实际调用`knowledge_service_status`返回`connected: true`。
- 用户原有其他MCP条目未被覆盖。
- 全程没有bootstrap、设备绑定、钥匙串、DPAPI或用户侧签名校验步骤。

## 回滚

安装或升级前备份原插件目录和用户MCP配置。任一步失败时保留现场，恢复两份备份，仅撤销`jiaotang-kb`变更，不影响其他MCP和用户项目资料。
