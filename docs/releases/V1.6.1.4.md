# V1.6.1.4 本地修复候选说明

V1.6.1.4 仅用于 Codex 本地回归与 macOS、Windows WorkBuddy 实机验证，不是 GitHub Latest，不替换 V1.6.1 正式发布。

## 本轮修复

- Windows 与 macOS Stop 在正式交付已经激活主业务 Skill 时建立 `effective_business_domain`。即使提示词层的 `business_domain` 漏判，Grounded 质量闸门也不得被跳过。
- Grounded 校验器默认把正式 `grounded-delivery/v1` 回执写入与宿主 Hook 相同的行为状态根。Windows 固定使用 `%USERPROFILE%\.workbuddy\state\gongchuang-behavior`，macOS 使用当前市场插件的用户级 `plugins/data/<plugin>-<marketplace>/behavior-hook`。
- 用户需要在工作区保留可见收据时使用 `--receipt-export-dir`。该参数只复制副本，不改变 Stop 消费的正式回执位置；正式交付不得再把 `--state-root` 指向 `artifacts` 或交付目录。
- Stop 只接受 `validator_id`、当前 `turn_id`、`status=pass` 与交付文件当前 SHA-256 全部一致的回执。旧 turn、失败状态或文件校验后发生变化时仍然阻断。
- `首台套`、`首批次`、`首版次`加入业务领域识别词，补齐三首正式报告的路由边界。
- Windows 原生 Hook 继续使用运行时 1.6.6，并把当前修复同步到固定 Go 源码与打包器，防止开发源和安装包二进制漂移。

## 数据、文档与发布边界

企业数字身份证不进入插件包。企业数字身份证、主题词典和知识索引继续由服务端与 OSS 独立管理。DOCX 宿主渲染能力不作为本轮 Stop 回执消费修复的强制验收项。本候选不发布 GitHub Latest，不切换正式技能包，也不发布新索引代际。

## 待实机验收

- macOS WorkBuddy：正式业务报告回合应在当前行为状态根生成 validator receipt，Stop 收据中的 `validator_receipts` 必须非空且 `delivery_check_ok=true`。
- Windows WorkBuddy：执行同一业务回合并核对 `%USERPROFILE%\.workbuddy\state\gongchuang-behavior\validator-receipts\<turn_id>`、交付文件 SHA-256 与 Stop 收据三方一致。
- 两端均另做负向测试：删去当前 turn 回执或在校验后修改交付文件，Stop 必须阻断，不得回退消费旧 turn 回执。

## 回滚

候选异常时恢复 V1.6.1 正式市场目录和原有 MCP 配置。旧候选与过期技术状态只移入系统回收站，不永久删除用户资料。
