# 企业全生命周期助手 V1.4.9

发布日期：2026年8月2日

V1.4.9 修复 WorkBuddy 默认安装布局下的 Hook 根目录发现，并补齐可独立核验的激活持久化回执。

## 完整版本事实

- Skill 激活启动器在宿主未注入 CODEBUDDY_PLUGIN_ROOT 和 CODEBUDDY_SKILL_DIR 时，会从用户目录下的 .workbuddy 与 .codebuddy 插件市场布局确定性发现当前插件。
- 根目录候选必须同时满足插件目录名、plugin.json、行为 Hook 脚本和目标 SKILL.md 校验；无效同名目录会被跳过，不会误执行当前工作目录中的脚本。
- 插件级 UserPromptSubmit 与 Stop Hook 使用同一套跨平台根目录发现逻辑，不再单独依赖宿主环境变量。
- Skill 激活成功回执新增 root_source、state_persisted、active_skills_after 和 active_skill_count，可直接证明激活状态已经持久化，无需依赖宿主未公开的 active_skills 查询接口。
- 49 项生成后 Skill 已在默认 WorkBuddy 市场布局中逐项执行激活回归，最终同一会话状态精确记录 49 项。
- 继续保持 49 项 Skill 首字节 YAML frontmatter、真实名称原生加载、正式业务零 Skill 激活阻断和提示词只存摘要的既有边界。
- 继续保持 49 项 Skills、用户级远程 HTTP MCP、自动填入个人 Token、只替换 jiaotang-kb、保留其他 MCP 和一次重载的简化安装边界。

## 修复范围

- 不拆分为 49 个独立安装包；仍是一份插件包，内含 49 个相互独立、可按真实名称加载的 Skills。
- 不修改 49 项业务规则正文，不包含业务算法化改造。
- 不修改知识库 MCP 协议、个人 Token 填充或用户级 MCP 合并逻辑。
- 不恢复用户侧签名校验、目录哈希、设备绑定、钥匙串或本地 MCP 启动器。

## 验收标准

- 49 项 Skills 继续以真实名称原生枚举并可按名加载。
- 在未注入插件根目录与 Skill 目录环境变量时，49 项 Skill 激活回执均为 `activation_ok=true`。
- 每次成功回执均包含根目录来源、持久化确认和激活后的 Skill 清单；最终 `active_skill_count=49`。
- 插件级提示词与停止 Hook 在默认市场布局中可启动。
- 无效同名插件目录不被采用，根目录不可用时返回明确错误码并保持失败开放。
- 三个知识服务工具继续枚举，`knowledge_service_status` 返回 `connected=true`。

## 兼容与回滚

- macOS 已完成默认 `.workbuddy` 与兼容 `.codebuddy` 市场布局自动化回归；发布后再做一次 WorkBuddy 黑箱复验。
- Windows 使用相同 ZIP 和基于用户主目录的跨平台路径逻辑；结构与 CI 已验证，实机激活仍待发布后复验。
- 升级失败时恢复安装前插件目录与用户 MCP 配置备份，不覆盖其他 MCP 条目、个人项目资料或个人偏好。
