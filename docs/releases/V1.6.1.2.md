# V1.6.1.2 本地修复候选说明

V1.6.1.2 仅用于 Codex 本地回归与 WorkBuddy 实机验证，不是 GitHub Latest，不替换 V1.6.1 正式发布。

## 本轮修复

- `recognition_search` 兼容“国家专精特新小巨人企业”“国家级专精特新小巨人”等常用项目名称，不再依赖失败后的自然语言重试。
- 真实宿主收据把技能激活、提示 Hook 可观测性和交付检查拆成三层。`activation_fallback` 可以证明 Skill 已激活，但不能冒充完整 Prompt/Stop Hook 闭环。
- `knowledge_search` 不返回分页状态；实际使用该路径时，全局 `truncated` 报告为 `unavailable`，除非其他检索路径已经明确截断。
- 收据生成器确定性检查双计数、分级合计和“声明无冲突但实际存在冲突”等问题。
- 验收任务未明确要求归档时不主动创建 `.workbuddy/memory`；未取得官方最终名单的批次不列为主表遗漏。

## 数据与发布边界

企业数字身份证不进入插件包。企业数字身份证、主题词典和知识索引继续由服务端与 OSS 独立管理，不进入插件 ZIP。本候选不发布 GitHub Latest，不切换正式技能包，也不发布新索引代际。

## 平台验收边界

- macOS WorkBuddy：重新安装本候选后复测湿巾主题反查、分页状态、冲突收据和只读边界。
- Windows WorkBuddy：本轮不重编原生 EXE，延用 V1.6.1 Hook；系统级签名和真实宿主运行仍需 Windows 实机证据。

## 回滚

候选异常时恢复 V1.6.1 正式市场目录和原有 MCP 配置。旧候选只移入系统回收站，不永久删除用户资料。
