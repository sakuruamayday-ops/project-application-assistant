# 企业全生命周期助手 V1.4.2

发布日期：2026 年 7 月 30 日

V1.4.2 修复 WorkBuddy 5.3.5 的插件 MCP 注册与首次设备绑定兼容性，恢复真实工具枚举，并保留 V1.4.1 的跨版本升级事务。

## 套件清单版本事实

- 按 WorkBuddy 5.3.5 的真实插件扫描规则恢复插件根目录 .mcp.json，并在 plugin.json 中保留相对路径声明；jiaotang-kb 现可被宿主注册和枚举。
- 移除宿主未实现的第三方 userConfig 依赖；未绑定插件先仅暴露 jiaotang_kb_setup 与无敏感信息状态工具，通过本地 MCP 工具完成一次性设备绑定。
- setup 工具不回显 bootstrap_url，长期 API Token 和 Ed25519 私钥继续只保存到 macOS 登录钥匙串或 Windows 当前用户凭据管理器。
- 绑定完成后在同一插件进程补做远端 MCP 初始化并发送 tools/list_changed 通知；若宿主未主动刷新，完全退出并重启 WorkBuddy 后直接加载远端 knowledge_search、knowledge_document 等真实工具。
- MCP stdio 代理改为串行处理 JSON-RPC 消息，避免 initialize、notifications/initialized 与 tools/list 并发转发造成会话竞争。
- V1.4.0 和 V1.4.1 已绑定设备升级 V1.4.2 时复用原设备标识、密钥和访问凭据，不重新登记；未绑定的 V1.4.1 安装可在升级后完成绑定。
- 验收门禁改为实际 tools/list 必须包含远端检索工具，并成功调用 knowledge_service_status 或任一只读检索；通用资源读取器返回业务错误不再视为连接成功。
- 49 项顶层 Skills 与 V1.4.1 业务规则保持不变。

## 根因与判定修正

- WorkBuddy 5.3.5 的第三方插件页不会渲染插件 `userConfig`，因此用户无法在界面填写 `bootstrap_url`。
- WorkBuddy 的插件连接器加载器扫描插件根目录 `.mcp.json`。V1.4.1 只在 `plugin.json` 内联 MCP 声明，导致宿主没有实际注册 `jiaotang-kb`。
- 通用 `ReadMcpResource` 返回 `no connector owns resource URI` 是宿主连接器路由错误，不能证明请求已经到达焦糖远端，也不能据此判断“远端未绑定 connector”。
- 安装成功必须以远端 `tools/list` 枚举出真实知识库工具，并成功调用一个只读工具为准。

## WorkBuddy 修复

- 恢复签名插件根目录 `.mcp.json`，并在 `.codebuddy-plugin/plugin.json` 中保留相对路径声明。
- `.mcp.json`、跨平台 Node 启动器和 MCP 代理均进入插件逐文件哈希与 Ed25519 签名清单。
- 移除对第三方 `userConfig` 界面的依赖。未绑定插件先暴露 `jiaotang_kb_setup` 和 `jiaotang_kb_setup_status`，由 Agent 将门户一次性 `bootstrap_url` 仅作为本地 setup 工具参数调用一次。
- setup 工具不回显一次性地址、API Token 或私钥。长期凭据继续只保存到 macOS 登录钥匙串或 Windows 当前用户凭据存储。
- 绑定成功后在同一插件进程补做远端 MCP 初始化并发送 `tools/list_changed`。若 WorkBuddy 未主动刷新，完全退出并重启后会直接加载远端工具。
- stdio 代理改为串行处理 JSON-RPC，避免 `initialize`、初始化通知与 `tools/list` 并发竞争。
- 安装器的连接门禁会真实检查 `knowledge_search`、`knowledge_document` 和 `knowledge_service_status`，并调用 `knowledge_service_status`。

## 两步安装协议

第一步只审查，不写入、不包含 `bootstrap_url`。Agent 必须先识别宿主名称与版本，核对宿主原生安装入口、签名适配包、联网范围、三层存储和回滚路径。

第二步必须由用户在门户明确授权。授权固定第一步已审查的宿主、版本、适配器类型和包哈希；发生任一漂移都停止安装。只有宿主注册、系统凭据回读、远端工具枚举、只读工具调用和门户四阶段状态全部通过，才报告完成。

## WorkBuddy 适配范围

| 宿主 | V1.4.2 自动两步安装 |
|---|---|
| WorkBuddy 5 macOS | 支持 |
| WorkBuddy 5 Windows | 结构与签名支持，真实 Windows 绑定待实机验收 |

该自动安装流程不适配其他 Agent。第一步若确认当前宿主不是 WorkBuddy 5 或更高版本，必须停止，不得下载或安装 WorkBuddy ZIP。

## 升级与回滚

- 已经完成绑定的 V1.4.0 或 V1.4.1 设备升级后复用原设备标识、Ed25519 密钥、API Token 与 `jiaotang-kb` 身份，不需要重新提供 `bootstrap_url`。
- V1.4.1 已安装但未完成绑定的设备升级 V1.4.2 后，可通过本地 setup 工具完成首次绑定。
- 升级失败时恢复原插件目录和原版本包，不删除持久市场、设备绑定、设备密钥、API Token、个人偏好或本地项目资料。

## 已知限制

- WorkBuddy 插件安装、启用和真实工具触发仍须由 WorkBuddy 应用内流程完成；外部构建回归不能冒充宿主实机验收。
- Windows 包已通过结构、签名和运行时回归，真实 Windows 安装、钥匙串等价凭据保存及重启仍需实机验收。
- 自动两步安装仅支持 WorkBuddy 5。
