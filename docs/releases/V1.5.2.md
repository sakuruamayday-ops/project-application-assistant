# 企业全生命周期助手 V1.5.2

发布日期：2026年8月3日

V1.5.2 是当前对外发布的唯一最新版本，修复 Windows 端新用户消息未可靠建立独立 Hook 轮次的问题，并增加 macOS 与 Windows 两个明确的一键安装入口。

## 本次发布

- WorkBuddy 插件继续只有一个 ZIP，49 项 Skills、交付规则和远程 `jiaotang-kb` MCP 均为双端共用。
- Hook 运行时拆分为共享状态核心、macOS 启动适配器和 Windows 启动适配器；`hooks.json` 不再执行超长内联 Python。
- Windows 适配器在 WorkBuddy 使用的 Git Bash 中选择可用的 `py -3`、`python` 或 `python3`，并原样转发 Hook 的 stdin。
- 每次 `UserPromptSubmit` 都生成新的 `turn_id`、提示摘要和提示信号，并把 `active_skills` 原子重建为空列表。
- 同一条用户消息内的多 Skill 继续累计；下一条用户消息从新的轮次和 `active_skill_count=1` 开始。
- Skill 激活回执增加 `state_origin`、`prompt_context_ok` 与 `prompt_sha256_present`。
- 如果 `UserPromptSubmit` 未执行或当前提示上下文不可用，激活状态明确标为 `activation_fallback`；Stop 失败开放并返回 `PROMPT_CONTEXT_UNAVAILABLE`、`delivery_check_ok=null`，不再暗示交付检查通过。
- 门户并排提供“一键安装 macOS 版”和“一键安装 Windows 版”，不自动识别系统。安装码、协议和下载链接绑定所选平台，跨平台误用返回 HTTP 409。
- Token 仍只在当前登录用户的一键安装指令和手工配置页中出现；其他 MCP 条目继续保留。
- 本次不修改知识索引，代码与 Skills 发布只校验签名回执、应用指针和现有索引绑定，不运行全库扫描。

## 用户是否需要更新

- Windows 用户必须更新，旧版可能在不同用户消息之间保留上一轮 Skill 状态。
- macOS 用户建议同步更新，以保持插件版本和机器回执字段一致；业务规则与已验证的交付逻辑不变。

## 验收标准

- 通用包与 WorkBuddy 包各含 49 项可识别 Skills，版本均为 1.5.2。
- 连续两条用户消息产生不同 `turn_id`，第二条不包含第一条激活的 Skill。
- 同一条用户消息连续激活多个 Skill 时，`turn_id` 保持不变且计数依次增加。
- 缺少 Prompt 上下文时返回 `PROMPT_CONTEXT_UNAVAILABLE`、`delivery_check_ok=null` 和 `continue=true`。
- macOS 与 Windows 安装入口生成各自系统路径，不混入另一平台路径；误用安装码返回 HTTP 409。
- `tools/list` 枚举三个核心知识工具，`knowledge_service_status` 返回 `connected: true`，其他 MCP 条目未被覆盖。
- 自动化发布门禁、Windows CI、macOS WorkBuddy 和 Windows WorkBuddy 实机验收均须通过后才能正式发布。

## 回滚

- Skills 安装失败时恢复搜索路径外的安装前插件快照和原 MCP 配置。
- 代码部署失败时把生产 `current` 指针切回上一应用槽，知识索引指针保持不变。
- V1.5.2 产物按版本和哈希不可变；同名版本已存在不同内容时停止，不覆盖。
