# 企业全生命周期助手 V1.5.2

发布日期：2026年8月3日

V1.5.2 是当前对外发布的唯一最新版本。

V1.5.2 修复 Windows Hook 新消息轮次未重置，并增加 macOS 与 Windows 双平台一键安装入口。

## 本次发布

- WorkBuddy Hook 改为共享状态核心加 macOS、Windows 两个极薄启动适配器，hooks.json 不再承载超长内联 Python。
- Windows 适配器在 Git Bash 中依次选择 py -3、python 和 python3，并把 Hook 事件 JSON 原样从 stdin 转交共享核心。
- 每次 UserPromptSubmit 原子生成新的 turn_id、提示摘要和提示信号，并清空上一轮 active_skills。
- 同一轮多 Skill 继续累计；下一条用户消息的 active_skill_count 从 1 重新开始。
- 激活回执增加 state_origin、prompt_context_ok 和 prompt_sha256_present，可区分真实提示状态与激活兜底状态。
- 缺少当前提示上下文时 Stop 失败开放并返回 PROMPT_CONTEXT_UNAVAILABLE、delivery_check_ok=null，不再暗示交付检查通过。
- 网站明确提供一键安装 macOS 版和一键安装 Windows 版两个并排入口，不自动识别系统；安装码和下载链接绑定所选平台，误用返回 HTTP 409。
- 两个入口继续共用一个 WorkBuddy ZIP、49 项 Skills、业务规则和远程 jiaotang-kb MCP，不复制业务包。
- 本次不修改知识索引；纯代码与 Skills 发布不运行全库扫描。
- Token 仍只在当前登录用户的一键安装指令和手工配置页中出现；其他 MCP 条目继续保留。

## 用户是否需要更新

- Windows 用户必须更新，旧版可能在不同用户消息之间保留上一轮 Skill 状态。
- macOS 用户建议同步更新，以保持插件版本和机器回执字段一致；业务规则与已验证的交付逻辑不变。

## 验收标准

- 通用包与 WorkBuddy 包各含 49 项可识别 Skills，版本均为 1.5.2。
- 连续两条用户消息产生不同 `turn_id`，第二条不包含第一条激活的 Skill。
- 同一条用户消息连续激活多个 Skill 时，`turn_id` 保持不变且计数依次增加。
- 缺少 Prompt 上下文时返回 `PROMPT_CONTEXT_UNAVAILABLE`、`delivery_check_ok=null` 和 `continue=true`。
- macOS 与 Windows 安装入口生成各自系统路径，不混入另一平台路径；误用安装码返回 HTTP 409。
- `tools/list` 枚举三个核心知识工具，`knowledge_service_status` 返回 `connected: true`，其他 MCP 条目未被覆盖。
- 自动化发布门禁与 Windows CI 通过后即可正式发布；macOS、Windows WorkBuddy 实机验收由主人在发布后补录，不阻断正式发布。

## 回滚

- Skills 安装失败时恢复搜索路径外的安装前插件快照和原 MCP 配置。
- 代码部署失败时把生产 `current` 指针切回上一应用槽，知识索引指针保持不变。
- V1.5.2 产物按版本和哈希不可变；同名版本已存在不同内容时停止，不覆盖。
