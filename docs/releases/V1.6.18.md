# 共创研究院企业全生命周期助手 V1.6.18 候选说明

V1.6.18 以 V1.6.17 正式版为上一基线，修复制造企业财税报告中生成器、确定性计算与专业交付契约互相不一致的问题。当前仅用于签名包和客户端真实业务验收；完成发布事务前，GitHub Latest 与门户正式版本仍为 V1.6.17。

## 一、本版本变更

- 财税报告固定生成“财务总览”“风险地图”“90天整改路线”“计算过程与来源”四张契约表，并按报告可见中文章节校验顺序。
- 确定性计算器自动输出营业收入同比、应收账款同比、研发费用率、资产负债表恒等式差额和无法计算原因。
- 报告生成器强制读取 `manufacturing-tax-risk-metrics/v1`，核对企业主体，并把确定性复算直接写入报告，避免模型遗漏或手工改写。
- 主技能没有专用模板或生成器时，客户端通过已签名 `evidence-ledger.create-docx` 将已预校验正文一次生成原生 DOCX，禁止临时脚本、环境探查和成品回读循环；专用模板仍保持最高优先级。
- 兜底 DOCX 统一采用紧凑 A4 版式；同一份 2796 字、2 个表格的质量品牌测试稿经 WPS 实际渲染由 4 页收敛为 3 页，避免内容校验通过但违反用户页数上限。
- 共享品牌运行时及同类 PDF 脚本统一使用 PyMuPDF 的当前导入入口，避免依赖弃用警告污染受签名操作的单一 JSON 回执。
- 51 项技能统一约束隐藏工具必须通过宿主 `run_code` 调用，先执行已记录命令，只有真实报错且契约不明确时才读取直接相关源码，避免根级工具失败和无效上下文膨胀。
- 发布前对全部 29 个 Office 模板和 4 个源码模板执行解析、保存回读与真实渲染，对 24 个项目报告母版逐一核对交付契约。
- 继承 V1.6.17 的文档读取、专业交付有界收束、模型与推理档位保持及同源技能投影能力。

## 二、验收边界

候选包必须通过源码测试、模板实渲染、逐技能清单与 Ed25519 签名、隔离安装和客户端原生业务复测。只有 GitHub 正式发布、门户切换、客户端技能更新清单回读和本机同步均成功后，才可将本文件状态改为正式发布。

- macOS 与 Windows 客户端均消费 V1.6.18 的同一签名技能身份；两端安装包、更新和回滚仍由各自客户端发布事务独立验收。
- 通用包不携带用户凭据、客户资料或本地知识索引，企业数字身份证不进入插件包或技能包。
