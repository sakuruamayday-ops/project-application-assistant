# V1.6.2 正式发布说明

V1.6.2 是企业全生命周期助手当前对外正式版本。本版本把 V1.6.1.3 与 V1.6.1.4 候选中已经完成双端正向实机验证的 WorkBuddy 状态与正式交付修复收束为稳定发布。

## 本次变更

- macOS 与 Windows Stop 在正式业务交付已经激活主业务 Skill 时，统一使用 `effective_business_domain` 进入 Grounded 质量门禁。
- Stop 只接受当前 `turn_id`、`status=pass`、正确 `validator_id` 且交付文件当前 SHA-256 一致的回执。
- Windows 正式回执固定写入用户级 `.workbuddy/state/jiaotang-behavior`；macOS 写入当前市场插件的用户级行为状态目录。
- `--receipt-export-dir` 仅生成用户可见副本，不再改变 Stop 读取的正式回执根目录。
- SessionStart、UserPromptSubmit、Skill 激活和 Stop 统一执行当前会话、当前回合和提示事件隔离，拒绝旧 session 或旧 turn 重放。
- 首台套、首批次和首版次纳入正式业务识别，避免三首报告因提示词漏判绕过主业务 Skill 或 Grounded 门禁。
- Windows 原生 Hook 运行时为 `1.6.6`，状态 Schema 为 `4`；产品正式版本和 49 项 Skill 契约统一为 `1.6.2`。

## 机器可验证的完整版本事实

V1.6.2 是正式稳定版：修复 WorkBuddy Stop 未消费当前 turn Grounded validator receipt 的问题，统一双端状态目录、有效业务域与 Session 隔离规则。企业数字身份证仍作为服务端外部数据单独发布，不进入插件包。

- Windows 与 macOS Stop 在正式交付已激活主业务 Skill 时建立 effective_business_domain，即使提示词 business_domain 漏判也必须执行 Grounded 质量闸门并消费当前 turn 回执。
- Grounded 校验器默认把正式回执写入与宿主 Hook 完全一致的行为状态根；Windows 固定使用用户级 .workbuddy/state/jiaotang-behavior，macOS 使用插件 data 行为目录。
- 工作区需要保留用户可见收据时改用 receipt-export-dir 复制副本；state-root 不得再指向 artifacts 或交付目录，避免 Stop 看不到已经生成的回执。
- Stop 只接受 validator_id、turn_id、pass 状态和当前文件 SHA-256 全部一致的回执；旧 turn 回执、失败回执和文件变更后的回执继续失败关闭。
- 首台套、首批次和首版次加入正式业务地域识别词，避免三首业务报告因领域提示词漏判而绕过主业务 Skill 与 Grounded 门禁。
- WorkBuddy Host Hook 与沙箱内 Skill 激活统一使用用户级 plugins/data/<plugin>-<marketplace>/behavior-hook 状态根；沙箱缺少 CODEBUDDY_PLUGIN_DATA 时从已验证的市场安装路径确定性推导，避免同轮被拆成恢复状态与 activation_fallback 两份状态。
- macOS 新增 SessionStart 冷启动恢复：只读取宿主提供的同一 session_id、两分钟内且位于 WorkBuddy 项目目录的 JSONL，提取当前 user_query 的摘要；不扫描其他任务，也不保存提示正文。
- SessionStart 恢复状态如实标记 state_origin=session_start_recovery、prompt_context_source=session_transcript、prompt_hook_observable=false；后续原生 UserPromptSubmit 到达同轮时升级为 user_prompt_submit。
- 同一会话同一提示在五秒内去重，避免市场级与 Skill 内联 Hook 重复注册生成两个 turn_id；Windows 原生 EXE 同步增加受限 SessionStart 恢复。
- Windows 生命周期 Hook 与 49 个 Skill 内联激活入口均从固定的 $HOME/.workbuddy 正式市场根直接调用原生 EXE，不依赖 Windows 进程中不稳定的 CODEBUDDY_PLUGIN_ROOT 注入。
- Windows 宿主未发出 Prompt Hook 时，Skill 激活只从当前项目两分钟内的新鲜转录恢复上下文，并如实标记 skill_activation_recovery；同一转录事件多 Skill 累积，新消息生成新 turn_id 并清空旧 Skill。
- Windows 原生 Hook 运行时升级为 1.6.6；Stop 载荷的 session_id 与 Skill 激活恢复会话不一致时，只在当前项目转录、current-turn、turn_id、提示哈希和事件编号全部对齐后改用当前 turn 审计，并输出 stop_state_source 与 stop_payload_session_matched 收据。
- macOS UserPromptSubmit 同时接受 WorkBuddy 5.3.11 的 user_prompt 与旧版 prompt 字段，真实提示能够创建全新轮次状态。
- 无宿主会话标识的 Skill 激活仅复用十五分钟内、状态一致且非测试会话的 current-turn；dry-run、夹具和过期轮次一律降级为 activation_fallback。
- 国家小巨人、省级专精特新等非三首权威名单不再接受无效的 product_name 或 industry 参数；主题词反查固定转入 recognition_search。
- 完整性回执分离 coverage_complete 与 truncated，并在覆盖不完整时禁止‘全部闭合’、‘确认不存在’等超证据表述。
- 新增 WorkBuddy 真实宿主 JSONL 确定性收据生成器，只按实际 Skill 事件、MCP 尝试、外网调用和写入事件计数。
- recognition_search 接受国家专精特新小巨人企业等常用项目名称，不再依赖失败后的自然语言重试。
- 真实宿主收据分离 activation_ok、prompt_hook_observable 与 delivery_check，fallback 激活不再被误报为技能激活失败。
- 使用无分页状态的 knowledge_search 时全局 truncated 固定为 unavailable，除非其他路径已经明确截断。
- 收据生成器自动发现含糊双计数、分级合计不一致和声明无冲突但实际存在冲突的报告。
- 验收任务未获明确授权时不再主动创建 .workbuddy/memory 工作日志；尚未形成官方最终名单的批次不列为主表遗漏。
- 统一来源登记、稳定编号、主张映射、计算血缘和最小披露规则，保留各文档类型的原生页面结构。
- 市场占有率采用固定乘除链、六同校验和 A 至 D 分级；D 级可生成明确限制用途的报告，但不得冒充可对外使用的精确结论。
- 正式 Grounded 交付必须产生与当前 turn_id 绑定的确定性验证回执；Stop Hook 不再把空 validator_receipts 判为已完成。
- Windows 将已明确请求的输出文件与作为输入的工作簿分开；离线、禁上传等限制不得取消正向报告交付意图。
- Windows 与 macOS 的正式交付否定只在否定词实际支配生成、输出或撰写等交付动作时生效；来源披露限制和生成器描述不得覆盖先前的正向交付请求。
- 来源登记增加 obtained 与 reference_only 访问状态；未取得原文的链接不得声称检索日期或伪装成用户文件。
- Word 交付拒绝模板默认修改时间、空最后修改者和生成器元数据，并交叉校验台账与成品的来源访问状态。
- Windows SessionStart、UserPromptSubmit、Skill 激活与 Stop 统一由原生 EXE 处理，状态写入用户级 .workbuddy/state/jiaotang-behavior。
- 本地 XLSX 只读检查提供无第三方依赖路径，不得为读取用户文件临时联网安装依赖。
- 未经用户明确授权不得把输入或交付文件上传到 COS、云渲染或其他外部服务。
- 分析报告来源位于文末，Excel 来源位于最后工作表，PowerPoint 来源位于最后一页；标准正文保持规范性引用文件结构并另附来源说明。
- 注册表、调用图、共享夹具、影响图和双端回执按批次同步更新。
- 前期培育报告先完成企业现有方向、用户给定方向和建议新增方向三类方向卡，再进入政策适配、成熟度和专利布局。
- 专利路由继续使用已核验的专利检索、挖掘、预审、布局和交付规则，不把企业数字身份证或索引数据打入插件。
- 人才项目增加基于真实履历、项目阶段与落地需求的创业区域预评估；例外通道必须有官方依据，人才券与算力券只作条件式分析。
- 服务端建立现名、曾用名、统一社会信用代码与合并主体的身份血缘，并支持按名称或信用代码反查冲突路径。
- 企业数字身份证、同行对比主题词和待补画像数量以服务端当前签名索引为准；插件包不固化会持续增长的数据总量。
- 应用槽与索引代际的活动目录只保留 current 和 previous；更早代际先移入系统回收站并记录精确路径，不在发布事务中永久删除。

## 发布物

V1.6.2 同步发布通用 Skills、macOS WorkBuddy 和 Windows WorkBuddy 三套完整安装包，三者均包含同一组 49 项 Skills。企业数字身份证不进入插件包；安装包也不包含知识索引、用户 Token、设备凭据、本地 MCP 服务或客户资料。

企业数字身份证、主题词和知识索引通过独立的服务端签名索引发布。本次与 V1.6.2 同一发布窗口更新，但不作为插件包构建输入。

## 兼容性与验收边界

V1.6.1.4 候选已经完成 macOS 与 Windows 真实 WorkBuddy 正向验收：正式业务交付能够消费当前 turn 的 `grounded-delivery/v1` pass 回执。最终 V1.6.2 ZIP 在发布前完成结构、签名、确定性回归、解压自检和安全扫描；最终包的真实设备安装结果允许由主人在发布后补录，不作为本次发布阻断项。

Windows Authenticode 不作为本次发布前置条件。正式安装包继续使用受控发布事务、Ed25519 签名和 SHA-256 绑定；Authenticode 系统级核验由主人在发布后补测，不能用 Ed25519 结果冒充。

## 回滚

客户端安装失败时恢复上一正式 Skills/WorkBuddy 快照，不覆盖用户项目、个人偏好或其他 MCP 配置。门户、应用代码和签名索引分别保留 current 与 previous，任一层失败只回滚对应指针。
