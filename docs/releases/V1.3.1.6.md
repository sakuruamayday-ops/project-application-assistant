# 企业全生命周期助手 V1.3.1.6

发布日期：2026 年 7 月 29 日

本版本修复 WorkBuddy 重启后插件运行文件丢失及运行时目录缺少 `.mcp.json` 导致的连接中断。安装流程会先把本地市场持久保存到宿主插件目录，再注册和启用；`jiaotang-kb` MCP 改由签名插件清单内联声明，不再要求 Agent 向用户目录或项目目录补写 MCP 配置。

## 套件清单版本事实

修复 WorkBuddy 重启后插件运行文件丢失与 .mcp.json 完整性依赖导致的连接中断，要求持久保存本地市场并由签名插件清单内联声明 jiaotang-kb。

- jiaotang-kb MCP 改由签名 .codebuddy-plugin/plugin.json 内联声明，正式包不再依赖插件根目录 .mcp.json。
- UserPromptSubmit 钩子统一输出 ASCII 安全 JSON，避免 Windows 控制台编码破坏错误信息。
- JIAOTANG_TEST_CREDENTIAL_FILE 仅在显式开启 JIAOTANG_ENABLE_TEST_CREDENTIAL_FILE=1 时生效，正式 Windows 路径继续使用当前用户 DPAPI。
- 门户明确禁止安装流程写入用户级、项目级或全局 MCP 配置；连接必须由已签名插件清单加载。
- 安装流程必须先把完整 jiaotang 市场保存到当前 WorkBuddy 的持久用户插件目录，再注册和启用；清理只覆盖下载包与未注册中转目录。
- 首次配置必须确认 jiaotang-kb 已进入当前 WorkBuddy 运行时并成功调用任一只读状态或检索工具，之后才提示安装 OCR、PDF、Word、PPT、Excel 和联网检索 Skills。

## 修复内容

- `.codebuddy-plugin/plugin.json` 内联声明 `jiaotang-kb` MCP，正式 WorkBuddy 包不再包含或依赖插件根目录 `.mcp.json`。
- `UserPromptSubmit` 钩子使用 ASCII 安全 JSON 输出，避免 Windows 控制台编码破坏错误信息。
- `JIAOTANG_TEST_CREDENTIAL_FILE` 仅在显式设置 `JIAOTANG_ENABLE_TEST_CREDENTIAL_FILE=1` 时生效；正式 Windows 环境继续使用当前用户 DPAPI，macOS 继续使用系统钥匙串。
- 门户安装协议禁止写入用户级、项目级或全局 MCP 配置。连接由已签名插件清单随插件安装和重启加载。
- 安全解压后必须先把完整 `jiaotang` 市场保存到当前 WorkBuddy 实际用户目录的 `plugins/marketplaces/jiaotang`，再从该持久目录注册。安装后只清理下载 ZIP 和未注册中转目录。
- 首次配置在四阶段登记后继续检查 `jiaotang-kb` 是否进入当前运行时，并实际调用任一只读状态或检索工具；成功后才提示安装 OCR、PDF、Word、PPT、Excel 和联网检索 Skills。

## 安装流程

1. 在门户复制第一步审查说明并发送给 WorkBuddy。
2. 核对后回到门户复制第二步安装确认，并发送给同一个 WorkBuddy 会话。
3. Agent 使用一次性受限地址自动下载固定的 V1.3.1.6 WorkBuddy 发布包，校验 SHA-256 和 Ed25519 签名后安装。
4. Agent 识别当前 WorkBuddy 实际用户目录，把完整 `jiaotang` 市场持久保存到其 `plugins/marketplaces/jiaotang`，再通过插件管理注册。不得直接注册临时下载或临时解压目录。
5. WorkBuddy 从签名 `plugin.json` 加载 `jiaotang-kb`，无需手工创建 `.mcp.json`，也不得写入用户级、项目级或全局 MCP 配置。
6. Agent 检查 `jiaotang-kb` 是否进入当前运行时，并实际调用任一只读状态或检索工具。
7. 只有调用成功后，首次配置才结束，随后提示安装 OCR、PDF、Word、PPT、Excel 和联网检索 Skills。清理只覆盖下载 ZIP 与未注册中转目录。

自动两步流程不要求用户提前下载插件包。只有主动选择“手工配置”时，才从 Skills 中心下载签名包。

## 兼容性

- macOS 已复现临时市场被清理后 `spawn ${CODEBUDDY_PLUGIN_ROOT}/bin/run-node ENOENT`；正式 V1.3.1.5 包内实际包含已签名的 `bin/run-node`，故障来自安装后删除了它所在的临时市场目录。
- Windows WorkBuddy 5.3.5 的原故障已完成结构复现：V1.3.1.5 在运行时缺少 `.mcp.json` 时会由提交钩子中止请求。
- V1.3.1.6 已通过包结构、签名、无 `.mcp.json` 启动和钩子编码回归，Windows 状态为“结构兼容，待主人实机验收”。
- 已完成设备绑定的用户升级时无需重新登记；系统凭据不随插件包复制或覆盖。

## 安全与发布门禁

- 未确认阶段不暴露插件下载地址；第二步只生成绑定当前已确认安装码的一次性受限地址。
- 安装协议禁止动态命令，只允许下载已核验发布资产、校验完整性和完成 WorkBuddy 应用内插件安装。
- 发布包使用 Ed25519 插件级签名、逐文件 SHA-256、解压回归与安装自检。
- MCP 配置属于签名插件内容；安装流程不得写入宿主用户级、项目级或全局 MCP 配置。
- 已注册的持久市场、插件运行文件和系统凭据不属于安装临时文件，安装后不得清理。
- 测试凭据文件必须显式开启测试开关，正式环境默认使用 macOS 系统钥匙串或 Windows 当前用户 DPAPI。

## 回滚

- 正式提升前失败：V1.3.1.5 保持网站当前正式版本，V1.3.1.6 只保留为预发布证据。
- 正式提升后需要回滚：恢复 V1.3.1.5 下载指向；已经完成的设备绑定保持有效。
- 本地回滚：在 WorkBuddy 中停用或卸载 V1.3.1.6，再按需安装 V1.3.1.5；不得手工替换签名包内文件或补写 `.mcp.json`。
