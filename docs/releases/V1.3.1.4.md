# 企业全生命周期助手 V1.3.1.4

发布日期：2026 年 7 月 29 日

本版本把 WorkBuddy 设备登记升级为“预登记—安全保存与回读—签名激活”的两阶段事务，并增加无敏感信息的一键诊断页。49 项业务技能内容保持不变，V1.3.1.3 继续作为不可变历史版本保留。

## 套件清单版本事实

设备登记升级为凭据保存后再激活的两阶段事务，并增加无敏感信息的一键诊断页。

- 设备登记改为预登记、系统凭据保存与回读、本机签名激活；预登记阶段不创建有效 Token、设备绑定或设备公钥。
- 激活阶段在单个数据库事务内创建凭据、绑定和公钥，并支持激活响应丢失后的幂等续跑，根除凭据未落盘造成的半绑定。
- Skills 中心新增无敏感信息一键诊断页，展示正式包 SHA-256、Ed25519 签名状态、脱敏登记 URL 和四阶段连接状态。
- 正式提升前保留 V1.3.1.3 滚动升级兼容路径；V1.3.1.4 成为当前包后阻断旧的一阶段登记请求，49 项业务技能内容不变。

## 修复内容

- 预登记只保存短期登记意图，不创建有效访问凭据、设备绑定或设备公钥。
- 插件把凭据写入 macOS 登录钥匙串或 Windows DPAPI 后必须立即回读；只有回读值一致，才使用本机私钥签名激活。
- 激活在单个数据库事务中创建访问凭据、设备绑定和设备公钥，同时记录凭据保存与首次验签时间。
- 激活请求支持幂等重试。即使激活响应丢失，插件下次启动也会读取本地待激活凭据继续完成事务，不会重复绑定。
- Skills 中心新增一键诊断页，显示正式包 SHA-256、连接器 SHA-256、Ed25519 签名状态、发布者公钥指纹、脱敏登记 URL 和四阶段状态。
- 诊断页不读取或输出一次性安装码、访问凭据、私钥、完整设备公钥和本机凭据路径。

## 两阶段登记事务

1. 插件生成本机 Ed25519 密钥对并发起预登记。
2. 服务器返回短期待激活凭据，但不把它加入有效凭据和设备绑定表。
3. 插件将凭据与私钥写入系统安全存储并回读校验。
4. 插件使用回读后的私钥对激活请求签名。
5. 服务器核对预登记、设备标识、公钥标识、凭据指纹和签名，在单一事务中激活。
6. 插件再发起签名 MCP 连接，门户依次确认设备登记、凭据保存、首次验签和 MCP 首次连接。

如果第 3 步失败，服务器只有会随安装码过期的预登记意图，门户不会显示已绑定设备，也不需要“更换绑定设备”。

## 一键诊断

登录门户后进入“Skills 中心 → 安装与设备 → 打开无敏感信息一键诊断”，可以核对：

- 发布记录与服务器文件的完整 SHA-256 是否一致。
- WorkBuddy 插件 Ed25519 签名和逐文件哈希是否有效。
- 当前登记 URL 是否已生成及其脱敏状态。
- 四阶段连接分别完成到哪一步。

诊断页只读，不执行设备更换、凭据吊销或重新登记。

## 兼容性

- 已正常连接的 V1.3.1.3 用户无需重新绑定。
- 服务端在 V1.3.1.4 提升前保留旧客户端滚动升级兼容入口；V1.3.1.4 成为当前正式包后，旧的一阶段登记请求会直接要求升级，不再创建半绑定。
- macOS 与 Windows 继续共用同一个签名 WorkBuddy 包。
- 旧版发生的半绑定仍可通过原有“撤销未完成登记”入口清理；V1.3.1.4 新登记不会再产生该状态。

## 安全与发布门禁

- WorkBuddy 插件包继续使用 Ed25519 插件级签名和逐文件 SHA-256。
- 激活证明绑定安装码、设备标识、公钥标识和访问凭据指纹，私钥始终不上传。
- 一键诊断页响应使用 `private, no-store`，页面源代码不包含安装码或凭据。
- GitHub 与知识门户继续执行“正式发布中 → 主人独立确认 → 正式提升”的两阶段发布流程。

## 回滚

- 发布提升前失败：V1.3.1.3 继续保持网站当前正式版本，V1.3.1.4 只保留为预发布证据。
- 发布提升后需要回滚：恢复 V1.3.1.3 下载指向；已经完成的 V1.3.1.4 设备激活仍是有效绑定，不自动改写。
- 本地回滚：在 WorkBuddy 中停用或卸载 V1.3.1.4；不得手工替换签名包内连接器文件。
