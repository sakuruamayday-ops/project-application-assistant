# 企业全生命周期助手 V1.3.1.3

发布日期：2026 年 7 月 29 日

本版本修复 Windows WorkBuddy MCP 首次连接的连接器摘要、登记 URL 与半绑定恢复链路。
49 项业务技能内容保持不变，V1.3.1.2 的既有发布资产继续作为不可变历史证据保留。

## 修复内容

- 插件模式改为校验当前正式 WorkBuddy 包内连接器摘要，独立安装器仍校验网站安装器摘要，避免两类产物交叉校验。
- 设备登记使用 URL 对象追加 register 路径，完整保留 platform=unified 查询参数，修复 Windows 首次登记 HTTP 405。
- Skills 管理中心在设备已登记但 MCP 尚未连接时显示撤销入口，可安全清理未完成绑定后重新配置。
- 新增连接器源码一致性、签名清单摘要、查询参数登记 URL 和半绑定门户入口回归门禁；49 项业务技能内容不变。

## 故障链路

V1.3.1.2 的 Windows 首次连接可能依次出现以下现象：

1. 插件内连接器与生产引导清单的安装器 SHA-256 不一致，MCP 子进程退出并显示 `-32000 Connection closed`。
2. 手工替换连接器会破坏插件级签名清单，`UserPromptSubmit` 因文件哈希不一致而失败关闭。
3. 带 `?platform=unified` 的引导地址使用字符串追加 `/register`，登记请求落入错误 URL 并返回 HTTP 405。
4. 设备已经登记但凭据未保存时形成半绑定，Skills 中心仅显示第一阶段完成，缺少就地撤销入口。

V1.3.1.3 将插件连接器完整性锚定到当前正式签名包，修正 URL 构造，并补齐半绑定撤销入口。

## 安装与恢复

1. 已正常连接的既有用户无需重新绑定。
2. 遇到半绑定的用户先在门户 Skills 中心点击“撤销未完成登记”。
3. 在 WorkBuddy 中停用并卸载旧版焦糖插件，重新下载 V1.3.1.3 跨平台 WorkBuddy 包。
4. 完整解压 `jiaotang` 市场目录，在 WorkBuddy 内通过 `/plugin` 添加市场、安装并启用插件。
5. 在门户完成两步审查，将新生成的 `bootstrap_url` 只填入插件敏感配置。
6. 门户的设备登记、凭据保存、首次验签与 MCP 首次连接四阶段全部完成后，方可判定成功。

不要手工替换签名插件中的 `mcp/jiaotang-agent.mjs`，否则插件完整性校验会按设计阻断。

## 安全与发布门禁

- WorkBuddy 插件包继续使用 Ed25519 插件级签名和逐文件 SHA-256。
- `bootstrap_url`、安装码、访问令牌和设备私钥不得写入普通配置、日志或聊天。
- 引导清单中的插件连接器摘要必须等于正式下载包内文件摘要及插件签名清单摘要。
- Windows 与 macOS 共用同一签名包；Windows runner 和真实 WorkBuddy 宿主验收结果分别记录，不互相冒充。
- GitHub 与知识门户继续执行“正式发布中 → 主人独立确认 → 正式提升”的两阶段流程。

## 回滚

- 发布提升前失败：保留 V1.3.1.2 为网站当前正式版本，不替换下载入口。
- 发布提升后需要回滚：将 V1.3.1.3 从网站当前入口撤下并恢复 V1.3.1.2 下载指向；服务器端设备、公钥与凭据不自动改写。
- 本地回滚：在 WorkBuddy 中停用或卸载 V1.3.1.3；半绑定记录通过门户撤销，不永久删除用户文件。
