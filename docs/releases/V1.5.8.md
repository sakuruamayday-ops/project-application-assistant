# 企业全生命周期助手 V1.5.8

发布日期：2026年8月4日

V1.5.8 是当前对外发布的唯一最新版本。

V1.5.8 将 Windows 行为 Hook 切换为宿主 Git Bash 直接调用的原生 EXE，并收紧正式交付意图与模板证据判定。

## 套件清单事实

- Windows UserPromptSubmit、Skill 激活与 Stop 统一由原生 EXE 处理，不再经过 PowerShell、CMD、Python 或多层 shell 桥接。
- Windows Hook 状态写入用户级 .workbuddy/state/gongchuang-behavior，插件目录保持发布后不可变。
- macOS 保持既有 Python 与 shell 启动链，不因 Windows 修复改变已验证路径。
- 正式交付判定排除否定、引用、未来计划、概念解释和插件技术验收汇总，仅在当前业务交付意图明确时启动主业务门禁。
- 待核验、当前检索层未命中、无官方来源和暂无法判断视为已披露的证据状态，不再误报章节缺失。
- 四问复盘从文件硬门禁降为任务结束提示，交付文件只检查业务必要章节与相互矛盾的确定性结论。
- 安装过程中禁止改写、转码或补丁处理正式包；预检失败时停止并保留原版本。
- 代码发布和索引发布继续独立执行；本版本没有知识内容或索引结构变化，只使用 code 模式。

## 本次发布

- Windows `UserPromptSubmit`、Skill 激活与 `Stop` 统一由实机验证过的原生 EXE 处理，不依赖 PowerShell、CMD 或本机 Python。
- macOS 保持 Shell 与 Python Hook 路线，两个平台共享正式交付规则并隔离运行时。
- 每条新消息重建 `turn_id` 并清空旧 Skill，同轮多个 Skill 正常累计且不重复计数。
- Stop 已阻断的任务保存独立的限时快照；明确继续未完成任务时恢复原门禁，普通新问题不继承。
- “不得生成”“禁止形成”、概念解释、引用、未来计划和插件技术验收不再误触发正式业务交付门禁。
- 正式业务交付缺少主业务 Skill 时继续返回 `NO_PRIMARY_BUSINESS_SKILL`；主业务 Skill 在场时正常放行。
- “待核验”“当前检索层未命中”“暂无官方来源”和“暂无法判断”作为诚实证据状态，不再被误报为模板缺项。
- 安装程序必须保持正式包逐字节不变，平台预检失败时保留旧插件与原 MCP 配置。
- 本版本不含知识内容或索引结构变化，只使用 `code` 模式发布。

## 实机验收

- Windows RC2-r3：新消息重建、同轮多 Skill、否定意图、正式交付阻断、阻断续轮和主业务 Skill 放行均通过。
- macOS RC2-r3：技术否定意图、正式交付阻断、阻断续轮和主业务 Skill 放行均通过。
- macOS 安装目录与候选包 299 个受控文件一致，`package_mutated=false`。
- 正式包从同一冻结源码生成，Windows 使用 RC2-r3 已验证 EXE 字节，不在安装阶段二次修补。

## 用户是否需要更新

- Windows 用户应更新，以移除对 PowerShell 执行策略、CMD 拼接和本机 Python 的依赖。
- macOS 用户建议同步更新，以获得正式交付意图修复和独立阻断快照。
- 已安装旧版本的用户无需手工删除插件；一键安装预检通过后建立回滚快照，只保留一个 V1.5.8 活动市场并保留其他 MCP 条目。

## 已知边界

- Windows EXE 当前未使用 Authenticode 签名。已通过当前实机测试，但部分企业 Defender 或 SmartScreen 策略仍可能要求管理员放行。
- Ed25519 发布签名用于验证焦糖发布者与安装包完整性，不等同于 Windows Authenticode。

## 回滚

- 安装失败时恢复活动搜索路径外的旧插件快照和原 MCP 配置，失败目录移入系统回收站。
- 代码部署失败时把生产 `current` 指针切回上一应用槽，并保留部署事务与失败槽。
- 知识索引未参与本次发布，不需要索引回滚。
- V1.5.8 同名附件不可覆盖；发现版本或哈希冲突时停止发布。
