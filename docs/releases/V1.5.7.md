# 企业全生命周期助手 V1.5.7

发布日期：2026年8月4日

V1.5.7 是当前对外发布的唯一最新版本。本版本修复正式交付被阻断后经宿主继续任务绕过门禁的问题，强化 Windows Hook 编码和状态写入，并把正式安装包设为不可变产物。

## 本次发布

- 上一轮 Stop 已被门禁阻断，且下一条由宿主明确标记自动继续或用户发送有限的继续表达时，新轮继续继承正式交付信号、缺项错误和已激活 Skill。普通新问题仍生成新轮次并清空上一轮状态。
- macOS Python Hook 与 Windows PowerShell Hook 统一返回 `previous_delivery_blocked`、`blocked_error_code`、`continued_from_turn_id`、正式交付判定和 Stop 事件回执，便于区分意图识别、Stop 执行和模板缺项。
- 正式交付分句判断不再把“只解释”“只回答”作为整句全局否定，并识别“不要只解释”“别只回答”等否定非交付表达。
- Windows 正式 ZIP 中的 PowerShell Hook 使用 UTF-8 BOM，显式设置 stdin、stdout 和管道编码；状态临时文件写入后回读验证，持锁替换后再次回读，替换失败保留原状态并失败开放。
- 门户一键安装先在隔离暂存目录对原包执行只读平台预检，预检通过后才移动旧版。安装过程中禁止改写、转码或补丁处理 `plugin.json`、`hooks.json`、PowerShell、Shell、Python、权限和换行符，也不得加入 `ExecutionPolicy Bypass`。
- 安装机器回执增加预检、包变更、失败阶段、错误码和回滚恢复字段。只要 `package_mutated=true` 或平台预检失败，安装即停止并恢复旧版。
- 本版本没有知识内容或索引结构变化，生产只执行 `code` 模式；不运行全库扫描，也不切换知识索引。

## 用户是否需要更新

- Windows 用户应更新，以取得 UTF-8 BOM PowerShell Hook、显式管道编码、状态文件回读验证和受限执行策略预检。
- macOS 用户建议同步更新，以修复被阻断任务在宿主自动继续时丢失正式交付门禁的问题。
- 已安装旧版本的用户不需要手工删除插件。一键安装在原包预检通过后把旧版移到活动搜索路径之外的回滚快照，只保留一个 V1.5.7 活动市场，并保留其他 MCP 配置。

## 验收标准

- 通用、macOS WorkBuddy 与 Windows WorkBuddy 三个签名包均包含 49 项 Skills，版本统一为 1.5.7。
- Windows 包内 `.ps1` 以 UTF-8 BOM 开始，直接由 `powershell.exe` 调用，不包含 Bash、CMD、Python 解释器发现或权限绕过参数。
- 正式交付被 `NO_PRIMARY_BUSINESS_SKILL` 或模板缺项阻断后，明确继续任务仍保持原门禁；新的普通问题不继承上一轮 Skill。
- “不要生成报告，只解释条件”放行；“不要只解释，直接生成报告”和“别只回答，输出正式申请书”触发正式交付门禁。
- 门户安装指令要求先预检后备份，安装前后文件逐字节一致，失败时恢复插件快照和原 MCP 配置。
- 自动化代码与封包门禁通过后正式发布；macOS、Windows WorkBuddy 实机验收由主人在发布后补录，不作为发布前阻断项。

## 回滚

- Skills 安装失败时恢复活动搜索路径外的安装前插件快照和原 MCP 配置；失败的新目录移入系统回收站，不永久删除。
- 代码部署失败时把生产 `current` 指针切回上一应用槽，并保留事务回执、日志与失败槽供复核。
- 知识索引未参与本次发布，不需要执行索引回滚。
- V1.5.7 产物按版本和哈希不可变；同名版本已存在不同内容时停止，不覆盖。
