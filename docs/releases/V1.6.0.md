# V1.6.0 正式发布说明

V1.6.0 是企业全生命周期助手当前对外发布版本。本版本把 Grounded 证据交付、前期培育方向卡、已核验专利规则和跨平台最小行为 Hook 合并到同一套 49 项 Skills 中。

## 本版本包含

- Grounded 证据登记、来源访问状态、主张与证据绑定、计算血缘和交付回执。
- 市场占有率固定计算链、同口径校验与 A 至 D 分级；受限复现结果不得冒充精确结论。
- 前期培育报告先形成企业现有方向、用户给定方向和建议新增方向三类方向卡，再进入政策适配、成熟度和专利布局。
- 专利总路由继续提供查新、挖掘交底、预审、布局、FTO 和交付规则，专利规则与证据台账保持独立可追溯。
- macOS 使用 Python Hook，Windows 使用原生 EXE Hook；普通问答失败开放，正式交付才执行对应门禁。
- 一键安装保持一次复制粘贴、保留其他 MCP、只替换 `mcpServers.jiaotang-kb` 并重载一次。

## 清单事实（发布门禁逐字记录）

本版本的套件清单事实如下：

- V1.6.0 正式发布 Grounded 证据交付、前期培育方向卡、专利规则与跨平台最小行为 Hook。企业数字身份证属于外部数据门禁，不进入插件包。
- 统一来源登记、稳定编号、主张映射、计算血缘和最小披露规则，保留各文档类型的原生页面结构。
- 市场占有率采用固定乘除链、六同校验和 A 至 D 分级；D 级可生成明确限制用途的报告，但不得冒充可对外使用的精确结论。
- 正式 Grounded 交付必须产生与当前 turn_id 绑定的确定性验证回执；Stop Hook 不再把空 validator_receipts 判为已完成。
- Windows 将已明确请求的输出文件与作为输入的工作簿分开；离线、禁上传等限制不得取消正向报告交付意图。
- Windows 与 macOS 的正式交付否定只在否定词实际支配生成、输出或撰写等交付动作时生效；来源披露限制和生成器描述不得覆盖先前的正向交付请求。
- 来源登记增加 obtained 与 reference_only 访问状态；未取得原文的链接不得声称检索日期或伪装成用户文件。
- Word 交付拒绝模板默认修改时间、空最后修改者和生成器元数据，并交叉校验台账与成品的来源访问状态。
- Windows UserPromptSubmit、Skill 激活与 Stop 继续由原生 EXE 处理，状态写入用户级 .workbuddy/state/gongchuang-behavior。
- 本地 XLSX 只读检查提供无第三方依赖路径，不得为读取用户文件临时联网安装依赖。
- 未经用户明确授权不得把输入或交付文件上传到 COS、云渲染或其他外部服务。
- 分析报告来源位于文末，Excel 来源位于最后工作表，PowerPoint 来源位于最后一页；标准正文保持规范性引用文件结构并另附来源说明。
- 注册表、调用图、共享夹具、影响图和双端回执按批次同步更新。
- 前期培育报告先完成企业现有方向、用户给定方向和建议新增方向三类方向卡，再进入政策适配、成熟度和专利布局。
- 专利路由继续使用已核验的专利检索、挖掘、预审、布局和交付规则，不把企业数字身份证或索引数据打入插件。

V1.6.0 Windows WorkBuddy 与 V1.6.0 macOS WorkBuddy 使用同一套 49 项 Skills；两端真实设备验收结果在发布后补录。

## 数据边界

企业数字身份证不进入插件包。企业数字身份证、主题词索引和知识库内容属于服务端外部数据门禁，不是插件包构建输入。本次仅发布代码与插件包，不运行全库索引扫描，也不把企业身份数据放入 ZIP。

## 验收与兼容性

- 49 项 Skills、注册表、调用图、Grounded 共享运行时和方向卡参考资料通过结构与脱敏门禁。
- 通用包、macOS WorkBuddy 包和 Windows WorkBuddy 包使用同一套 Skills 与业务规则。
- Windows 和 macOS 的真实设备结果由主人在发布后补录；这不改变本次代码/插件包发布事务。

## 回滚

失败时恢复上一正式版本的 Skills 目录、插件目录和用户 MCP 配置；不覆盖用户资料、个人偏好或其他 MCP。回滚记录与本版本产物哈希一并保留。
