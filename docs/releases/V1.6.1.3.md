# V1.6.1.3 本地修复候选说明

V1.6.1.3 仅用于 Codex 本地回归与 macOS、Windows WorkBuddy 实机验证，不是 GitHub Latest，不替换 V1.6.1 正式发布。

## 本轮修复

- Host Hook 与沙箱内 Skill 激活统一使用 WorkBuddy 用户级插件数据目录。沙箱未注入 `CODEBUDDY_PLUGIN_DATA` 时，从已验证的市场安装路径确定性推导同一状态根，避免成功恢复的真实轮次在 Skill 激活时被误读成 `activation_fallback`。
- WorkBuddy 5.3.11 在启动和恢复同一任务的每条用户消息前均可能先写入消息、再触发插件 `SessionStart`；macOS 与 Windows 均使用同会话转录恢复，避免真实轮次只能进入 `activation_fallback`。
- 恢复只接受宿主给出的真实 `session_id`，且 `transcript_path` 必须是两分钟内、文件名与会话一致、位于 `~/.workbuddy/projects` 或 `~/.codebuddy/projects` 的 JSONL；不扫描其他任务，不保存提示正文。
- 恢复状态如实标记为 `state_origin=session_start_recovery`、`prompt_context_source=session_transcript`、`prompt_hook_observable=false`。若宿主后续实际发出原生 `UserPromptSubmit`，同一轮才升级为 `user_prompt_submit`；不得把未发出的事件写成已观察。
- 同会话同摘要五秒内去重，避免重复注册的 Hook 生成两个 `turn_id`。
- macOS `UserPromptSubmit` 同时识别 WorkBuddy 5.3.11 使用的 `user_prompt` 和旧版 `prompt` 字段，真实用户提示能够建立全新轮次。
- 空会话 Skill 激活只复用十五分钟内、轮次与状态文件一致、来源为 `user_prompt_submit` 或 `session_start_recovery` 且仍为 `pending` 的当前轮次。
- `dry-run-`、`fixture-`、`local-self-check-` 和 `test-` 会话不得作为真实宿主当前轮次；过期、错配或测试状态统一降级为 `activation_fallback`，不得声称 Prompt Hook 闭环。
- dry-run 与回归测试使用临时插件数据目录，不向活动市场的 `.behavior-data` 写入测试轮次。
- V1.6.1.2 已有的认定反查、截断状态、冲突收据和 Grounded 交付门禁保持不变。

## 数据与发布边界

企业数字身份证不进入插件包。企业数字身份证、主题词典和知识索引继续由服务端与 OSS 独立管理，不进入插件 ZIP。本候选不发布 GitHub Latest，不切换正式技能包，也不发布新索引代际。

## 平台验收边界

- macOS WorkBuddy：安装本候选后，连续执行两轮独立用户消息。WorkBuddy 5.3.11 当前实测两轮均可由 `SessionStart` 转录恢复；两轮必须保持同一 `session_id`、生成不同 `turn_id`、返回 `prompt_context_ok=true`，并至少为当前轮保留可绑定的 Stop 原始回执。原生 `UserPromptSubmit` 仅在宿主真实发出时核对，不作为本版本强制验收前提。
- Windows WorkBuddy：本轮已用固定 Go 1.26.4 工具链重编原生 EXE，增加受限 `SessionStart` 恢复、同提示去重和新回合 Skill 清零；自动测试不替代 Windows 实机回执，且 Authenticode 系统级签名仍须单独核验。

## 回滚

候选异常时恢复 V1.6.1 正式市场目录和原有 MCP 配置。旧候选与过期技术状态只移入系统回收站，不永久删除用户资料。
