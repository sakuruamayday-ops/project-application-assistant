# 企业全生命周期助手 V1.4.4

发布日期：2026 年 8 月 1 日

V1.4.4 合并六个任务中的已验证改动，并补齐知识库案例包与统一验收框架。版本继续包含 49 项业务 Skills，沿用 V1.4.3 的固定发布者 Ed25519 信任链和受控发布事务。

## 主要变化

- 索引生产指针改用 OSS 不可变前驱转换声明实现原子切换，避免依赖阿里云 `PutObject` 不支持的 `If-Match` 条件头；并发发布保持失败关闭，同一目标支持中断后恢复。
- 新设备采用“审查、安装、bootstrap 绑定”三步流程；第三步授权前不得获取一次性引导地址。新增 macOS、Windows 共用自动端到端夹具，真实双端验收由主人在发布后完成。
- 国家小巨人、省级专精特新中小企业和三首新增权威结构化事实入口，返回完整总数、官方匹配数、来源等级和分页状态；权威专表缺失时失败关闭，不回落到通用实体表。
- 专利总路由增加技术特征证据图、分层检索、自然人发明人门禁和 AI 专利充分公开检查。能力采用独立实现，不包含第三方私有代码、模型、数据库或界面。
- 统一 Acceptance Harness 覆盖知识库分类、敏感资料、政策生命周期、检索回归和案例包结构。机密及受限资料优先于目录规则，禁止对象存储和语义上云。
- 新索引增加稳定项目身份、案例包、案例文档和文档关系表，并提供 `knowledge_case_pack` 分层查询。自动归组结果标为待复核；案例仅可借鉴结构和证据类型。

## 兼容性与验收

- 现有 `knowledge_search`、`knowledge_document`、`knowledge_service_status`、名单及三首工具保持兼容。
- `knowledge_service_status` 新增知识架构版本、索引发布身份、构建时间、案例包能力和案例包总数。
- WorkBuddy 包仍保留插件根 `.mcp.json`、跨平台 Node 启动器和本地 setup 工具，全部进入签名清单。
- 安装入口按宿主分流：WorkBuddy 仅使用三步安装完成插件与 MCP 配置；非 WorkBuddy 用户使用个人 Token 手工配置远程 Streamable HTTP MCP，不再展示手工 WorkBuddy 配置。
- 发布前不再启动真实 WorkBuddy CLI；改为校验最终签名候选包、49 项技能覆盖、插件根 MCP 配置、跨平台启动器及 macOS/Windows 三步安装夹具。真实双端宿主验收保留在发布后进行。
- 发布后状态在主人完成 macOS、Windows 手工验收前统一标记为“已发布，待双端实机验收”。

## 已知边界

- 全库案例关系先由目录与项目身份自动归组；未人工确认的案例包为 `auto_grouped`，不得视为事实已核验。
- 本版本不执行此前明确排除的 RPO/RTO 恢复演练，也不处置历史 OSS 对象、暂存或部署备份。
- Windows WorkBuddy 真实凭据保存、重启和 MCP -32000 回归由主人在发布后实机验收。
