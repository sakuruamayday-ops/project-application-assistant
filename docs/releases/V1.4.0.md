# 企业全生命周期助手 V1.4.0

发布日期：2026 年 7 月 30 日

V1.4.0 是政策算法、企业身份、交付质量和专利案卷能力升级版。版本保持 49 项顶层 Skills，不改变已绑定设备身份；签名通用包和 WorkBuddy 跨平台包均重新构建，不覆盖 V1.3.1.6。

## 套件清单版本事实

V1.4.0 将 28 个常规项目、政策时间语义、企业项目身份数字孪生、政策变化影响模拟、交付契约和专利完整案卷纳入同一可追溯执行内核。

- 28 个常规项目全部进入统一规则中间语言；网站展示 28 类常规项目，运行时另保留 1 个兼容别名编译单元。
- 政策检索支持主管部门原文、下级政府明确引用、当前有效管理办法三级降级；降级来源不得虚构年度截止时间和批次要求。
- 正式判断、历史回放、当年申报前准备、预测和回测使用不同政策时间类型，阻止新规则冒充历史事实。
- 已核验且明确替代旧政策的征求意见稿，在申报尚未开放时作为准备主基线；页面和报告保留尚未正式生效标识。
- 杭州、宁波、绍兴、金华研发平台统一路由为市级研发中心（四市属地版）和市级企业技术中心（四市属地版），保留旧名称别名和历史记录。
- 杭州、宁波、绍兴、金华共 38 个行政区县完成绿色工厂正式政策适用注册；未解析属地规则时禁止用省级门槛替代区级结论。
- 增加企业项目身份数字孪生和生命周期事件回放，覆盖政策版本、名单附件、主体匹配和身份迁移。
- 增加政策变化影响模拟器、依赖图和内容哈希增量编译，只更新受影响的城市、年度和项目族。
- 增加 WorkBuddy 交付契约和自动修复任务，约束政策选择、同行对比、四问复盘、内置表格、证据来源、品牌、水印和产物哈希。
- 专利完整申请任务增加全案唯一清单、事实锁、统一申请文件生成器、文件哈希和提交前交付契约，阶段错版会被阻止并生成重建任务。
- 正式提升前以通用签名包原子升级发布机 Codex Skills，完成套件级与 49 项技能级验签、开发源与正式包及实际安装目录三方哈希比对，并输出单一部署审计报告。
- 49 项顶层 Skills 数量保持不变；V1.3.1.6 已绑定设备升级 V1.4.0 时无需重新登记。

## 项目算法与政策版本

- 28 类常规项目都已形成正式阈值规则包。企业事实先进入叶节点阈值，再由原生 `all/any` 组合得出符合、不符合、待补材料或当前无法判断。
- 主管部门年度原文未命中时，可以使用下级政府官网对上级通知的明确引用；仍未命中时回到当前有效管理办法，但不得据此补造年度批次、截止日期或材料要求。
- 正式判断、当年申报前准备、历史回放、预测和回测分别选择政策时间类型。已核验且明确替代旧政策的征求意见稿可作为未来准备主基线，但保留草案状态。
- 四市研发平台和企业技术中心按杭州、宁波、绍兴、金华属地规则路由。四市 38 个行政区县的绿色工厂项目已登记正式适用路径，省级政策只作为上位依赖。

## 企业项目身份数字孪生

系统将名单身份与规则判断分开保存。认定年度、认定时名称和认定时地区保留名单原文；当前企业名称、统一社会信用代码、注册地址和登记机关来自工商核验。更名、迁址、复评、复核、失效和重新认定形成独立生命周期事件，可回放到政策版本、名单附件、主体匹配和身份迁移过程。

## 政策变化影响模拟

新政策进入后，系统用政策依赖图定位受影响项目，再用内容哈希判断城市、年度或项目族是否真的发生变化。只有变化单元重新编译；受影响的企业身份事件、准备评估、预测和历史回测会进入重算清单，未受影响结果继续复用。

## 交付契约与自动修复

分析报告、专精特新前后期材料、金税四期报告等交付物分别登记必填章节、来源、证据台账、内置表格、品牌、水印、文件格式和产物哈希。门禁失败时，自动修复器生成精确到章节、表格、证据来源或重新渲染的任务，不接受一段“已完成”说明代替文件验收。

## 专利完整案卷

专利公司级任务继续由 `jiaotang-patent-router` 统一分诊，中国专利申请 Word 核稿继续使用 `checking-patdocx-cn-single-agent`。完整申请案卷增加以下约束：

- 每案只有一份 `patent-case-manifest`，统一登记任务头、技术交底、检索计划、现有技术证据、申请输入、申请 Word、附图规范、权利要求现有技术矩阵、核稿、核稿验证、预审建议和提交清单。
- 申请文件生成器只读取确认后的事实锁 JSON 和标准输入，不再为每件案件维护多套临时脚本。
- 文件角色、案件版本、SHA-256 和上游依赖哈希必须一致；上游变化、阶段错版或文件缺失会阻止 `filing-ready` 并生成具体重建任务。
- 仓库匿名测试夹具不含真实企业、发明人、技术方案、参数、专利编号或原案标题，只用于升级回归，不能作为真实申请案卷。

客户原始案卷继续保留在商业秘密档案，不进入通用 Skills、标准包或签名插件。

## 安装与兼容性

- 通用 Skills 与 WorkBuddy 继续使用同一套 49 项业务能力。
- V1.3.1.6 已完成设备绑定的用户升级时无需重新登记。
- WorkBuddy macOS 与 Windows 继续使用同一个签名跨平台包。Windows 已通过结构、签名和钩子回归，真实升级与重启仍保留实机验收标识。
- 自动两步安装与手工配置二选一；安装后必须确认 `jiaotang-kb` 已进入当前运行时并成功调用只读状态或检索工具。

## 安全与发布门禁

- 通用包与 WorkBuddy 包均重新生成逐文件 SHA-256 和 Ed25519 签名。
- 发布门禁检查套件清单、规则编译、交付契约、专利案卷夹具、品牌水印、Word 渲染和知识门户回归。
- `--promote` 在网站正式提升和 GitHub Latest 切换前，以通用正式包完成本机原子升级、全量验签和三方哈希审计；任一步失败均保留旧安装并阻断发布。
- 网站、GitHub Release、套件清单、Word 用户手册、下载文件名和签名清单统一使用 V1.4.0。

## 回滚

- 通用 Skills 回滚时恢复上一版本 skills 目录，并重新运行安装完整性检查。
- WorkBuddy 回滚时在插件管理中停用、卸载 `jiaotang-workbuddy-skills` 并移除 `jiaotang` 本地市场；需要时重新安装 V1.3.1.6 原包。
- 回滚不得覆盖个人项目资料、本地政策规则、个人偏好、设备身份或系统凭据。
